# 1. Course Thesis

> **디지털 전환은 기술을 도입하는 프로젝트가 아니라 디지털 역량을 이용해 가치창출 방식과 운영체계를 바꾸는 조직 변화이며, AI 전환은 그 위에서 사람과 AI 사이의 업무·판단·책임 배분까지 다시 설계하는 다음 단계의 전환이다.**

이 과정에서 `AX`는 **AI Transformation을 지칭하는 교육용 약칭**으로 사용한다. 업계 전체에 단일 표준 명칭이 확립되어 있다고 가정하지 않는다.

과정 전체의 핵심 흐름:

```text
Computerization
→ Digitization
→ Digitalization
→ Digital Transformation
→ AI-enabled Transformation
→ AI-native Operating Model
```

그러나 이는 단순 기술 세대 교체가 아니다.

```text
Technology Change
      ↓
Capability Change
      ↓
Process / Decision Change
      ↓
Operating Model Change
      ↓
Value Model Change
```

## Learner & Context Fit

- **Audience / Work Context:** 조직의 DT/AX 전략과 실행 우선순위를 정해야 하는 리더·기획자·아키텍트.
- **Current Capability / Failure Mode:** 기술 도입 목록을 transformation으로 오해하거나 전사 roadmap에서 실제 bottleneck과 사용자/업무 문제를 놓친다.
- **Target Capability:** business/process/decision change를 중심으로 transformation opportunity를 발견하고 pilot evidence로 scale/stop을 결정한다.
- **Decision Level:** Decide / Govern.
- **Transfer:** 수업 산출물과 판단을 실제 업무의 동일 유형 결정에 재사용할 수 있어야 한다.

## Foundational Decision Lens Alignment

- **APPLY:** Design Thinking; Systems Thinking; Lean Thinking; Theory of Constraints; Empiricism / Scientific Thinking.
- **Why:** 문제와 value stream을 먼저 보고 whole system과 constraint를 진단한 뒤 pilot을 통해 학습하고 확대한다.
- **Rule:** 관련 없는 Lens를 과정 형식상 억지로 추가하지 않는다. Lens는 Course-owned concept를 재정의하지 않고 판단을 강화한다.

# 2. 기존 DT 교재에서 보존할 자산

기존 자료는 다음 강점을 그대로 보존한다.

## 2.1 역사적 연속성

```text
전산화
→ Master Plan / ISP
→ BPR
→ EA
→ DT
→ AI Transformation
```

핵심 메시지:

> **새로운 전환 방법론은 과거의 전략·프로세스·아키텍처 문제를 없애는 것이 아니라 다시 다른 기술 조건에서 풀어야 한다.**

## 2.2 기술보다 전체 시스템

기존 자료의:

```text
Technology
+ Culture
+ Process
```

구조를 유지하되 다음으로 확장한다.

```text
Strategy
+ Value
+ Process
+ Data
+ Technology
+ People
+ Governance
```

## 2.3 ISP / ISMP / EA를 폐기하지 않는다

이들은 DT 이전의 낡은 산출물 체계로만 보지 않는다.

- ISP → 전략과 IT 투자 정렬
- ISMP → 구축 가능한 요구·구조·규모 구체화
- EA → 조직 차원의 구조·표준·전환 제약
- BPR → 업무 프로세스 재설계

가 오늘날 DT/AX에서도 다시 필요하다.

단:

> **산출물을 만드는 것이 목적이 되면 다시 Cargo Cult가 된다.**

## 2.4 변화관리

기술이 준비되어도:

- Vision
- Alignment
- Skill
- Resource
- Incentive
- Action

이 없으면 변화가 정착되지 않는다는 기존 교육 메시지를 유지한다.

## 2.5 Roadmap → KPI → Pilot → Scale

기존 교재의 실행 부분은 적극 재사용한다.

```text
Strategy
→ Roadmap
→ Pilot
→ Evidence
→ Adapt
→ Scale / Stop
```

# 4. DT와 AX의 관계

## Digital Transformation

질문:

> **디지털 기술을 이용해 고객가치·업무·운영모델을 어떻게 재설계할 것인가?**

주요 변화:
- 정보의 디지털화
- 프로세스 연결
- 데이터 기반 운영
- 플랫폼
- 자동화
- 고객경험
- 새로운 Business Model

## AI Transformation

질문:

> **AI가 예측·생성·판단·행동 능력을 갖게 될 때 사람·프로세스·시스템의 역할을 어떻게 다시 배치할 것인가?**

주요 변화:
- Task automation
- Decision augmentation
- Knowledge work transformation
- Generative interaction
- Autonomous / agentic execution where appropriate
- continuous evaluation
- human oversight
- AI governance

### 관계

```text
Digital Foundation
      ↓
Data / Process / Platform Capability
      ↓
AI Capability
      ↓
Human + AI Work Redesign
      ↓
New Operating Model
```

### 중요한 결론

> **DT가 미성숙한 조직도 AI를 사용할 수는 있지만, 데이터·프로세스·시스템·책임구조가 약하면 AI가 그 불안정성을 증폭할 수 있다.**

# 12. Topic 05 — DT에서 AX로: AI가 무엇을 바꾸는가 — 45m

기존 교재의 AI Transformation을 과정 중심으로 승격한다.

AI의 역할을 네 층으로 구분한다.

### L1. Assist
사람이 일하고 AI가 보조.

### L2. Augment
AI가 분석·생성·추천하고 사람이 판단.

### L3. Automate
정의된 범위에서 AI가 Task 수행.

### L4. Agentic / Autonomous
목표와 Guardrail 안에서 여러 단계를 계획·실행하고 상태에 따라 행동.

중요:

> **높은 Level이 더 좋은 것은 아니다.**

선택 기준:
- impact
- uncertainty
- reversibility
- risk
- required judgment
- data quality
- observability
- accountability

### AX의 핵심 변화

```text
기존
Human
→ System
→ Output

AX
Human
↔ AI
↔ Tools / Systems
→ Outcome
```

따라서 질문이 달라진다.

> **무엇을 자동화할 것인가?**

보다:

> **어떤 판단과 행동을 누구에게 맡기고 어디에서 사람이 개입해야 하는가?**

공통 `support/01_governance/12_llm-integrated-practice-standard.md`를 적용한다. **4개**, 1일 4개, 총 약 **90분**이며 기존 instructional time 안에 포함한다.

상세 Practice Pack: `support/02_course-assets/11_dt-to-ax/01_llm-integrated-practice-pack-v1.1.md`

| ID | Placement | Practice | Time | Core Decision |
|---|---|---|---:|---|
| P1 | T04 | Transformation Readiness Diagnosis | 20분 | 현재 문제를 기술 도입이 아니라 value/operating model/data/people/governance readiness로 어떻게 진단할 것인가 |
| P2 | T06 | AI Use Case Portfolio Decision | 25분 | AI use case를 가치·실행가능성·위험으로 어떻게 선택할 것인가 |

| P4 | T11/T12/T13 | Roadmap of Bets → Value Evidence | 20분 | 어떤 pilot을 어떤 evidence로 scale/stop할 것인가 |

운영은 `Learner Prompt → First Run → Instructor Intervention → Keep Going → Recommended Prompt Reveal → Compare/Adapt` 순서다. Recommended Prompt는 정답이 아니며, 평가는 Prompt 문장력이 아니라 해당 과정의 전문적 판단 Evidence를 기준으로 한다.

# 23. Learning Outcomes

수강 후 학습자는:

1. Computerization / Digitization / Digitalization / DT / AX를 구분한다.
2. ISP·BPR·EA가 오늘날 Transformation에도 남긴 핵심 역할을 설명한다.
3. 기술도입과 Transformation을 구분한다.
4. Transformation을 Value / Capability / Operating Model 관점에서 진단한다.
5. AI 적용을 Assist / Augment / Automate / Agentic 수준으로 구분한다.
6. 업무·판단·행동을 Human / AI / Hybrid로 재배치한다.
7. AI Use Case를 가치·준비도·위험으로 우선순위화한다.
8. AI에 필요한 Data / Context / Integration 기반을 진단한다.
9. Human oversight와 AI Governance 필요성을 판단한다.
10. 조직·역량·인센티브 변화를 기술변화와 연결한다.
11. Pilot → Evidence → Scale / Stop 방식의 Roadmap을 설계한다.
12. Adoption metric이 아닌 Business Value evidence를 정의한다.

# 24. Anti-Patterns

1. DT = Cloud migration
2. DT = 새 시스템 구축
3. AX = 특정 Chat AI 도입
4. AX = 모든 업무 자동화
5. Agent = 더 성숙한 AI
6. AI 적용건수 = 성과
7. PoC 수 = 혁신
8. 기존 프로세스를 그대로 둔 채 AI만 추가
9. 데이터 품질 문제를 모델로 해결
10. 책임 불명확 상태에서 자동 의사결정 확대
11. Governance = 승인위원회
12. AI 교육 = Prompt 교육
13. 전사 Transformation부터 시작
14. 성공사례를 Context 없이 복제
15. AI 사용량을 직원 KPI로 사용
16. 사람을 제거하는 것을 ROI로만 계산
17. Technology Roadmap = Transformation Roadmap
18. EA/Architecture를 문서산출물로만 취급
19. Pilot 성공 후 운영 준비 없이 Scale
20. 실패한 Pilot을 중단하지 못함

# 26. Current Governance Baseline

AI Governance는 별도 부록이 아니라 AX 설계에 포함한다.

현재 참조 가능한 안정적 기준:

- NIST AI RMF: AI 위험을 조직의 설계·개발·배포·사용 전반에서 관리
- NIST Generative AI Profile: 생성 AI 고유/증폭 위험과 대응
- ISO/IEC 42001: 조직 차원의 AI Management System과 지속개선

이 과정은 표준 조항을 교육하지 않고 다음 원칙만 적용한다.

```text
AI Opportunity
      +
AI Risk
      ↓
Governed Experiment
      ↓
Evidence
      ↓
Scale / Adapt / Stop
```

# 27. Quality Gate

과정 승인 전 모두 YES여야 한다.

- DT를 기술목록으로 가르치지 않는가?
- 기존 ISP/BPR/EA 역사를 현재 문제와 연결하는가?
- ISP/ISMP/EA 상세가 과정 중심을 차지하지 않는가?
- DT와 AX의 연속성과 차이를 동시에 설명하는가?
- AX를 단순 AI 도입으로 정의하지 않는가?
- AI가 Human/Process/Decision 구조를 바꾼다는 점이 중심인가?
- Agentic AI를 무조건 상위 성숙도로 가르치지 않는가?
- AI Use Case가 Problem/Value에서 시작하는가?
- Data뿐 아니라 Context/Policy/Tool access를 포함하는가?
- Governance가 혁신의 반대가 아닌 안전한 확산 장치인가?
- Human oversight와 Accountability를 다루는가?
- Roadmap이 Big-Bang이 아니라 Pilot/Evidence 기반인가?
- KPI가 Adoption보다 Outcome을 우선하는가?
- AI-Native SW Engineering 과정의 OWNER를 침범하지 않는가?
- Topic 시간이 50분 고정이 아닌가?
- 순수 학습시간이 약 400분인가?
- 총 운영시간이 480분 이내인가?

# 28. Final Course Message

> **디지털 전환의 본질은 기술을 디지털로 바꾸는 것이 아니라 조직이 가치를 만드는 방식을 바꾸는 것이며, AI 전환의 본질은 그 과정에서 사람과 AI의 역할·판단·책임까지 다시 설계하는 것이다.**

최종 질문:

> **“어떤 AI를 도입할 것인가?”가 아니라  
> “우리 조직의 어떤 가치창출 문제를 바꾸어야 하며, 그 일을 사람과 AI가 어떻게 나누고 어떤 Evidence로 전환의 효과를 증명할 것인가?”**
