# Course Portfolio Catalog v1.1

> **Purpose:** 현재 및 계획 과정 목록을 관리한다.
> **Rule:** 과정의 추가·분리·통합은 여기서 관리하며 Program Canon의 최상위 원칙을 불필요하게 변경하지 않는다.

## 1. Active / Current Engineering Portfolio

### Engineering Foundations
- **OOAD** — 현실 문제를 모델·책임·협력·객체 계약으로 구조화.
- **DDD** — Domain의 개념·규칙·언어·경계를 명시적 모델로 심화.

### Architecture & Distribution
- **SW Architecture** — Quality/Constraint를 근거로 구조를 선택하고, Clean Architecture의 Dependency Rule을 기본 구조적 기준점으로 삼아 Evolutionary Architecture 방식으로 지속 검증·진화.
- **MSA** — 분산의 가치와 Service Contract / Failure / Operation 비용을 판단.

### AI Engineering
- **AI-Native Software Engineering** — Specification / Context / Control을 바탕으로 AI에 책임을 위임하고 평가.

### Quality — Cross-Cutting
- **Modern QM** — Prevention / Evidence / Gate / Feedback / Continuous Improvement로 Engineering System의 품질을 관리.

## 2. Bridge Topic

- **Ontology / Explicit Semantics** — DDD와 AI-Native 사이의 optional bridge. 현재 독립 Core Course가 아님.

## 4. Candidate Admission Workflow

`Candidate → Course Spec → Canon/Ownership Review → Pilot Curriculum → Evidence Review → Active`

Candidate 이름만으로 과정 구조나 OWNER를 확정하지 않는다.

## 5. Portfolio Rules

1. Prerequisite recommended, never assumed.
2. One Concept, One Canonical Owner.
3. 새 과정은 기존 과정 정의를 복제하지 않는다.
4. 독립 problem/decision이 없으면 module/appendix로 둔다.
5. 과정 분류는 Portfolio 관리 정보이지 교육 철학의 정본이 아니다.
6. Tool/Vendor는 과정 identity가 될 수 없다.
7. Retire/Merge 시 개념 OWNER의 이동을 먼저 결정한다.
