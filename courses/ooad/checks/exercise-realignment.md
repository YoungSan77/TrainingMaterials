# 실습 사례 정렬 — 정기배송에서 주문으로

**`course-design.md`는 2026-10-21에 고쳤다. 세션 원고의 실습·별첨은 아직 정기배송이다.** 원고 정렬은 **ai-native 전면 보완이 끝난 뒤**에 한다(2026-10-21 사용자 결정). 그동안 과정 설계와 원고가 어긋나 있으므로, 원고를 읽을 때는 이 문서와 과정 설계가 기준이다.

## 결정 (2026-10-21)

- **도메인은 하나다.** OOAD는 16시간·14세션이고 실습이 13개다. 실습에 다른 도메인(정기배송)을 두면 모델링 기법을 익힐 시간에 업무를 익힌다. 배운 것을 실습에서 확인하는 것만으로도 시간이 짧다.
- **실습도 강의와 같은 주문 사례를 쓴다.**
- **강의는 발췌를 보이고 실습이 산출물을 완성한다.** 강의 본문은 기법을 설명하며 주문의 한 장면·한 개념·한 전이를 예로 보이고, 수강생이 실습에서 같은 사례의 산출물 전체를 만든다. 강의가 완성된 산출물을 미리 보이지 않는다 — 같은 사례를 쓰면서 실습이 받아쓰기가 되지 않게 하는 장치다.
- 실습마다의 장면은 그 세션의 기법이 필요한 곳으로 정한다 — 요구·유스케이스·정적 모델은 주문을 관리한다 전체, 동적·설계·통합은 결제한다, 책임·협력은 주문 취소다.
- 실습 8의 변경 요청은 **배송지 변경을 배송 요청 후에도 허용한다**로 바꾼다(강의가 쓰는 변경 요청 둘 — 결제 전 취소, 간편결제 추가 — 과 겹치지 않는 세 번째 요청).
- 용어집은 하나다. 정기배송 전용 용어집·식별자를 두지 않는다.
- AI-native SW 공학 과정도 같은 주문 사례를 쓴다. 경계는 가르치는 것이다 — 이 과정은 **모델의 상세와 표기법**, 그 과정은 **결정과 검사, 사람과 AI의 역할**이며 표기법을 가르치지 않는다. 상태 기계의 원천은 이 과정의 전체(취소됨 포함)이고 그 과정은 주문한다 한 과제만 쓴다. 그 과정에서 정한 이름(`pay`·`requestApproval`·`requestDelivery`·`PaymentMethod`)은 이 과정의 용어집에도 같은 이름으로 더한다.

## 과정 설계에서 고친 것 (완료, 2026-10-21)

- 「실습 관통 사례」 문단 — 정기배송 전용 시나리오를 주문으로 교체하고 강의 발췌 / 실습 완성의 구조를 적었다.
- 「깊이의 결정」 — "도메인은 하나로 둔다"를 더했다.
- 실습 표 8행의 변경 요청을 교체하고, 실습 표 아래에 실습마다의 장면을 한 줄로 적었다.
- 「재사용 사례의 공통 용어와 전제」 — "정기배송(실습 사례)" 행을 "실습 사례"와 "AI-native 과정과의 관계" 두 행으로 교체했다.
- 영한 용어집의 정기배송 원천 문장을 "용어집은 하나다"로 바꿨다.
- 세부 목차 여섯 곳의 `(정기배송)` 표기를 `(주문)`으로 바꿨다 — S01·S02·S03·S04·S05·S06.

## 세션 원고에서 고칠 것 (남음)

실습 장과 별첨 답이 정기배송으로 쓰여 있다. 실습 1~13을 주문 사례로 다시 쓴다.

| 세션 | 고칠 것 |
|---|---|
| s01 | 실습 — 요구사항 정의서. 별첨 「요구사항 정의서 (안)」이 정기배송의 이름·규칙의 원천이었다. 주문으로 바꾸고 원천은 공통 전제 하나로 둔다 |
| s02 | 유스케이스 다이어그램·명세서, 용어집 (안). 정기배송 용어집을 없앤다 |
| s03 | 도메인 모델 초안·상세 (안) |
| s04 | 시퀀스·상태 기계 (안) |
| s05 | 패키지 다이어그램 초안·상세 (안) |
| s06 | 결제한다의 설계 시퀀스 (안) |
| s07 | CRC와 설계 클래스 (안) |
| s08 | 변경 설계 — 배송 주기 "매월 ○일" → 배송지 변경을 배송 요청 후에도 허용한다 |
| s09 | 설계 대안 (안) |
| s10 | 물리 모델 (안) |
| s11 | 통합 (안) |
| s12 | 피드백 (안) |
| s13 | 아키텍처 스타일 구현 (안) |

- 본편(강의 본문)은 이미 주문 사례다. **실습 장과 별첨만 고친다** — s01~s05는 목표 품질의 기준 예시이므로 본편의 구성과 문장을 건드리지 않는다(`AGENTS.md`).
- 강의 본문이 완성된 산출물을 통째로 보이는 자리가 있으면 발췌로 줄인다.
- 실습의 투입물 참조("실습 3의 도메인 모델" 등)는 번호가 그대로이므로 유지된다.
- `(안)` 표기와 "유저 스토리" 용어도 이때 **사용자 이야기**로 바꾼다(ai-native와 맞춤).

## 작업 순서

1. 실습 1의 요구사항 정의서부터. 그것이 뒤 실습의 입력이다.
2. 세션마다 실습 장 → 별첨 → 렌더링(오류 0·경고 0) → 바뀐 장만 시각 검토.
3. 13개가 끝나면 `node engine/production/src/cli.js --check courses/ooad/sessions/s*.md`로 참조를 한 번에 확인한다.
4. 끝나면 이 문서를 지운다.
