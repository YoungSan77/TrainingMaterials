# Agentic SW dev 실습 설계

## 위상
- 앞 넷 형식 복제. 대조 대상 = **파이프라인 설계와 게이트 배치**(통제 유무·자율 폭).
- 코드보다 **설계 대면**이 (a)의 중심(DDD와 유사) — 파이프라인·게이트를 도표로 짜고, 코드는 게이트 확인용.
- 아키텍처(포트·경계)·MSA(Saga·롤백) 게이트를 재사용.

## 렌즈 차이
- AI-assisted: 사람이 지시하고 출력을 통제(한 번의 생성·검증).
- Agentic: 에이전트가 다단계로 자율 실행 → 사람은 **어디에 게이트를 두고 자율 폭을 얼마로 할지 설계**. 대상이 코드가 아니라 파이프라인 구조.

## 실습 3층
| 층 | 대상 | 활동 |
|---|---|---|
| 판단 | 전원 | "이 단계에 게이트가 필요한가 / 자율 폭이 옳은가" 결정 |
| **설계 대면** | 전원 | 파이프라인 도표에 게이트를 배치·조정. 실패 시나리오를 따라가 본다 |
| 코드 작성 | 코더 | 게이트를 실제 검증(단계 산출을 ArchUnit·린터에 통과) |

## 부 1 · 파이프라인 경계

### (a) 설계 대조 · 경계가 있나

**쌍 G-1 · 통짜 에이전트 vs 단계 파이프라인**
- 대조: 요구→완성을 한 번에 맡긴 에이전트 vs 요구→설계→구현→테스트→리팩토링 단계로 쪼갠 파이프라인.
- 물음: 통짜에서 3단계째 오류가 나면 어디서 잡히나(안 잡힘). 단계에선? 경계가 blast radius를 자른다.

**쌍 G-2 · 도구 호출이 포트인가** — 에이전트가 파일·DB를 직접 만지는 설계 vs 포트 뒤로 격리한 설계. 아키텍처 재사용.

### (b) 통짜 · 파이프라인 스케치
- Order 기능 하나를 통짜 에이전트 vs 단계 파이프라인 두 설계로. 각각 실패 주입 시 무엇이 어디까지 번지나.

## 부 2 · HITL 게이트

### (a) 게이트 대조 · 어디에 사람이 서나

**쌍 G-3 · 게이트 없음 vs 되돌릴 수 없는 단계 앞 게이트**
- 대조: 전 단계 자동 승인 vs "커밋·배포·외부 호출" 앞에 사람 승인.
- 물음: 게이트 없는 파이프라인이 잘못된 리팩토링을 커밋하면? 기준 = 위험·되돌릴 수 없음·확률적 불확실성.

**쌍 G-4 · 자율 폭 조절** — 신뢰 낮은 단계(설계 판단) 좁게 vs 높은 단계(포맷팅) 넓게. 폭을 신뢰에 맞춘 설계 대조.

### (b) 통짜 · 게이트 배치 + 실패·롤백
- Order 파이프라인에 게이트를 배치하고, 한 단계 실패를 주입 → Saga·보상으로 롤백(MSA 재사용) → 관측 로그로 원인 추적.
- 물음: 어느 게이트가 이 실패를 막았나. 없었으면 어디까지 오염됐나.

## 코더 층
- (a): 파이프라인 한 단계의 산출을 주고 **게이트 검증 코드 빈칸**(단계 출력이 의존성 규칙·캡슐화를 지키는지).
- (b): 실패 주입 → 롤백 훅을 직접 구현.

## 코드·자산 (준비물)
- 파이프라인 도표 세트(통짜 vs 단계, 게이트 유무).
- 인메모리 파이프라인 스텁(실제 에이전트 프레임워크 없이 단계·게이트·롤백을 시뮬레이션 — 오프라인 번들 준수).
- 게이트: ArchUnit·캡슐화 린터·규칙 테스트 + 단계 전이 검증.

## 격리·유지 주기
- 에이전트 프레임워크·모델은 부록에만. 본문 대조는 "경계·게이트·롤백" 원리로 — 프레임워크가 바뀌어도 설계 실습이 산다.
- 비용 인식(토큰·자원)은 관측 로그에서 **보여만** 준다 — 배분 최적화(FinOps)는 안 다룬다(지평선).
