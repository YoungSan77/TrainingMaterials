# AI-native SW Engineering — Curriculum / Session Architecture

**세션 구성·시간 배분·세션별 목표·Anchor Message·실습 편성과 연결 관계**의 정본이다. [Course Design](course-design.md)의 승인 범위와 교육 목표 1~7을 적용한다. 과정 정체성·목적·대상·범위·공통 판단 원칙·교육 접근법은 Course Design이 소유하며 이 문서가 중복 정의하지 않는다. 이 문서의 승인은 Session Architecture에 해당하고, 세션별 구성안·원고 승인과 전체 Curriculum의 통합 승인은 후속 단계다(`guides/governance.md`).

이 편성은 2026-11-26 원점 재검토의 결과다. 이전 편성은 Git 커밋 `764ac26`에 있으며 비교 자료다.

## 과정 개요

하나의 시나리오를 공학 활동의 흐름대로 따라가며, **활동마다 그 활동을 받치는 본질적 원리**와 **AI로 달라지는 수행 방식·산출물의 역할·인간과 AI의 협업과 분업**을 교육하고 같은 사례에서 실습으로 수행한다. 최초 개발을 중심에 두고, 변경은 후반부 통합 실습으로 다룬다. AI 관련 개념은 그 문제가 생기는 활동에서 처음 설명하고 이후 활동에서 필요한 범위로 적용한다.

> **도입** → **요구사항** → **도메인 모델(정적 → 동적)** → **아키텍처** → **설계** → **설계에서 코드로** → **테스트·CI로 확인** → **변경(통합 실습)** → **AI 활용 및 통제 기법** → **운영·적용**

순서는 학습 편성이며 개발 절차가 아니다. 뒤 활동에서 발견한 근거는 앞 결정으로 환류한다. **일자 구분은 교육 주제와 시간 편성에 따른 것이며, 인간과 AI의 역할을 구분하는 경계가 아니다** — 모든 활동에서 인간과 AI가 협업하고 분업한다.

## 편성 단위

**순수 교육시간 700분 = 50분 블록 14개.** 블록마다 휴식 10분을 더해 편성 경과시간 840분(14시간)이다. **블록마다 실습은 최대 25분**(교육 시간의 절반)이다. 세션은 블록 1개 또는 2개로 구성하며, 한 블록이 두 짧은 세션을 담을 수도 있다.

## 세션별 교육 목표와 Anchor Message

| 세션 | 교육 목표 | Anchor Message | 과정 목표 |
|---|---|---|---|
| **S01** | 공학 활동의 흐름과 산출물의 연결을 그릴 수 있고, 인간과 AI의 협업·분업에서 고려할 요소를 안다. AI 상호작용을 목적·입력·제약·기대 결과와 피드백으로 구성한다 | SW 공학의 목적과 본질적 원칙은 유지되지만 수행 방식은 달라진다 | 1·3 |
| **S02** | 요구사항과 수용 기준의 역할을 이해하고, AI와 함께 요구사항을 도출·정리하며 범위·제외·미정을 가른다. 명세를 중심으로 이후 활동을 연결하는 접근을 안다 | 명확한 요구사항은 인간과 AI가 공유하는 문제 해결의 출발점이다 | 2·4 |
| **S03** | 도메인 모델이 업무의 의미와 규칙을 구조화한다는 것을 이해하고, 개념·관계·다중성·불변 조건을 식별·상세화하며 모델의 정합성과 적정 상세 수준을 판단한다 | 도메인 모델은 업무의 의미와 규칙을 구조화하고 공유하는 수단이다 | 2·3·4 |
| **S04** | 사건·상태·전이로 업무의 행위를 표현하고 정적 모델과 교차 검증한다 | 정적 모델과 동적 모델은 업무의 구조와 행위를 상호 보완적으로 표현한다 | 2·4 |
| **S05** | 기능 요구사항과 품질 속성을 받아 구조와 경계·의존성·외부 연동을 정하고, 주요 구조적 결정의 Trade-off를 설명한다 | 아키텍처는 요구사항과 품질 목표를 만족시키기 위한 주요 구조적 결정의 집합이다 | 2·4 |
| **S06** | 책임과 협력·응집도와 결합도·정보 은닉으로 복잡성을 관리하고, 인터페이스와 계약으로 변경 용이성과 설계–코드의 연결을 확보한다 | 좋은 설계는 복잡성을 관리하고 인간과 AI의 이해·구현·변경을 돕는다 | 2·4 |
| **S07** | 구현에 필요한 맥락을 선택해 AI 코드 생성에 활용하고, 생성 결과와 선행 결정의 정합성을 확인한다 | 명확한 요구사항과 설계는 AI를 활용한 효과적인 구현의 기반이다 | 2·4·5 |
| **S08** | 테스트의 목적과 독립성을 이해하고, 업무 규칙·요구사항에 기반한 테스트를 갖춰 자동화된 검증과 CI로 확인한다 | 자동화된 검증은 구현 결과가 기대한 조건을 충족하는지 지속적으로 확인한다 | 5 |
| **S09** | 변경 영향을 분석하고 필요한 산출물을 수정하며, 기존 결정과 업무 규칙을 보존한 채 회귀를 검증한다 | 명시된 지식과 공학적 결정은 효과적인 변경의 기반이다 | 2·4·5 |
| **S10** | 앞서 경험한 AI 활용 기법을 종합하고, 각 기법의 공학적 목적과 적용 조건을 판단한다. Agentic AI·Evals·FinOps와 AI 활용의 위험·통제를 안다 | AI 활용 기법은 공학적 목적과 적용 조건에 따라 선택한다 | 5·6 |
| **S11** | AI가 딜리버리·운영의 수행 방식을 어떻게 확장하는지 사례로 이해하고, 유지되는 공학적 판단과 책임을 안다 | AI는 딜리버리와 운영의 수행 방식을 확장하며 공학적 판단과 책임은 유지된다 | 2 |
| **S12** | 업무 특성과 자신의 역량에 맞는 협업 방식을 판단하고, 직무에 적합한 적용 방안을 도출한다 | 효과적인 인간과 AI의 협업 방식은 업무의 특성과 역량에 따라 달라진다 | 7 |

Anchor Message는 해당 활동의 **본질과 목적**, AI로 변화하는 **수행 방식**, 인간과 AI의 **협업과 분업**을 중심으로 적는다. AI의 오류·위험·통제에 편향하지 않는다.

## 실습 편성과 연결

실습 **12개**다. 모든 실습은 [Course Design](course-design.md)의 「공통 업무 시나리오와 필수 공통 전제」를 사례로 쓴다 — 업무 시나리오·범위·공통 업무 규칙·미정 사항·품질 요구사항·외부 시스템·변경 요구·공통 업무 용어는 그 절이 소유하며 이 문서가 다시 정의하지 않는다.

공학 활동과 산출물의 논리적 연속성은 유지하되 **실행 의존성은 없다** — 모든 실습의 투입물은 **수강생 자신의 선행 산출물 또는 제공된 기준 산출물** 중 수강생이 고른다. **투입물은 실습 목적에 필요한 맥락을 선택해 제공하며, 모든 선행 문서를 매번 전문으로 제공하는 것이 아니다.** 실습 문제·프롬프트·점검항목은 Session Authoring이 설계한다.

| **P11** | 12 · S09 | 25 | **변경 요구와 변경에 필요한 기존 산출물 및 검증된 실행 환경** | 변경 영향을 분석하고 산출물을 수정하며 회귀를 검증한다 | 변경 결과 |

**산출물의 소비 관계** — P02의 요구사항은 P03·P04·P05·P06·P07·P09·P10에서, P04의 정적 모델은 P05·P06·P07에서, P05의 동적 모델은 P06·P07에서, P06의 아키텍처 결정은 P07·P09에서, P08의 설계는 P09에서, P09의 코드는 P10에서, 그리고 P02~P10의 산출물이 P11에서 쓰인다. 각 실습은 그중 **목적에 필요한 것만** 투입물로 받는다.

**P01→P02, P03→P04, P07→P08**은 같은 세션의 두 실습으로 같은 맥락을 이어 쓴다. 블록 상한 25분을 지키면서 결정이 둘인 활동을 두 바퀴로 나눈 것이며, 두 번째 실습도 **기준 산출물로 시작하는 선택이 열려 있다.**

**실습 P01~P10이 핵심 SW 공학 활동에 속한다**(240분, 실습의 85.7%). P11은 변경 통합 실습, P12는 적용 방안 도출이다.

**실습 형태** — 투입물 · 첫 프롬프트(제공) · 중간 프롬프트(수강생의 검토와 피드백 반복) · 최종 프롬프트(제공) · 점검항목. 운영 원칙은 [Course Design](course-design.md)의 「교육 접근법」을 따른다.

## 세션 간 경계와 연결

- **S02는 수용할 결과와 범위를 정하고, S03·S04는 그 업무의 의미와 행위를 표현한다.** 정적 관점과 동적 관점은 하나의 도메인 모델의 두 관점이며 상호 보완적이다. 별개의 업무 모델로 분리하지 않는다(`guides/sw-engineering-principles.md`).
- **S05와 S06은 모두 설계에 속하며 결정 수준이 다르다.** S05는 요구사항과 품질 목표를 받아 시스템의 주요 구조·경계·의존성·외부 연동을 정하고, S06은 책임·협력·인터페이스·계약을 정한다. 세션을 나눈 것이 독립 모델이나 고정 개발 단계를 뜻하지 않는다.
- **S06의 책임 분해와 S07의 위임 작업 분해를 동일시하지 않는다.** 전자는 소프트웨어 구조의 결정이고 후자는 수행 방식의 결정이다.
- **S07은 구현에 필요한 맥락을 선택해 코드를 생성하고, S08은 결과를 확인할 검증을 갖춘다.** S08은 로컬 테스트 실행과 CI 파이프라인 실행을 구분한다.
- **S09는 S02~S08의 산출물을 입력으로 받는 유일한 세션**이며, 변경에서 그 산출물이 어떻게 쓰이는지 확인한다.
- **S10은 앞서 경험한 개념을 종합하고 Agentic AI·Evals·FinOps와 AI 활용의 위험·통제를 교육한다.**
- **S11은 사례 중심으로 간결하게** 다루며 실습을 두지 않는다. **S12는 블록 14를 S11과 나눠 쓴다.**

## Session Authoring 인계

- 세션 원고의 경로는 `sessions/sNN.md`다. 두 블록으로 구성된 세션(S02·S03·S06)은 하나의 원고가 두 블록의 교수 전개와 두 실습을 함께 소유한다.
- 세션 원고 작성의 입력은 **승인된 Course Design과 이 Curriculum**이다. 이전 설계의 원고와 실습 설계는 입력이 아니며 비교 자료다.
- **Session Authoring 시작 전에 공통 업무 시나리오와 필수 공통 전제, 지정 출처를 결정한다** — `guides/governance.md`의 「단계와 정본」이 Session Authoring의 승인 입력으로 "출처와 확정된 사례 입력"을 규정한다. 세션별 용어와 참고 자료는 해당 세션의 구성안 검토에서 보완할 수 있다.
- 세션별 구성안·원고 승인과 Curriculum 통합 승인에서 교육 활동의 시간 적합성과 산출물 연결 범위를 검토한다.
