## 13절 표와 실제 검사: 수정 제안만 제공

대상은 원고 **725행**, 출력 **23쪽**, 「모델 규칙과 코드·테스트의 대응」 표의 **‘개념과 식별’ 행(머리글 제외 1행), ‘테스트에서 확인할 내용’ 열(3열)**이다.

현재 문장:

> 결제 거절 후 재결제에서도 주문 번호가 같은지 확인한다.

이는 업무 사례의 기대 결과이며, **현재 Java에서는 검사하지 않았다.** `StaticModelTest.java` 13행은 `new OrderNumber("ORDER")`로 주문을 생성한다. 15행의 식별자 검사는 `item.productNumber()`의 **상품 번호**다. 테스트에는 `order.number()` 단언이나 결제 거절·재결제 실행이 없다. `Order.java`의 final 필드와 생성자 보관은 구현을 설명할 근거지만, 재결제 동작을 실행해 검증했다는 근거는 아니다.

해당 셀의 수정안:

> 현재 Java 테스트는 재결제 전후의 주문 번호 유지를 검사하지 않는다. 같은 주문 번호 유지는 재결제 사례의 기대 결과이며, 행동 검사에서 확인해야 한다.

수정안은 이 보고서와 QA의 수동 검토 항목에만 기록했다. 원고와 테스트 코드를 고치지 않았다. 코드 표의 다른 행은 다음 실제 검사와 대응한다.

| 행 | 현재 Java의 실제 근거 | 판정 |
|---|---|---|
| 단가와 판매가 | 테스트 20~22행: 현재 판매가·확정 단가·주문 금액 | 검사됨 |
| 값 조건 | 33~35행: 0/음수 수량·음수 금액 거절 | 검사됨 |
| 다중성 1..* | 30~32행: 빈 주문 거절 | 검사됨 |
| 합계 등식 | 14행 및 43~51행: 단가×수량, 1~20개 항목 합산 | 검사됨 |

## 제작 확인

10절 19쪽의 검토 모델 문장 4개 모두 PPTX 속성상 `spcBef=300`, `spcAft=300`(앞뒤 각각 **3pt**)이다. 실제 렌더에서도 같은 목록 단계와 일정한 간격을 유지하며 질문과 구분된다. Java 3개 코드 블록의 내부 문단 간격은 기존 **0pt**이고 원본 공백·줄바꿈·Consolas/맑은 고딕 서식을 유지한다.

인용 9곳, 실습 문제 한 장, 「연관명과 다중성」 한 장, 별첨 8pt 표 260셀과 내용 기반 열 너비·왼쪽 우선 흐름·첫 두 항목·`.....`를 확인했다. 별첨 28~37장의 슬라이드 XML은 정식 기준선과 비교해 명시적 영문 줄바꿈 금지 속성 외 바이트 단위 동일하다. 이는 별첨의 표 폭·좌표·내용·순서·생략·도식 보존의 전수 근거다.

새 PDF 전체 **24표·421셀**의 텍스트·경계·영문 식별자 줄 분리 검사는 PASS이며 문제 0건이다(`render.json`). 표/후속 설명의 최종 객체 경계는 native QA `table_layout`에서도 검사했다. 30·33·34쪽의 표와 뒤 계산·설명에도 겹침을 발견하지 않았다.

이번에는 제작 결함을 찾지 못했고 렌더러를 변경하지 않았다. 따라서 조건부 S03·OOAD 회귀를 새로 실행하지 않았다. 기존 테스트/대표 회귀를 이번 실행 결과로 재기록하지 않았다.
