- 첫 렌더링에서 경고 12개가 났다 — 표 셀 넘침 5, 핵심어 bold 누락 2, 의문문 표 칸의 `?` 2, 도식 글자 6.7pt 1, continuation 본문 부족 2. 전부 고쳐 0으로 만들었다.

## 재개 후 최종 검증 — 2026-10-24

### 선행 검토

`courses/ai-native/checks/s01-s05-ai-native-review.md`에 「세션 01. 사람의 일과 AI의 일」~「세션 05. 동적 모델」의 AI-native 적합성을 기록했다. 목적에 적합하되 실습 1~5는 대화형 보조이며 검사 증거로 에이전트가 자가 수정하는 실행은 후속 세션이 담당한다. S01~S05 원고는 수정하지 않았다. 다섯 원고 `--check`는 오류 0·경고 0, 정적 예제 18개 검사와 동적 예제 6개 묶음은 통과했다.

### 보완한 판단과 산출물

- S06 실습 프롬프트에 도메인 모델을 입력으로 명시하고 Order·OrderItem의 order 소유와 Product의 product 소유, 기존 업무 연관 보존을 요구했다.
- 패키지 경계와 포트 소유를 subgraph로 표시했다. 실선 업무 연관과 점선 설계 의존을 범례로 구분하고 Order가 외부 포트를 직접 호출한다고 결정하지 않았다. 구체 객체 책임은 후속 설계 활동에 남겼다.
- 그림 두 개의 질문은 업무 경계와 포트 구현이다. 노드·의미 있는 관계를 지우지 않았다. 내부 세로 정렬과 포트 표식 줄바꿈으로 배치를 조정했다.
- 허용 밖의 업무 간 의존은 순환이 없어도 금지다. 15장의 설명과 표, 실제 응답의 의존 규칙, 검사 코드와 위반 예제를 함께 보완했다.
- 이 검사로 `product → payment.Money`라는 예제의 실제 위반을 발견했다. 상품 포트의 판매가 반환을 원 단위 정수로 바꿔 결제 자료형 의존을 제거했다. 정상 구조와 금지 의존·허용 목록 위반·하위 패키지 위반·순환 탐지가 모두 통과했다.
- 별첨은 실제 최종 응답 전문이며 제목 단계·SA 표식·문서 배치만 변환했다. 문장·도식·강조의 payload 일치를 기계적으로 확인했다. 최종 MD는 codex-response-05.md와 바이트 동일하다.
- 포트 이름은 과정 공통 이름 PaymentGateway·DeliveryGateway·ProductGateway·OrderRepository로 맞췄다. 실습 결과물 셋과 course-design.md의 실습 산출물 표도 맞췄다.
- 종전의 전역 flowchart 간격 변경은 유지했다. 축소된 페이지 용량을 검사하는 중단 작업에는 회귀 테스트 2개와 실제 flush 용량 기록 검증을 더했다. 전체 189개 테스트 통과.
