# 전면 보완 — 옛 원고에서 새 세션으로의 매핑

`course-design.md`를 **2026-10-21에 11세션으로 다시 설계했다**(활동 축 + 결정과 검사의 짝). 이 문서는 지금까지 쓴 원고의 내용이 새 세션의 어디로 가는지와, 세션 사이 참조를 고치는 방법을 적는다. 전면 보완이 끝나면 지운다.

## 왜 다시 설계했는가 (2026-10-21)

10-18 설계는 활동 축을 선언했지만 열두 세션 중 여섯이 **장치 이름**(맥락·권한·실행 흐름·하네스·실패·평가)이었다. 그래서

- **설계(책임과 협력) 활동에 세션이 없었다.** 도메인 모델에서 코드로 바로 건너뛴다.
- **구현·테스트가 세션의 주제가 아니었다.** 실제 위임 실행이 마지막 한 세션에만 있어, 정적·동적 모델이 코드와 검사로 어떻게 이어지는지 수강생이 경험하지 못한다.
- **실습 1~7이 모두 문서 작업이었다.** 그래서 권한 세션의 실습이 적용할 대상이 없어 가짜 샌드박스를 만들어야 했다(10-21의 s07 검토에서 드러났다).
- 장면을 연출해 세션을 채운 자리가 둘 있었다 — s07의 제공 환경, s10의 "거절 뒤 재결제" 되풀이 실패(03에서 이미 확정한 자기 전이를 일부러 누락시켜야 성립한다).

**세션이 성립하는 조건**을 과정 설계에 못박았다 — 세션은 공학 활동 하나이거나, 그 활동을 AI에게 맡기는 결정 하나다. 이 규칙이 맥락·가드레일·실패 세션을 없앴다.

## 파일 처리

파일명은 새 번호를 그대로 쓴다(`s01.md`~`s11.md`). 새 01부터 순서대로 덮어쓰며, 다 끝난 뒤 `s12.md`·`s12.pptx`·`s12.qa.json`을 지운다. 예시 코드 폴더도 새 번호로 옮긴다(`code/sNN/`).

- 새 원고를 쓰기 전의 옛 내용은 git history에만 둔다. 옛 번호의 파일을 참고용으로 복사해 두지 않는다.
- 실습 번호도 세션 번호와 1:1로 다시 매긴다(실습 1~11).

## 세션 사이 참조

- 참조는 **그 원고를 다시 쓸 때 함께 고친다.** 아직 쓰지 않은 세션을 가리키는 참조는 Production이 경고로 남기므로, 전부 끝난 뒤 `--check`로 한 번에 확인한다.
- **s02~s11의 헤더는 새 세션명이고 본문은 옛 축이다**(2026-10-22). 그래서 과정 전체를 `--check`하면 그 열 세션에서 세션 참조 오류가 난다. **의도한 중간 상태**이며, 한 세션을 다시 쓸 때마다 그 세션의 오류가 사라진다. 지금 고친 세션만 단독으로 `--check`해 오류 0·경고 0을 확인한다.
- 턴 종료 검사가 그 열 세션을 반복해서 막지 않도록 `checks/rewrite-pending.json`에 적어 두었다(`guides/production-guide.md`의 「자동 검사 — 참조와 경고」). **세션을 다시 쓸 때 그 줄을 지우고, 열한 세션이 끝나면 파일을 지운다.**
- 세션을 하나 끝낼 때마다 `node engine/production/src/cli.js --check courses/ai-native/sessions/s*.md`로 남은 오류 수가 줄어드는지만 본다. 전면 보완 중에는 오류 0이 되지 않는다.
- 완료 조건은 열한 세션과 별첨이 모두 **오류 0·경고 0**으로 렌더링되는 것이다.

## 확정된 것 (2026-10-21)

- **실습 저장소 — 빈 저장소.** 과정이 주는 저장소·코드·빌드 구성·스텁은 없다. 수강생이 실습 1~11로 요구부터 검사까지 직접 쌓고 hands-off 경험을 한다.
- **과제는 주문한다 하나다.** 기능을 여럿 두면 둘 다 얕아지고, 14시간은 하나를 요구에서 검사까지 끝내기에도 빡빡하다. 반복은 새 기능이 아니라 **작업 단위**로 한다 — 07이 4개로 쪼개고, 08이 첫 단위, 09가 검사, 10이 남은 단위도 맡길지 판단, 11이 남은 셋을 끝낸다. 그래서 11은 "다음 기능"이 아니라 "기능을 끝내는" 세션이고, 두 번째 위임이 첫 번째와 어떻게 다른지(환경이 자랐다)가 그 자리의 학습 내용이다. 취소·배송지 변경은 쓰지 않으며 주문 상태에서 취소됨을 뺐다(03의 제외로 적는다). 2026-10-21.
- **실습 사례 — 정기배송을 버리고 강의와 같은 주문 시스템을 쓴다.** 빈 저장소에서 14시간 안에 끝까지 가야 하므로 **도메인 이해 비용을 0으로** 만들었다. 정기배송은 회차 일정 계산(날짜 산술·반복 생성)이라는 구현 난이도까지 더해져 판단 연습 시간을 먹는다. 강의와 실습의 차이는 도메인이 아니라 **결정**이다 — 강의의 업무 규칙 3가지는 그 회사가 정한 것이고, 실습에서는 수강생이 실습 1에서 자기 판단으로 정한다. 두 번째 과제는 강의가 **주문 취소**, 실습이 **주문의 배송지 변경**으로 갈린다. 과정 설계의 원칙 "강의가 실습의 답을 미리 보이지 않는다"를 "강의는 판단의 과정을 보이고 실습은 같은 과제를 수강생이 직접 결정한다"로 바꿨다(2026-10-21).
- **검사 명령 — `gradle check`.** 실무와 같은 빌드 도구로 묶는다. **구성 파일은 과정이 주지 않고 수강생이 코딩 에이전트의 도움으로 만든다**(실습 8~9) — 빌드 구성도 위임의 대상이다. 강의 저장소(`code/sNN/`)도 javac + `run-tests.sh`에서 Gradle로 전환한다(09 원고를 쓸 때).
- **V 모델 — 이름은 쓰고 출처는 달지 않는다.** 분야의 통용 개념이며, 원문을 확인하지 못한 관점은 출처 없이 과정의 설명으로 쓴다는 「인용과 추론」 결정을 따른다. 단계의 순서가 아니라 대응 관계로만 가르친다.
- **환경 설정은 슬라이드가 끝까지 안내한다.** Claude Team 로그인 뒤의 모든 단계(도구 확인, 저장소 초기화, 빌드 구성, 에이전트 권한, 검사 명령)를 해당 세션 슬라이드에 둔다 — 01 도구 확인, 08 저장소·빌드·권한, 09 검사 명령. 별도 사전 설치 안내 문서나 강사 구두 설명에 맡기지 않는다. 도구의 기능을 가르치는 것과 환경 단계를 안내하는 것을 범위에서 구분해 적었다(2026-10-21).

## 남은 작업 메모

- 강의 저장소의 Gradle 전환은 09 작업에서 한다. 그때까지 `code/sNN/`은 javac + `run-tests.sh`로 둔다.
- 실습 1~5의 기존 대화 기록(`code/sNN/exercise-conversation/`)과 `code/s01/subscription/`은 **정기배송 사례의 것이라 모두 버린다.** 해당 실습을 다시 쓸 때 주문 사례로 다시 실행한다.
- **OOAD와 같은 시나리오로 맞춘다**(2026-10-21 결정). 두 과정이 주문 시스템의 주문한다를 쓰고, 가르치는 것으로 경계를 가른다 — OOAD는 정적·동적 모델의 상세와 **표기법**, 이 과정은 **결정과 검사**이며 표기법을 가르치지 않는다. 이 과정에서 다이어그램은 LLM이 만들고 사람은 읽고 판정하므로, 04·05는 다이어그램과 함께 **목록**(용어·관계·불변 조건·전이·금지된 순서)을 두고 판정의 근거로 쓴다.
- **OOAD도 같은 주문 사례로 정렬한다 — 과정 설계는 고쳤고 원고는 뒤에 한다(2026-10-21).** OOAD의 `course-design.md`를 주문 사례로 고쳤다(도메인 하나, 실습도 주문, 강의는 발췌·실습은 완성). **세션 원고 13개의 실습·별첨은 이 과정의 전면 보완이 끝난 뒤에 정렬한다** — 고칠 목록과 순서는 `courses/ooad/checks/exercise-realignment.md`에 있다. 상태 기계의 원천은 OOAD의 전체(취소됨 포함)이고 ai-native는 주문한다 한 과제만 쓴다.

## 작업 순서

1. 01부터 11까지 순서대로. 세션마다 인용 확인 → 구성안 승인 → 원고 → 렌더링.
2. 01·02는 현 s01을 둘로 가르는 작업이다. 비용의 구조가 신규이므로 02의 인용을 먼저 확인한다.
3. 04·05는 현 s03을 둘로 가르고 각자의 검사를 더하는 작업이다.
4. 07은 신설이다. 현 s04의 설계 원칙과 s05의 작업 단위를 입력으로 쓴다.
5. 08은 실습 저장소가 확정된 뒤에 쓴다.
6. 전부 끝나면 이 문서를 지운다.
