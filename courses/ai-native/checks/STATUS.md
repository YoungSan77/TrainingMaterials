## 재검토 방식

- 2026-11-26 **원점 재검토** 결정. 이전 설계의 교육 목표·성과(O01~O12)·목차·세션 구성·시나리오·실습 구조를 출발점으로 삼지 않았다. 보편적 SW 공학 원칙과 AI 등장으로 인한 변화에서 독립적으로 도출한 뒤 비교했다.
- **단계별 결정 경과** — ① 과정의 정체성과 교육 필요성 ② 교육 대상과 선수지식 ③ 교육 목적 및 목표 ④ 핵심 교육 내용과 범위 ⑤ 교육 접근법 ⑥ 성과 처리(측정하지 않음) ⑦ 과정 구성과 시간 배분. 각 단계를 Human과 논의해 합의했고 결과는 `course-design.md`와 `curriculum.md`가 소유한다.
- **합의된 정체성** — AI-native SW Engineering은 SW 공학의 보편적 원칙을 기반으로 인간과 AI의 능력 및 제약을 고려하여 소프트웨어 개발·딜리버리·운영·진화의 수행 방식을 재구성하는 공학적 접근이다.
- **합의된 편성** — 순수 교육시간 700분(50분 블록 14개), 강의·토의 395분 · 실습 280분(40.0%) · 환경 설정 25분. 핵심 SW 공학 활동 10블록 500분(71.4%). 세션 12개, 실습 12개.
- **수강생 평가 없음** — 교육 성과를 측정하거나 평가하지 않는다. 최소 달성선·역량 입증 기준·평가표를 설계하지 않는다. 점검항목은 학습 도구다. 과정 자체의 품질 검증은 성과 측정과 구분한다.

## 문서 책임의 구분

- **Course Design** — 과정 정체성, 교육 목적·목표·대상·범위, 공통 판단 원칙, 교육 접근법, 시간 제약.
- **Curriculum** — 세션 구성, 시간 배분, 세션별 목표, Anchor Message, 실습 편성과 연결 관계.
- 세션별 상세 시간의 원천은 Curriculum이며 Course Design은 중복 정의하지 않는다.

## 단계 계약 충돌 — 해결됨 (2026-11-26)

이전에 보고한 충돌(「필수 항목」이 "필수 학습 성과와 관찰 가능한 실패 조건"을 필수로 규정)은 **공통 지침을 최소 범위로 보완해 해결했다.** 교육 목표의 정의는 필수로 두고, 별도의 학습 성과 정의와 실패 조건은 **과정의 목적과 교육 방식에 따라 선택**하도록 바꿨다. 과정별 예외는 두지 않았다.

수정한 지침 — `guides/course-design-guide.md`(「목적」·「필수 항목」·「실습 방향」·「판단 기준」·「내용 완성과 시간 평가」·「Downstream handoff」), `guides/curriculum-dd-guide.md`(Curriculum 필수 검사), `guides/session-authoring-guide.md`(세션 목표의 연결), `guides/governance.md`(「단계와 정본」의 Course Design 소유 항목). 기존 기능·검사·단계 계약의 다른 요구사항은 바꾸지 않았고, 다른 과정의 교육 목표나 성과 정의도 바꾸지 않았다.

## 비교 자료와 복구

- **이전 설계** — `course-design.md`·`curriculum.md`의 이전 내용은 Git 커밋 `764ac26`에 있다. 필요하면 그 커밋에서 꺼내 비교한다. 이전 설계는 새 설계의 전제나 제약이 아니다.
- **이전 원고** — `sessions/s01.md`~`s12.md`는 이전 설계의 Deck 원고다. **비교 자료이며 현재 승인 정본이 아니다.** 새 세션 구성과 세션 번호가 달라졌으므로 번호로 대응시키지 않는다.
- **`production-standard.md`** — 이전 설계의 과정별 제작 기준이다. 새 설계의 승인 범위가 아니며 비교 자료로 둔다.
- **제거한 것** — PPTX·QA, 실습 실행 증거(`sessions/code/**`), 과거 검토 기록, 실제 응답 등록부(`recorded-responses.json`·`recorded-checks.json`), git 제외였던 시각 검토 출력(`out/`). 추적 파일은 `79cba69`에서 꺼내고, `out/`은 git 제외라 그 커밋에 없으므로 PPTX를 꺼내 다시 만든다.
- **실제 응답 검증** — 등록부를 제거했으므로 원고에 `**실제 LLM 응답**` 범위가 표시돼 있으면 재등록 전까지 `execution provenance missing or ambiguous`로 중단된다. 검사의 결함이 아니라 등록부 부재다. 새 실습의 실행 원본과 SHA-256으로 다시 등록한다.
