- **단계별 결정 경과** — ① 과정의 정체성과 교육 필요성 ② 교육 대상과 선수지식 ③ 교육 목적 및 목표 ④ 핵심 교육 내용과 범위 ⑤ 교육 접근법 ⑥ 성과 처리(측정하지 않음) ⑦ 과정 구성과 시간 배분. 각 단계를 Human과 논의해 합의했고 결과는 `course-design.md`와 `curriculum.md`가 소유한다.
- **합의된 정체성** — AI-native SW Engineering은 SW 공학의 보편적 원칙을 기반으로 인간과 AI의 능력 및 제약을 고려하여 소프트웨어 개발·딜리버리·운영·진화의 수행 방식을 재구성하는 공학적 접근이다.
- **합의된 편성** — 순수 교육시간 700분(50분 블록 14개), 강의·토의 400분 · 실습 280분(40.0%) · 환경 설정 20분. 핵심 SW 공학 활동 10블록 500분(71.4%). 세션 12개, 실습 12개.

**시각 검토 — 17장 전부 수행**(2026-11-27). `tools/review-pdf.sh`가 PowerPoint 컨테이너에 파일을 복사하다 macOS에 막혀 있었다(`Operation not permitted`). 복사를 없애고 **저장소 경로의 PPTX를 그대로 열어 `out/review/<sNN>/`에 PDF를 쓰도록** 고쳤고, AppleScript를 `with timeout`으로 감쌌다. **이전 상태 — 시각 검토를 수행하지 못했다.** `tools/review-pdf.sh`가 PowerPoint 컨테이너(`~/Library/Containers/com.microsoft.Powerpoint/Data/Documents`)에 파일을 복사할 수 없고(`Operation not permitted`), 이 기기에 LibreOffice도 없다. 대신 `tools/slide-density.js`로 재어 **장당 485자(권장 350~800), 최대 758자, 얇은 장은 표지 하나**임을 확인했다 — 넘침의 수치 근거이며 **겹침·잘림의 눈 검토를 대신하지 않는다.** 도식은 2개로 권장치(4 이상)보다 적은데, 이는 S01의 승인된 구성이다.

## 과정 고유 결합을 renderer와 지침에서 걷어냄 (2026-11-27)

세션 목표 게이트가 `01. 세션 목표`라는 **번호 붙은 제목**에 묶여 있었다. 목표 앞에 topic 하나를 끼워 넣으면 목표 7개 제한과 한 장 제한이 **아무 말 없이 꺼진다** — 통과했다고 나오는데 검사는 돌지 않은 상태다. 존재 확인을 `checkDeckShape`로 떼어 **이름으로 찾고 없으면 오류**로 바꿨다(요약도 같다). 번호는 있어도 되고 없어도 된다.

그 과정에서 더 깊은 결합이 드러났다. **renderer가 과정 폴더 이름(`ai-native`) 하나와 세션명 세 개로 조판을 바꾸고 있었다** — 문단 간격(3pt↔6pt), 요약형 인용의 표시 따옴표, 번호 내어쓰기, 코드 들여쓰기, 별첨의 표 배치. 그 세션명들은 2026-11-26 편성 개편으로 사라졌는데 코드에 남아, 새 S03을 쓰면 **옛 S04의 조판이 걸릴 상태**였다. 같은 결정이 `production-standard.md`에는 글로, `builder.js`에는 세션명 비교로 **두 곳에 적혀** 있었다.

- **지운 것** — `course.js`의 `productionProfile`(과정 폴더 이름), `builder.js`의 `s03Profile`·`s04Profile`·세션명으로 켜던 `mixedTables`, `paragraphs.js`의 세션별 간격·인용·여백 분기. 배치 게이트 세 개(`draft-diagrams`·`draft-review`·`comparison`)와 `firstDraftReviewPage`·`draftSequenceWindow`도 지웠다 — 교재의 표 제목·열 이름·도식 라벨(`Before — 상태 기계`, `Order->>Payment`)을 renderer의 합격 조건으로 적어 둔 것이었고, 그 표식을 쓰는 원고는 하나도 없었다.
- **표식으로 바꾼 것** — 단내 표는 `**문서 형식 — 단내 표**`, 도식과 표를 한 장에 두는 배치는 `**배치 — 도식과 표 한 장**`이 요청한다. 도식·표 제목은 각자의 표식에서 읽는다.
- **회귀 방지** — `course-independent-typography.test.js`가 같은 원고를 과정명·세션명만 바꿔 렌더해 조판이 같은지 확인한다. 세션명으로 조판을 가르는 코드가 다시 들어오면 실패한다.
- **지침 분리** — 「목차 첫 항목은 `01. 세션 목표`」를 범용 지침 두 곳에서 떼어, 덱의 앞 세 장(표지·과정 목차·세션 목차)만 공통으로 두고 **목표가 몇 번째인지는 과정이 정한다**로 바꿨다. 목표 앞에 맥락을 세우는 도입 topic을 둘 수 있다. 폐지된 DD를 가리키던 조항 7곳과 「참조 PPTX」 조항도 현재 계약에 맞게 고쳤다.
- **별첨 레이블 대조** — 별첨은 **현행 세션**(승인 Curriculum과 세션명이 같은 원고)이 쓰는 레이블만 요구한다. 아직 쓰지 않은 세션이 있으면 「아무도 쓰지 않는 레이블」 검사는 돌리지 않고 `미검사:`로 적는다 — 돌리지 못한 검사를 경고로 내면 지울 수 없는 경고가 완료 기준을 막는다.

**결과** — 전체 테스트 366개 통과. `courses/ai-native/sessions/s01`은 18장·오류 0·경고 0이고 `tools/check-rendered.js`도 오류 0·경고 0이다(PDF 재생성 후). `courses/ai-native/sessions/references.md`는 오류 8 · 경고 19에서 **오류 0 · 경고 0**이 됐고 `미검사:` 두 줄이 남는다.

## S01에 도입을 넣고 시각 검토 (2026-11-28)

본문을 **AI와 LLM이 바꾼 것** 3장으로 연다. 덱은 표지·과정 목차·세션 목차 다음에 **세션 목표(4장)**, 그 뒤가 도입 3장(5~7장)이다(2026-11-28 사용자 결정). 목표를 먼저 보이고 도입이 그 목표를 사실로 받친다 — 목표의 첫 줄이 왜 거기 있는지를 도입 세 장이 답한다. 인용 세 개는 모두 원문 확인된 것이다([Hassan 외 2026]·[METR 2025]·[Willison 2025b]). 목표와 요약을 네 줄로 맞추고 요약이 목차의 본문 주제를 빠짐없이 닫게 했다(08의 로컬 품질 게이트 포함). 18장 → **21장, 오류 0 · 경고 0**이며 `tools/check-rendered.js`도 오류 0 · 경고 0이다. 3~7장과 21장을 PDF로 눈으로 확인했고 겹침·잘림·넘침이 없다.

**`tools/review-pdf.sh`가 사람의 PowerPoint를 막던 것을 고쳤다.** 2026-11-27에 「문서가 열려 있으면 거절」을 넣었던 이유는 `save active presentation`이 **맨 앞 문서**를 내보내 엉뚱한 파일이 나오는 것이었는데, 전제가 틀렸다 — 내보낼 문서를 **이름으로 가리키면** 맨 앞이 무엇이든 상관없다. 이제 다른 파일이 열려 있어도 그냥 돈다. **같은 파일이 열려 있을 때만** 거절한다. 열린 창은 디스크를 덮어써도 갱신되지 않으므로 그대로 내보내면 **옛 덱이 새 덱인 양** PDF로 나오기 때문이고, 저장하지 않은 편집이 있을 수 있어 스크립트가 닫지 않는다.

## 외부 검토(ChatGPT·Codex) 반영 (2026-11-28)

두 검토를 대조해 **합의되거나 원고에서 확인된 것만** 반영했다. 검토 자료는 승인 기준이 아니며 저장소 기준의 변경 권한을 주지 않는다(`guides/governance.md` 「책임과 승인」).

**반영**

- **측정값을 넣었다**(Codex) — 06절이 기대 24%·체감 20%만 보이고 **실제 측정**을 빼 비교의 한쪽이 비어 있었다. METR의 핵심 결과(**19% 지연**)를 인용으로 올리고 기대·체감은 본문과 강사 노트로 내렸다. 새 인용은 원문 확인 기록에 등록했다.
- **부분의 속도와 전체의 생산성을 갈랐다**(ChatGPT) — 「코드는 빨라지는데 전체는 느려질 수 있다면 AI가 개선한 것은 무엇인가」에 답하는 줄이 없었다. 06절 마지막 줄이 그 답이다.
- **「AI가 못 하는 것」의 정의를 고쳤다**(ChatGPT) — AI는 요청에 없는 업무 결정을 **제안하거나 임의로 채운다.** 못 하는 것은 그것이 업무적으로 맞는지 **판정**하는 일이다. 08절의 표현이 실제보다 AI를 무능하게 적고 있었고, 09절의 「임의로 채운다」와도 어긋났다.
- **테스트 단정을 위험으로 바꿨다**(ChatGPT) — "테스트는 그 코드에서 기대값을 가져와 통과한다"는 필연이 아니다. "코드와 테스트를 함께 생성하면 잘못 가정한 규칙에 맞춰 통과할 **위험**이 있다"로 고쳤다.
- **역할 분담을 조건부로 적었다**(ChatGPT) — 13절이 「사람이 한다·AI가 한다·함께 한다」로 고정해 12절의 「역할은 작업에 따라 달라진다」와 어긋났다. 업무 권한은 사람이 **책임지고**, 코드는 **조건이 맞으면** 맡기며, 검증은 **실행을 맡기고 수용은 사람이** 한다로 갈랐다.
- **대화형과 Agentic의 이분법을 정밀화했다**(ChatGPT) — 둘 다 요청과 맥락이 필요하고, 다른 것은 **갖추는 시점**이다(실행이 이어지는 동안 사람이 끼어들지 못하므로 미리 넣는다).
- **방식 선택 사례를 넣었다**(두 검토 공통) — 질문 작성은 대화형, 여러 파일 수정과 반복 실행은 Agentic, 판정할 수 없고 되돌리기 어려운 일은 범위를 좁히거나 사람이. 교환이 "그만큼 더 나은 결과를 얻을 때만" 맞는다고 단서를 달았다.

**반영하지 않음**

- **「17쪽 표·본문 겹침」(ChatGPT P0) — 재현되지 않는다.** PowerPoint가 내보낸 PDF에서 표 마지막 행과 아래 본문 사이에 간격이 있고, `tools/check-rendered-tables.py`가 21쪽·표 4개·셀 77개에서 issues 0으로 PASS한다(PPTX·PDF 해시 기록). 생성 때 도는 `tableLayoutChecks.js`의 경계 침범 검사도 통과한다. **재현되지 않는 결함으로 renderer를 고치지 않는다** — 어느 렌더러로 본 것인지 확인한 뒤 판단한다.
- **목표·요약 축약** — 사용자가 직전에 요약을 **보완**하라고 지시했다. 상충하므로 사용자 판정 전까지 바꾸지 않는다.
- **완성 프롬프트 제시**(두 검토 공통) — 넣지 않는다(2026-11-28 사용자 판정). 완성된 요청을 **쓰고 고쳐 보는 일**은 실습의 몫인데 이 세션에는 실습이 없다(환경 설정뿐). 개요가 할 일은 요청을 이루는 **다섯 요소를 가려내는 것**까지이고, 실제 작성은 그 요소를 처음 쓰는 "세션 02. 요구사항"의 실습이 맡는다. 거기 넣으면 답을 미리 보이는 문제도 함께 사라진다.

**추가**(2026-11-28 사용자 지시)

- **「활동마다 AI가 하는 일이 다르다」 한 장을 04절에 더했다.** 승인 Course Design의 **교육 목표 2**(「활동별로 달라지는 수행 방식을 안다 — 각 공학 활동에서 수행 방식·산출물의 역할·작업의 분해와 할당이 어떻게 달라지는지」)가 이 장을 요구한다. 표는 활동 다섯(요구사항·도메인 모델·아키텍처·설계·코드·자동 테스트)마다 **AI가 하는 일**과 **사람이 확인할 것**을 가른다. 뒤 세션과 겹치더라도 수강생의 이해를 먼저 둔다 — 깊이는 그 활동을 맡는 세션이 사례로 주고, 이 표는 어디서 무엇을 배울지 가리키는 지도다.
- **「단계」를 「활동」으로 고쳤다** — 11절 표의 제목·열 이름과 그 강사 노트. 승인 Course Design과 04절 제목이 **공학 활동**이라 쓰고, `guides/sw-engineering-principles.md`가 흐름을 **반복**으로 전제한다. 「단계」는 순서가 고정된 절차를 뜻해 10절 도식의 피드백 화살표와 어긋난다.

**결과** — 21장 → **22장**, 오류 0 · 경고 0, `check-rendered.js` 0 · 0, `check-rendered-tables.py` PASS(22쪽·표 5개·셀 95개). 6·9·11·12·13·17·18장을 눈으로 확인했다.

## 확인이 필요한 현실 조건

**[확인 필요]** 아래는 제품·계약·교육장 조건이어서 설계로 정할 수 없다. 대표 실행과 파일럿 전에 확인한다.

- Claude Team의 좌석 발급 주체와 수강생 20명 안팎의 동시 사용 가능 여부
- 동시 사용 시의 사용량 한도와 초과 시 동작
- 교육장 PC의 설치 권한과 사내 네트워크(프록시·방화벽)
- 실습에 투입할 자료의 데이터 정책 — 과정이 제공하는 사례로 한정하는 것이 안전하다
- 교육 시점의 도구·모델 변경 — 대표 실행 기록에 실행 일자와 도구·모델을 함께 적는다
- **유료 자료의 구매 여부** — [Ousterhout 2021]·[Wiegers 2013]·[Bass 외 2021]과 요구사항·품질 모델 표준의 본문. 구매하지 않아도 과정은 성립하며(「12. 원전 적용 결정」), 축자 인용의 범위만 달라진다
- **Windows 설치 경로** — 전원이 Windows이므로 설치는 Windows 하나만 지원한다. 확인할 것은 **Windows 버전과 `winget` 사용 가능 여부, 사용자 범위 설치 권한, 사내 프록시에서의 패키지 저장소 접근**이다. 확인되지 않으면 오프라인 배포물이 유일한 경로다
- **`.sh`를 실행할 셸** — Windows에는 기본 셸이 없고 Git Bash는 Git과 함께 설치된다. **Git을 설치하기 전에는 `.sh`를 실행할 수 없으므로** 첫 단계만 PowerShell로 하거나 Git을 사전 설치해야 한다. 어느 쪽으로 할지는 교육장 조건을 확인한 뒤 정한다
- **경로와 줄바꿈** — 사용자 이름이 한글이거나 공백이 있는 홈 경로(`C:\Users\홍길동`)에서 JDK·Gradle 경로가 깨지는지, 저장소의 `.sh`가 CRLF로 체크아웃되어 실행되지 않는지 확인한다
- **Claude Code CLI 설치 소요 시간** — 공식 설정 문서(2026-11-26 확인)의 절차는 설치 → `claude --version`/`claude doctor` → `claude` 실행 후 브라우저 로그인이다. 환경 설정 20분 가운데 **설치 배정 시간은 추정**이며 네트워크와 설치 권한에 좌우된다. 파일럿에서 측정해 고친다
- **Claude Code Desktop 앱 경로** — 터미널 없이 쓰는 경로가 공식 문서에 있는 것은 확인했으나 **교육장 환경에서 검증하지 않았다.** 검증 전에는 수강생에게 안내하지 않는다. 설치 자체가 막힌 경우에는 이 경로도 막히므로 대체가 되지 않는다
- **Team 계정의 CLI 로그인** — Claude Code는 Pro·Max·Ultra·Team·Enterprise·Console 계정을 요구하고 무료 플랜을 제외한다(공식 문서, 2026-11-26 확인). **Team 계정으로 CLI에 로그인할 때 관리자 설정이 필요한지는 확인하지 않았다.** 과정은 API Key를 쓰지 않으므로 설정 전에 `ANTHROPIC_API_KEY`가 설정되어 있지 않은지 확인한다
- **로컬 검증의 표현** — CI를 구축하지 않기로 했으므로 확인할 조건은 CI 계정·네트워크가 아니라 **로컬 검증 결과를 CI 통과로 바꿔 말하지 않는지**다. 원고·실습 안내·실행 증거에서 "로컬 검증 PASS"와 "CI 통과"를 가른다

파일이 있다는 사실만으로 현재 설계의 승인이나 완료를 판단하지 않는다.
