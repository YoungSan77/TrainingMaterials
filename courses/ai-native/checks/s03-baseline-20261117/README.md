# AI-native 과정 정합화 및 S03 확장 기준본 검증

검증일: 2026-11-17(KST). 저장소 루트의 `AGENTS.md`와 현재 작업 트리를 확인하고 `courses/ACTIVE=ai-native`를 유지했다. 시작 시 광범위한 미커밋 변경이 있었으며 이를 초기화·되돌리기하지 않았다. 커밋·푸시는 하지 않았다.

## 과정 설계와 공통 계약

- 과정 설계의 잠정 시간표: 강의·결과 비교 490분, 실습 210분, 작업 700분. S12는 기존 1시간을 유지해 강의·결과 비교 25분·실습 25분. 다른 세션 시간은 유지했다. 모든 실습 상한은 예외 없이 25분이다. 세부 개념 목록을 직접 세어 S03 14개·전체 122개를 검산했다(`verification.json`). 개념당 시간은 분량 검토 지표이며 전체 시간 적합성은 과정 완성 후 평가한다.
- S12 수강생 필수 수행: 기존 저장소·앞 산출물·검사 명령으로 대표 단위 하나 위임 → 결과 검사 → 배송 요청 실패에 AI가 채운 근거 없는 정책 식별 → 사람의 결정·수용 사례·검사 반영과 재실행. 결과물은 지시·응답·diff·검사 출력 및 정책·수용 사례·검사 보완 기록이다. 나머지 단위 연결·전체 완료 증거는 강사의 검증된 실행 기록과 비교한다. 수료 목표·세션 목표·실습 설명·결과물 표를 같은 범위로 맞췄다.
- S08은 저장소·빌드 준비와 위임 계약, S09는 권한을 적용한 첫 업무 코드 실행, S10은 검사 통합·반복 실행이다. 앞 실습이 부족하면 마지막 검증 저장소 상태에서 재개한다. 환경 장애 시 기록 기반 판단을 연습하되 직접 실행 완료와 구별한다.
- S03에 맞춰 이번 구현의 주문 상태는 결제대기·결제완료 2개로 정렬했다. 배송중·배송완료와 통보는 전체 생명주기 설명용으로 한정했다. ‘주문한다’ 스토리 하나와 네 위임 작업 단위를 구별하고 정의서와 작업 명세서의 목적을 정렬했다. `subscription` 예를 제거했다. 배송 요청 실패 결정이 다른 미정(`UNCONFIRMED` 등)의 해결을 뜻하지 않도록 완료 범위를 명시했다. 시연 질문 수·새 모델 실패 증가를 근거 없이 사실로 단정하던 문구를 바로잡았다.
- 과정별 제작 기준의 새 위치: `courses/ai-native/production-standard.md`. 기존 과정별 제작 기준 문서가 없어 하나를 만들고 공통 Production Guide의 「S03 제작 기준」 절을 옮겼다. 장 배치·글꼴·여백·참조 PPTX·실행 기록 경로·승인 조건이 여기에 있다. 과정 설계에서 이를 참조한다.
- 공통 지침에는 승인 원고 인계·실제 응답 보존·최종 전 장 렌더링·지정 수치의 PPTX 전수 검사·공통 렌더러 회귀만 남겼다. SW 공학 원칙에서는 수용 사례(기대 결과의 합의)와 실행 테스트(실행 증거)를 구분하고 요구사항에서 필요한 모델·설계 제약·검사를 참조하도록 맞췄다. AGENTS와 센서 표도 함께 정렬했다.

## 의존성 조사와 렌더러

규칙 이동 전 `engine/production/src/`·테스트·도구의 제목·경로 의존을 조사했다. 렌더러는 지침 Markdown을 읽어 수치를 가져오지 않았으며 `03. 요구사항` 세션명과 topic 제목에 따른 예외를 갖고 있었다. 참조 검사기는 ‘제작 지침의 「SNN 제작 기준」’을 세션명과 구분하는 정규식을 사용했다.

- `course.js`는 AI-native 폴더의 과정에만 `ai-native-s03` profile을 전달한다. builder·paragraphs·inspect의 기존 S03 예외는 profile과 세션명을 함께 확인한다. 다른 과정에 같은 세션명이 있어도 기본 문단 간격·인용 서식을 유지하는 fixture를 추가했다. 기존 기본 서식을 바꾸지 않았다.
- `references.js`와 테스트는 이동된 제작 기준 문서 참조도 인식하며 같은 줄의 실제 잘못된 세션 참조를 계속 검출한다. S03 MD 변경은 638행의 제작 기준 참조 경로 하나뿐이며 승인 본문·프롬프트·발췌는 보존했다.
- `inspect.js`는 profile 대상 모든 표 셀의 사방 54000EMU와 열 너비 합·frame 폭을 검사한다. 마지막 셀의 각 여백과 frame 폭을 손상시켜 검사 실패를 확인하는 테스트를 추가했다.
- 최종 렌더 대조 중 28쪽 표의 가격 변경 사례가 실제 3줄인데 계측이 2줄로 잡히는 결함을 발견했다. `tableRowMetrics.js`에서 한글 어절을 우선 유지하도록 수정하고 재현 테스트를 추가했다. 표 문구·글꼴·여백은 바꾸지 않았다. 최종 PDF의 모든 셀을 다시 대조해 해결을 확인했다.

최종 PPTX·QA는 같은 현재 S03 입력에서 생성했다. 입력·출력·QA의 경로·SHA256·수정 시각과 Node/renderer 버전은 `verification.json`에 기록했다. 실제 응답은 `sessions/code/s03/exercise-conversation/production-2026-11-16/`의 시연 1턴·실습 3턴을 재사용했다. 현재 시연 입력·실습 첫/마지막 요청·첨부 2개와 일치하며, 종료코드 0과 JSONL의 마지막 agent_message/응답 전문 및 선택 발췌를 대조했다. 새 LLM 실행은 0회다.

최종 렌더 증거는 저장소의 `out/review/s03/s03.pdf`, `p-01.png`~`p-30.png`, `s03-bbox.html`이다. PDF·PPTX 해시는 `render-verification.json`에 있다. 최종 30장을 모두 눈으로 확인했다. 기존 별첨 설명이 30쪽으로 이어지는 배치는 보존했다.

전체 renderer 테스트 최종 **307/307 통과**. 범위 밖 대표 세션 `courses/ooad/sessions/s02.md`는 정식 파일을 덮어쓰지 않고 `out/ai-native-baseline-20261117/ooad-s02.pptx`로 생성했다. 93장·표715셀 기본10pt·오류0을 확인했다(`regression.json`). 이 대표 세션의 기존 경고6개는 범위 밖 원고 항목이며 시각 검증은 수행하지 않았다. 고정 fixture 전체 테스트와 동일 세션명 타 과정 기본값 분리 테스트가 출력 회귀를 함께 확인한다.

## 미해결·미확인과 승인 경계

- S03 경고51개는 표 줄바꿈21, 핵심어 강조24, 목록 머리말5, 요약 노트의 모델 보완 기록1이다. 전체 문구는 QA에 그대로 있다. 표21건은 이번 실제 행 높이·PDF 대조를 통과했지만 일반 원고 정책 경고는 남겼다. 목록5건은 실제 응답의 원문 구조다. 실제 응답을 고쳐 경고를 없애지 않았다. 강조와 요약 기록도 승인 본문을 임의로 다시 저작하지 않았다. 경고 면제·기준 완화나 Human의 승인 완료를 추정하지 않았다.
- `references/inputs/s03-op.pptx`는 존재를 확인하고 경로·해시·장 수를 기록했다. 현재 명시된 제작 계약이 우선이며 이전 조정본을 내용 원천으로 쓰지 않았다. 이전 기준에 이름이 남아 있는 `s03_or.pptx`는 제공된 접근 가능 파일 목록에 없어 그 파일과의 메모별 대조는 NOT VERIFIED다. 다른 파일로 대체하지 않았다. 보호된 참조 폴더는 접근하지 않았다.
- 배송 요청 실패 정책의 실제 교육용 결정은 S12에서 사람이 정할 대상으로 유지했다. `UNCONFIRMED` 후속 정책·다른 미정은 이번 완료 범위가 아니다. 모델 비교 실패 증가의 실측 결과는 이번에 만들지 않았으며 과정 설계에서는 가설로 구분했다.
- 기준본의 기계적·렌더 검증 결과와 최종 승인 조건을 구별한다. 경고51개와 미확인 조정본 대조가 남아 있어 **SA 완료·Human 기준본 승인 완료로 선언하지 않는다**. 다른 세션의 정식 제작은 시작하지 않았다. S12 등 다른 세션 원고의 기존 문구는 다음 저작 단계에서 새 과정 설계에 맞출 대상이며 이번 설계·S03 검증과 구분한다.
