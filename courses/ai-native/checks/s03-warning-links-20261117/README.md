# S03 경고 전수 분류와 두 페이지 연결 검증

검증일: 2026-11-17(KST). 저장소 루트에서 현재 작업 트리, `courses/ACTIVE=ai-native`, 직전 `checks/s03-baseline-20261117/README.md`와 `production-standard.md`를 확인했다. 이번 범위는 기존 경고51개와 17→18·29→30쪽 연결뿐이다. 기존 미커밋 변경은 보존했다. 승인 S03 MD는 수정하지 않았고, 다른 세션 제작·기준본 승인 선언·커밋·푸시는 하지 않았다.

**원본 경고마다 검사 함수·원고 경로·행·표 열·판정 근거·처리·수정안을** [warning-audit.md](warning-audit.md)에 기록했다. 같은 원인의6개 묶음에도 발생 행과 건수를 적었으며, 기계 판독본은 `warning-audit.json`이다. 기존 QA51개는 `before.qa.json`으로 보존했다. 인용문이라는 이유만으로 강조 검사를 면제하지 않았다. Larman 정의 인용은 한국어 핵심어의 강조 수정안을 제시하고 영어 원문은 보존한다.

`structure.js`의 표 한 줄 검사는 과정 profile·동일 topic·8pt 계약·해당 표의 **모든 행과 생성 manifest의 대응**이 확인될 때만 일반10pt 경고를 제외한다. 다른 과정·다른 topic·10pt·대응 행 누락에서는 기존 경고가 유지된다. 표 내용·글꼴·여백·폭 검사와 최종 렌더 검증은 그대로다. 핵심어 검사는 닫힌 파일명 목록·파일명→다음 실습 입력 형식만 명사 목록으로 구분하며, 뒤에 수행 지시가 붙으면 경고한다. topic 전체나 실제 응답 전체를 새로 제외하지 않았다.

새 `s03-warning-links.test.js`는 정상 입력·실제 위반·동일 제목의 다른 topic/profile·대응 행 누락을 함께 검사한다. 실제 프롬프트2개와 목록 소개5개는 원문 보존과 일반 저작 규칙의 충돌로 남겼으며 일괄 억제하지 않았다.

## 페이지 연결 전후

| 대상 | 이전 | 최종 | 결과 |
|---|---|---|---|
| US-01 제목·설명·인수 조건 | 제목·설명17쪽, 인수 조건18쪽 | 전부17쪽 | 같은 오른쪽 열의 편집 가능한 텍스트 개체 하나에 제목·설명·인수 조건·발췌 생략 표시를 함께 배치 |
| 판매가와 기록 단가 구분 | 용어표29쪽, 구분 문장30쪽 | 표·구분 문장 모두29쪽 | 같은 열에서 표 바로 아래8pt 간격. ‘9. 미정 사항’ 제목·본문·목록·생략 표시는30쪽에 함께 유지 |

먼저 묶음 전체가 들어가는지 높이를 계산했다. 시연의 ‘용어 / 정의’ 표와 별첨의 ‘용어 / 표기 / 정의’ 표에 일반10pt·0.8cm 추정 높이를 사용하던 탓에 실제8pt 표 아래 공간을 과소평가했다. 두 표의 현재 열 너비·사방54000EMU·실제8pt 행 높이로 계획하도록 범위를 한정해 수정했다.

US-01을 한 묶음으로 다음 열·장에 옮기는 대안도 검토했다. 보수적인 이전 표 높이로 묶음을 옮기면31장이 되었으나, 실제 표 높이를 적용하면17쪽에 묶음 전체가 들어가므로 그 대안을 채택하지 않았다. 문구·순서·글자 크기를 줄일 필요가 없었다. 별첨 역시 실제 높이로 계획하니 구분 문장을29쪽에 담을 수 있었다. 미정 사항 전체를 묶어 생략 표시만 마지막 장에 남는 부수 문제도 막았다.

최종은 **30장**이며, 직전 정식 PPTX 대비 XML이 바뀐 장은 **17·18·29·30쪽**뿐이다. 나머지26장은 바이트 단위로 동일하다. 승인 MD의 SHA256은 직전 기준본과 동일하다. 모든 문단의 문구·run 글꼴 크기·강조, 모든 표 셀 XML을 이전 출력과 전수 대조했다. 시연17~19쪽과 별첨26~30쪽은 좌→우·위→아래 읽기 순서로도 원문 순서가 동일하다(`verification.json`).

## 최종 검증

- 관련 테스트로 수정 중 영향을 확인하고 마지막에 저장소 규칙에 따른 renderer 전체 테스트를1회 실행했다. **311/311 통과**, 오류0. 정상 표·실제 위반·경로 목록·문장·US-01 묶음·8pt 용어표의 높이와 후속 설명 회귀를 포함한다.
- 최종 PPTX·QA를 생성하고, **최종 전30장을 PowerPoint로1회 렌더링**했다. `out/review/s03/s03.pdf`, `p-01.png`~`p-30.png`, `s03-bbox.html`이 증거다. 변경과 인접 **16·17·18·19·28·29·30쪽(7장)**을 시각 검토해 두 연결의 누락·겹침·잘림이 없음을 확인했다.
- 표 **254셀** 전수 검사: 본문121셀10pt, 시연50셀·판단표18셀·별첨65셀은 모두8pt. 모든 셀 사방 여백은 각각54000EMU다. 셀 XML의 문구·서식도 이전 출력과 동일하다. 표 frame 폭=열 너비 합, frame 높이=행 높이 합을 확인했다.
- 최종 PDF에서254셀의 텍스트가 PPTX와 모두 일치하며 행 밖 넘침0, 페이지 밖 텍스트0이다(`render-verification.json`). 시연 입력·실습 첫/최종 요청과 저장 실행, 선정 발췌도 보존됐다. 새 LLM 실행은0회다.
- 자동 검사는 **오류0·경고28**이다. QA의 `visual_status=NOT_VERIFIED`는 자동 생성 필드로 유지하며 별도 렌더 검증 기록과 구별한다. 경고0이나 기준본 승인을 뜻하지 않는다.

산출물은 `courses/ai-native/sessions/s03.pptx`·`s03.qa.json`이다. 동일 입력 버전의 원고·PPTX·QA 경로·해시·수정 시각, 변경 장·연결 위치·글꼴·여백 검사는 `verification.json`, 최종PDF/PPTX 해시와 실제 출력 대조는 `render-verification.json`에 있다. 이전 PPTX·PDF는 `out/s03-warning-links-before.pptx`·`out/s03-warning-links-before.pdf`에 별도로 보존했다.

## 승인 전에 남은 항목

1. 저자 문장 강조20개와 요약 노트의 모델 보완 기록1개: [전수 분류와 수정안](warning-audit.md)의 해당21개 수정안을 검토해 원고에 반영하는 단계가 남았다. 이번 요청대로 수정안만 보고했고 승인 원고를 바꾸지 않았다.
2. 실제 프롬프트2개·응답 목록 소개5개: 실행 원문 보존과 일반 저작 규칙의 충돌이다. 원문을 고치거나 검사에서 숨기지 않았으며 QA에7건을 남겼다. 해당 원문을 그대로 수용할지의 판단은 기준본 승인과 구별해 기록해야 한다.

이 두 묶음 이외에 이번51개 경고 중 자료 부족으로 판정을 유보한 항목은 없다. 이번 검증 범위를 넘어 기존 기준본의 다른 승인 항목을 완료한 것으로 바꾸지 않는다.
