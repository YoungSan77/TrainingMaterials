# S03 8pt 표 실제 텍스트 높이 기준 행 높이 검증

대상 실제 장:17·18·20·28·29쪽,6표133셀. 원고와 실행 기록은 변경하지 않았다. 정식 출력은30장이다.

기존0.8cm 기본 행 높이와10pt 줄바꿈당12pt 추가 방식은 대상 표의 최종 행 높이로 쓰지 않는다. 설치된 실제 맑은 고딕 일반/굵은 글꼴을 fontkit으로 계측해 현재 열 너비·좌우 셀 여백에서8pt 줄바꿈을 구했다. 현재 PowerPoint PDF133셀의 실제 줄 수와 사전 계측이 전부 일치했다. 자연 줄 높이는10.640625pt, 위아래0.15cm 합은8.503937pt이며 문단 앞뒤0pt다. 각 행의 가장 높은 셀을 선택해 EMU 단위로 올림한다. 따라서1줄19.144567pt,2줄29.785197pt,3줄40.425827pt,4줄51.066457pt다.

`tableRowMetrics.js`는 글꼴·문단 간격·열 너비·좌우 여백을 읽어 행을 산정하고, table frame의 `cy`를 행 높이 합으로 덮어쓴다. 원래의 table frame 높이가 행을 다시 늘리지 않는다. 같은 열에서 뒤따르는 본문 배치는 새 표 높이 합+기존8pt 간격을 사용한다.17쪽 오른쪽 용어표 뒤 유저 스토리 설명은110.044724pt 위로 이동했다. 그 외 본문 배치는 보존했다. 기존의 페이지/열 배분은 유지하며 범위 밖30쪽 설명을 옮기지 않았다.

표별 전체 행의 변경 전후 높이와 frame 높이는 `rowfit-verification.json`, 각 셀의 줄 수·유효 폭·줄 높이·문단 간격은 `rowfit-measurements.json`에 보존했다. 최종6표 전부 frame 높이=행 높이 합이 성립한다. 내용·열 너비·글꼴·모든 셀 여백은 그대로이며, 대상 장의 행 높이/frame높이와 허용된 뒤 본문 y좌표 외에는 생성 전후 XML이 동일하다. 범위 밖25장 XML은 완전히 동일하다.

최종 정식 출력의 같은 파일을 `tools/review-pdf.sh courses/ai-native/sessions/s03.md 17-18 20 28-29`로 렌더링했다. 변경된5장만 시각 검토했다.

PDF 좌표와 실제 텍스트를 대조한133셀 전부 문구·줄 수가 같고 모든 마지막 줄이 표 행에 남는다(`rowfit-render-verification.json`). PDF 글리프 상자와 typographic line box의 원점 차이 최대0.299pt를 구별해1/3pt 허용치를 명시했으며, 셀 여백 자체는 OOXML값을 그대로 보존했음을 별도 비교했다.
