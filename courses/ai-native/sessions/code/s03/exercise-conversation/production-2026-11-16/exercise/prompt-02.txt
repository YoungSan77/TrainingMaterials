[앞선 질문에 대한 답 — 확인된 후속 조건]
두 첨부 문서에 없던 품질·사례 조건은 이번에 담당자가 제공한다. 다음은 실습 3 강사 노트와 Course Design 및 기존 확정 대화에 근거한 답이며, 새로운 운영 정책이 아니다.
- 사례는 주문 생성 시 판매가 1,000원인 펜 2개와 배송지 서울이다. 주문 금액은 2,000원이다. 가격 변경 상황은 주문 생성 뒤 판매가가 1,200원으로 오른 뒤 같은 주문을 결제하는 것이다.
- 카드 X는 거절되고 카드 Y는 승인된다. 승인 뒤 상태명은 결제완료(PAID), 거절 뒤는 결제대기(PENDING_PAYMENT)다. 같은 주문의 식별자를 보존한다.
- 정상 승인과 가격 변경 후 승인에서는 배송 요청 1회, 카드 거절 직후에는 0회, X 거절 뒤 Y 승인까지 전체 과정에서는 총 1회다. 금액은 카드 승인 요청 금액을 확인하며 카드 거절을 청구 완료로 취급하지 않는다.
- 기본 흐름 1 상품 조회, 2 장바구니는 전제이며 상세 범위는 3 배송지 확정, 4 결제, 5 주문 결과 확인이다. 본인 주문만 조회·변경할 권한이 있고 타인의 주문 조회·변경은 거절한다. 본인이라도 결제대기 주문의 상품·수량·배송지는 바꿀 수 없다. 인증 방법과 오류 코드·화면은 정하지 않는다.
- 정상 품질 시험은 외부 상품·결제·배송 시스템이 정상 응답하는 테스트 대역이고 각 응답이 1초 이내인 조건에서 카드 결제 요청 100건을 동시에 실행한다. 결제 요청부터 주문 결과 수신까지 100건 중 95건 이상이 3초 이내여야 한다. 운영 환경의 보장 수치가 아니다.
- 용어 표기는 주문(Order), 주문 항목(OrderItem), 판매가(salePrice), 주문 금액(totalAmount), 결제대기(PENDING_PAYMENT), 결제완료(PAID)다. 판매가는 상품 시스템의 현재 판매 가격이며 주문 생성 때 기록한 항목 단가와 구분한다. 이는 용어이지 설계가 아니다.
- 질문 1~26과 28~30 가운데 위 답으로 확인되지 않은 사항은 미정이다. H·B·F·E·G·I, 재고 판단 시점·호출 횟수, 승인 전 재고 부족의 처리를 새로 결정하지 않는다. 질문 27의 승인 뒤 상태명만 위에서 확정했다.

[추가 질문·수정 요청 — 첫 응답 검토]
기본 흐름 도식은 배송지 확정 전에 재고를 확인하고 재고가 없으면 주문을 진행하지 않는 것으로 고정했다. 그러나 확인 시점과 승인 전 부족 처리는 주어진 조건에 없다. 이 흐름을 확정 절차로 제시하지 마라. 승인 뒤 재고 확인의 호출 순서도 확정하지 마라.
미정 정책을 구현자가 임의로 채우지 못한다는 제약을 영구적인 무동작 정책으로 바꾸지 마라. 담당자 결정 전에는 해당 분기의 최종 수용 기준이 미완성이라고 구분해라. 입력의 기능 제외와 이번 요구사항 문서에서 작성하지 않을 모델·설계·코드 산출물을 구분해라.
사용자 스토리는 ‘주문한다’ 하나로 유지하고, 정상 승인·가격 변경·거절·재결제의 네 대표 상황마다 전제·사건과 동일 주문 여부·주문 금액·승인 요청 금액·상태·누적 배송 요청 횟수가 확인되도록 초안을 보완해라. 한 상황의 재결제를 새 주문 생성으로 바꾸지 마라. 확인된 조건만 반영하고 남은 미정 질문을 보존해라.
