지금까지 합의한 도메인 모델을 다음 실습에 사용할 간결한 Markdown 파일로 생성해라. 용어와 업무 규칙은 하나의 상위 절 안에서 별도 소제목으로 구분해라. 클래스·시퀀스·상태 머신은 독립 절에 plantuml:class·plantuml:sequence·plantuml:state 원본과 필요한 설명을 포함해라. 실습 2의 날짜·금액 조건을 반복하지 말고 참조해라. 새 결정을 추가하거나 폐기한 안을 되살리지 마라. 남은 미결 사항은 해당 항목에 이유와 영향을 표시해라.

방금 파일은 실습 3의 산출물인데 제목이 실습 2로 되어 있다. 제목을 바로잡아라. 업무 규칙에서 실습 2의 날짜·금액 조건을 반복한 부분은 해당 정의서 참조로 바꾸고, 이번 모델에서 명확해진 의미에 집중해라. 클래스 속성의 상태·결과에는 타입 이름만 적고 상태 값은 상태 머신으로 설명해라. 공통 규칙을 여러 절과 도식에 중복하지 마라. PlantUML 원본은 유효한 문법으로 작성하고 메시지 본문은 화살표와 같은 줄에 적되 줄바꿈은 \n을 사용해라. note 문은 사용하지 말고 필요한 규칙은 업무 규칙 그룹에 모아라. 시퀀스는 기존 정보 확인을 묶고 최초 신청 결과까지 표현해라. 이후 결과 확인의 기술적 방식은 설계 사항으로 남겨라. 별도의 수용 기준·미결 요약 절을 덧붙이지 말고 미결이 있으면 해당 항목에만 적어라. 보완된 문서 전체를 다시 생성해라.
