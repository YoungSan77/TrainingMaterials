아래 동적 모델은 정기배송 신청을 중심으로 하며, 성공이 확인된 첫 결제로만 계약이 성립하도록 표현했다. 일정 묶음용 별도 개념이나 구현 구성요소는 두지 않았다.

### 시퀀스 다이어그램

```mermaid
sequenceDiagram
    actor 고객
    participant 정기업무 as 정기배송 업무
    participant 쇼핑몰 as 기존 쇼핑몰
    participant 결제 as 결제 시스템

    고객->>정기업무: 상품·수량, 등록 배송지·결제수단,<br/>계약기간, 배송 주기, 첫 배송일 선택

    정기업무->>쇼핑몰: 회원과 선택 대상의 유효성 및<br/>본인 소유 여부 확인
    쇼핑몰-->>정기업무: 확인 결과

    정기업무->>쇼핑몰: 첫 배송일의 배송 가능 여부 확인
    쇼핑몰-->>정기업무: 배송 가능 여부

    정기업무->>쇼핑몰: 신청 시점의 가격·할인·배송비 산정 요청
    쇼핑몰-->>정기업무: 모든 회차에 적용할 동일 결제금액

    Note over 정기업무: 계약 종료 예정일 산정<br/>첫 배송일부터 주기별 회차 산정<br/>종료 예정일보다 이른 회차만 포함

    정기업무-->>고객: 선택 내용, 계약 시작·종료 예정일,<br/>전체 회차와 예정 배송일,<br/>모든 회차의 동일 결제금액 고지
    정기업무-->>고객: 첫 회차는 신청 시 결제,<br/>이후 회차는 배송 예정일 3달력일 전 결제,<br/>금액 유지 및 자동 갱신 없음 고지

    고객->>정기업무: 고지 내용 확인 후 신청 의사 확정
    정기업무->>결제: 첫 회차 결제
    Note right of 결제: 첫 회차에는 배송일 기준<br/>결제 예정일을 부여하지 않음

    alt 결제 성공 확인
        결제-->>정기업무: 성공
        Note over 정기업무: 정기배송 계약 성립<br/>신청의 회차와 동일 금액을 계약 내용으로 확정
        정기업무-->>고객: 신청 완료 및 계약 성립 안내
    else 결제 실패 확정
        결제-->>정기업무: 실패
        Note over 정기업무: 계약이 성립하지 않음<br/>같은 신청에서 재결제하지 않음
        정기업무-->>고객: 신청 미완료 안내
    else 결제 결과 확인 불가
        결제-->>정기업무: 결과 확인 불가
        Note over 정기업무: 계약 성립 여부를 확정하지 않음
        정기업무-->>고객: 결제 결과 확인 필요 안내
    end

    opt 동일 신청이 반복 전송됨
        고객->>정기업무: 동일한 신청 의사의 반복 전송
        Note over 정기업무,결제: 첫 결제를 다시 실행하지 않고<br/>계약도 중복 성립시키지 않음
        정기업무-->>고객: 기존 신청의 현재 결과 안내
    end

    opt 결제 결과 확인 불가 후 결과가 확정됨
        결제-->>정기업무: 최종 성공 또는 실패
        alt 최종 성공
            Note over 정기업무: 계약 하나만 성립
            정기업무-->>고객: 신청 완료 및 계약 성립 안내
        else 최종 실패
            Note over 정기업무: 계약은 성립하지 않음
            정기업무-->>고객: 신청 미완료 안내
        end
    end
```

### 정기배송 신청 상태 머신

```mermaid
stateDiagram-v2
    [*] --> 신청준비 : 새 신청 절차 시작

    신청준비 --> 신청준비 : 선택 내용 변경
    신청준비 --> 첫결제결과확인중 : 고지 확인 및 신청 의사 확정\n첫 회차 결제 시작

    첫결제결과확인중 --> 신청완료 : 첫 결제 성공 확인\n정기배송 계약 1건 성립
    첫결제결과확인중 --> 신청미완료 : 첫 결제 실패 확정\n계약 미성립
    첫결제결과확인중 --> 결과확인필요 : 결제 결과 확인 불가\n계약 성립 여부 미확정

    결과확인필요 --> 신청완료 : 첫 결제 성공 확인\n정기배송 계약 1건 성립
    결과확인필요 --> 신청미완료 : 첫 결제 실패 확정\n계약 미성립

    첫결제결과확인중 --> 첫결제결과확인중 : 동일 신청 반복 전송\n추가 결제·계약 생성 없음
    결과확인필요 --> 결과확인필요 : 동일 신청 반복 전송\n추가 결제·계약 생성 없음
    신청완료 --> 신청완료 : 동일 신청 반복 전송\n추가 결제·계약 생성 없음
    신청미완료 --> 신청미완료 : 동일 신청 반복 전송\n재결제·계약 생성 없음

    신청완료 --> [*]
    신청미완료 --> [*]
```

적용한 핵심 의미는 다음과 같다.

- 신청 준비 및 결제 결과 확인 단계에서는 아직 계약이 성립하지 않는다.
- 첫 결제의 성공이 확인된 사건만 `신청완료` 전이와 계약 성립을 발생시킨다.
- 결과 확인 불가는 실패가 아니며, 성공이나 실패가 확인될 때까지 계약 성립 여부도 확정하지 않는다.
- 실패 확정 후 재신청하려면 새로운 신청 절차를 시작한다.
- 동일 신청의 반복 전송은 어느 상태에서도 추가 결제나 중복 계약을 만들지 않는다.
- 모든 회차의 결제금액은 신청 시 산정한 하나의 동일 금액이다.
- 첫 회차는 신청 시 결제하고, 배송 예정일 3일 전 결제 조건은 이후 회차에만 적용한다.

확인이 필요한 사항이 하나 있다. 결제 결과 확인 불가 상태에서 최종 결과를 확인하는 주체와 고객 안내 방식이 정해져 있지 않다. 결제 시스템이 결과를 전달하는 것으로 표현했지만, 고객이 별도로 결과 확인을 요청하는 흐름도 허용해야 하는지 확인이 필요하다.
