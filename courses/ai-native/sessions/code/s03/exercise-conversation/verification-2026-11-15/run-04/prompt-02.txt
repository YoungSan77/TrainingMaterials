[앞선 질문에 대한 답 — 기존 확정 자료에 근거한 답만 제공]
두 입력에는 품질 조건이 없으므로 새로 추측하지 않고 courses/ai-native/course-design.md의 공통 용어와 전제 및 기존 S03 실습 대화에서 확인된 조건을 제공한다.
실습 예는 펜 2개, 주문 생성 시 판매가 각 1,000원, 배송지 서울이다. 주문 금액은 2,000원이다. 주문 생성 후 가격 변경 사례는 각 1,200원이다. 카드 X는 거절, 카드 Y는 승인되는 시험 사례다. 승인 완료 뒤 같은 주문의 상태명은 결제완료다. 정상 승인·가격 변경 승인에서는 배송 요청 1회, 거절 직후 0회, X 거절 후 Y 승인까지 총 1회다. 거절은 청구 완료가 아니며 금액은 승인 요청 금액이다.
기본 흐름 번호는 1 상품 조회, 2 장바구니, 3 배송지 지정, 4 결제, 5 주문 결과 확인이다. 1~2는 전제, 상세 범위는 3~5다. 결과 확인은 별도 통지 주체를 확정하지 않는다.
실습 정상 품질 시험은 외부 상품·결제·배송 시스템을 정상 응답하는 테스트 대역으로 두고 각 외부 응답이 1초 이내인 조건에서 카드 결제 요청 100건을 동시에 실행한다. 흐름 4의 요청부터 5의 결과 수신까지 100건 중 95건 이상이 3초 이내여야 한다. 운영 보장 수치가 아니다. 본인의 주문만 조회·변경할 권한이 있으며 타인의 주문 조회·변경 요청은 거절한다. 본인이라도 결제대기 주문의 상품·수량·배송지는 변경할 수 없다. 인증 방식·응답 코드·화면은 정하지 않는다.
기본 용어의 공통 표기는 주문(Order), 주문 항목(OrderItem), 판매가(salePrice), 주문 금액(totalAmount), 결제대기(PENDING_PAYMENT), 결제완료(PAID)다. 이는 용어 표기이지 클래스·속성 설계가 아니다.
H·B·F·E·G·I, 재고 판단 시점, 승인 전 재고 부족 처리는 답할 근거가 없으므로 미정으로 유지한다. 그 밖의 입력에 없는 질문도 새 정책으로 확정하지 않는다.

[추가 질문·수정 요청 — 첫 초안 검토]
재고 확인 시점을 도식에서 고정하지 않은 점은 유지해라. 다만 AC-09·AC-10과 품질 항목에서 미정 정책을 구현자가 결정하지 말라는 제약을 운영 중 영구 무동작 정책으로 바꾸지 마라. 해당 분기의 최종 수용 기준은 담당자 결정 전에는 완성되지 않았다고 구분해라.
기술 설계·모델·코드는 기능 제외가 아니라 이번 문서에서 작성하지 않는 산출물로 구분해라. 확정 규칙은 보존하고 사용자 스토리 하나, 기능·흐름, 기본 용어, 4가지 대표 상황의 전제·사건·기대 결과, 품질·접근 기준, 제외·미정이 연결되도록 초안을 보완해라. 네 상황 모두 동일 주문 여부·주문 금액·승인 요청 금액·상태·배송 요청 횟수를 관찰할 수 있게 해라. 불필요한 새 정책·모델·설계·코드는 추가하지 마라.
