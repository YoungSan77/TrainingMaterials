합의한 정적 모델을 간결한 Markdown 파일로 생성해라. 용어·관계·속성·조건·클래스 도식 원본과 대표 예를 보존하고 새 정책·설계는 추가하지 마라.
파일명은 주문한다-정적모델.md다. 구성은 합의한 네 부분으로 하되 문서 전체의 핵심을 한 문장으로 먼저 적어라.
1. 용어와 속성: 개념 세 개의 속성과 Money·Quantity·Address·식별자·상태의 뜻, salePrice·unitPrice·totalAmount의 의미를 짧은 목록으로 적어라. 이미 속성에 있는 정보를 표·별도 목록으로 반복하지 마라.
2. 클래스 도식과 관계: 합의한 세 개념의 Mermaid 원본을 보존하고 양쪽 다중성을 네 문장으로 읽어라. 값 타입 박스·연관 방향·메서드는 추가하지 마라.
3. 조건과 대표 예: 금액·수량·항목 수·배송지 조건, 총액 등식, 주문 생성 시점 단가 확정, 가격 변경 뒤 보존과 결제대기 내용 고정을 짧은 목록으로 명시해라. 대표 예는 펜 2개·1,000원·2,000원·서울과 판매가 1,200원 변경 전후를 한 번만 보여라. 같은 수식과 값을 여러 절에서 반복하지 마라.
4. 정하지 않은 항목과 기존 업무 미정: 본인 주문 접근 요구는 보존하고 구체 타입을 발명하지 마라. 식별자/주소 세부/수량 상한/병합 정책/결제 이력 구조/추가 상태의 미확정, 기존 업무 미정을 의미가 통하는 짧은 묶음으로 보존해라. 미정에서 허용 또는 금지 정책을 도출하지 마라.
수정 이력·검토 절차·후속 산출물 목록·파일 생성 안내는 문서에 넣지 마라. 합의의 파일화만 수행해라.
