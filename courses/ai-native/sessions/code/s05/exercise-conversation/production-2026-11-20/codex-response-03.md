합의한 다음 최종 요청의 적용 기준은 다음과 같습니다.

- 상태 기계와 전이 목록 모두 `배송지 지정으로 주문 생성` 사건으로 최초 `PENDING_PAYMENT` 진입을 표시한다.
- 생성 전은 주문 상태로 선언하지 않는다.
- 상태 전이는 다음만 표현한다.
  - 주문 생성 → `PENDING_PAYMENT`
  - 명시적 승인 거절 → `PENDING_PAYMENT` 자기 전이
  - 승인 완료 → `PAID`
- 재결제 요청, 배송 요청·성공, `PAID` 이후 종료점은 상태 전이로 넣지 않는다.
- 정상 승인 시퀀스는 고객·주문 시스템·결제 시스템·배송 시스템만 사용하며, 승인 완료 → `PAID` → 서울 배송 요청의 순서를 보인다.
- 시퀀스에서 결과 확인 `opt`는 제거한다. 결과 확인 가능 범위와 별도 통지의 담당·시점 미정은 본문으로만 남긴다.
- 수강생이 빠르게 교차 확인할 수 있도록 두 도식, 전이 및 금지 목록, 네 대표 사례, 미정 질문 중심으로 구성한다.
- 주문 조회·변경 상세와 정적 구조의 반복 설명은 제외한다.
- 네 사례를 각각 분리한다.
  1. 정상 승인
  2. 판매가 1,200원 변경 뒤 승인
  3. 카드 X 거절
  4. 같은 주문에서 카드 Y 재결제
- 모든 사례에서 펜 2개, 기록 단가 1,000원, 확정 총액 2,000원, 배송지 서울을 일관되게 사용한다.
