[앞선 질문에 대한 답]
실습 3·4의 미정 정책은 새로 결정하지 않는다. 본인 확인, 기한, 응답 미확정의 후속 처리, 재고 판단·부족 처리, 배송 요청 실패, 별도 통지 정책은 미정으로 유지해라. 정해진 정상 승인·거절의 대표 예를 모델링할 수 있으므로 이 미정 전체를 해결하려고 범위를 늘리지 마라. 정상 응답의 대표 예에서 배송 요청 1회는 기록한 업무 요청이 1번이라는 뜻이며 운영상 중복 방지·재시도 정책은 아직 정하지 않는다.

[추가 질문·수정 요청]
같은 주문 생애주기의 참고 범위를 확장하겠다. PAID에서 배송 시작 통보를 받으면 IN_DELIVERY, 배송중에 배송 완료 통보를 받으면 DELIVERED다. 이 두 상태와 전이는 주문한다의 요구 범위 밖인 생애주기 맥락으로 표시하고 실습 3 요구 범위 자체를 확대하지 마라. 취소는 범위 밖으로 유지해라.
상태 기계에서 카드 승인 거절은 PENDING_PAYMENT 자기 전이로 유지해라. 배송 요청은 PAID 상태에 진입하는 승인 사건의 반응이며 요청 자체로 IN_DELIVERY가 되지 않는다.
시퀀스는 고객·주문 시스템·결제 시스템·배송 시스템의 분석 수준으로 정상 승인 장면과 거절 뒤 재결제 장면을 나눠 보여라. 업무 사건의 선후 관계를 나타낼 뿐 동기·비동기 전달 방식을 정하지 않는다. 기술 객체·DB·재시도·복구 정책은 추가하지 마라. 펜 2개·확정 단가 1000원·총액 2000원·서울을 유지하고, 같은 주문의 식별·상품·수량·배송지·금액이 거절 뒤에도 유지됨을 명시해라.
이 조건으로 상태 기계·전이 목록·정상 승인 시퀀스·대표 예를 보완하고, 금지된 전이와 미정 정책의 차이를 짚어라. 전체 도메인 사건 목록을 발명하지 말고 범위 안의 대표 사건만 담아라.
