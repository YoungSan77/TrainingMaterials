# 실습 5 — 주문한다 동적 모델

2026-10-23(Asia/Seoul), `tools/run-exercise-turn.py`로 ①~⑤를 실제 실행했다. ①~③은 Codex CLI, ④~⑤는 Claude CLI다(`codex-response-03.md` 다음이 `claude-response-04.md`). 단계별 실행 시각·명령·종료 코드는 `<tool>-metadata-NN.json`에 있다. 도구를 바꾼 이유는 ③ 직후 Codex CLI의 사용 한도였고, 실행기가 앞선 실제 입력과 응답을 모두 이어 주므로 대화는 끊기지 않았다.

- `input-s03.md`는 실습 3의 `주문한다-요구사항-정의서.md`, `input-s04.md`는 실습 4의 `주문한다-정적모델.md` 원문 복사본이다. ①에 둘을 함께 첨부했다.
- `prompt-NN.txt`는 실제 피드백을 포함한다. `<tool>-input-NN.txt`는 앞선 실제 입력과 응답을 이어 준 전체 입력이다. 응답·이벤트·stderr도 보존한다.
- ①의 초안은 요구 범위를 따라 `PENDING_PAYMENT`·`PAID`만 그렸다. 누락 오류로 보지 않고, 범위 밖임을 밝힌 생애주기 맥락을 ②에서 사람이 더했다.
- ②: `IN_DELIVERY`·`DELIVERED`를 참고 범위로 명시했다. 거절을 `PENDING_PAYMENT` 자기 전이로, 배송 요청을 승인 사건의 반응으로 고정하고 미정 정책을 해결하려 범위를 늘리지 않게 했다.
- ③: 상태 기계가 `PAID`를 복합 상태 두 곳에 중복 선언한 것을 네 상태 한 번씩으로 고쳤다. 시퀀스의 응답 점선·색 바탕을 없애고 사건의 선후 관계만 남겼다.
- ④: 시퀀스가 주문 시스템 → 고객의 결과 통보를 그려 **미정인 통지 주체를 확정**한 것과, 주문 시스템의 자기 화살표로 상태 전이를 그린 것을 고쳤다. "배송 요청 1회 기록"을 "1회 발생"으로 바꿔 기록 구조를 정하지 않게 했다. 본인 주문 조건이 카드 결제 요청에도 적용되는지 질문을 받아 ⑤에서 미정으로 유지했다.
- ⑤ 첫 최종화는 「규칙의 대표 예」를 다섯 열 표 하나로 합쳐 칸마다 문장이 들어갔다. 행을 훑어 비교할 수 없어 원래 실행을 `finalization-rounds/01`에 보존하고 피드백 후 다시 생성했다. 대표 예는 예마다 짧은 목록으로, 전이 목록은 네 열로 줄이고 반응을 표 아래 목록으로 옮겼다. 실제 실행 총 6회다.
- `주문한다-동적모델.md`는 최종 `claude-response-05.md`와 바이트 단위로 같다. 세션 별첨은 이 응답 전체를 5부분으로 나누어 제목 단계·목록 들여쓰기만 변환했다.

다음 실습에는 요구사항 정의서·정적 모델과 이 동적 모델을 함께 첨부한다. 실습 3·4의 대화와 최종 응답은 고치지 않았다. 생애주기 참고 범위는 요구나 수용 기준으로 승격하지 않으며, 미정 정책은 답을 발명하지 않고 유지한다. Mermaid 원본만 받은 CLI를 시각 검토 완료로 보지 않고, 실제 도식의 표시는 Production 결과에서 별도로 검토한다.
