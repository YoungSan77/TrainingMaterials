# 실습 6 — 주문한다 아키텍처 결정

2026-10-24(Asia/Seoul). `tools/run-exercise-turn.py`와 Codex CLI로 실제 실행했다. 단계별 시각·명령·종료 코드는 `codex-metadata-NN.json`에 있다. 성공한 실제 실행은 총 14회(①~④ 4회, ⑤ 최종화 10회)다. 응답 생성 전 샌드박스 권한 실패 1회는 제외했다.

- 입력 `input-s03.md`·`input-s04.md`·`input-s05.md`는 앞 실습의 실제 최종 요구·정적·동적 모델 복사본이다.
- ①의 입력 포트·포트 집중·기술 역할별 경계를 ②에서 보완했다. ③은 순환 금지, ④는 제공자 필드를 업무 포트 밖으로 옮기는 보완이다.
- 이전 ⑤의 요청·입력·응답·실행 근거는 `finalization-rounds/01`~`09`에 보존한다. 현재 ⑤는 마지막 응답이다. 최초 최종화의 장황한 규격을 줄이고 산출물을 패키지 다이어그램·의존 규칙·결제 포트 규격 셋으로 좁혔다.
- 사용자 검토에서 별첨이 도메인 모델·패키지 경계·상품 관계를 잃은 문제를 확인했다. 이전 발췌본과 편집본을 최종 답으로 취급하지 않는다.
- 후속 피드백은 Order·OrderItem·OrderStatus의 order 소유, Product의 product 소유, 기존 업무 연관과 설계 의존의 구별, 포트 소유와 구현 경계를 요구했다. 구체 객체의 호출 책임은 후속 설계 활동에 남겼다.
- 허용 목록 밖의 업무 간 의존은 순환과 별개로 금지했다. `payment → delivery`는 순환이 없어도 위반이다.
- 이전 ⑤에서는 업무 판단을 유지하고 내부 요소를 보이지 않는 연결로 세로 정렬했다. 이는 도식의 배치 정보이며 새 업무 관계가 아니다. 포트 구현은 LR 방향으로 그렸다. 노드·의미 있는 관계를 삭제하지 않았다.

`주문한다-아키텍처결정.md`는 현재 `codex-response-05.md`와 바이트 단위로 같다. 원고 별첨은 응답 전문을 여섯 topic으로 나눴다. 제목 단계와 SA 표식만 바꾸며 문장·도식·강조는 편집하지 않는다. 기계적으로 payload 일치 여부도 확인한다.

실습 시간은 미계측이다. 실제 실행 횟수는 저자의 보완 기록이며 수강생의 필수 프롬프트 횟수가 아니다. 다음 실습은 요구·정적·동적 모델과 이 결정을 함께 읽는다. Mermaid 코드만 받은 CLI 응답을 시각 검토 완료로 보지 않으며 실제 PPT의 도식 표시는 Production에서 별도로 확인한다.

마지막 식별자 대조에서 PaymentGateway·DeliveryGateway·ProductGateway를 과정 공통 이름으로 유지했다. 실제 최종화 08 보존본의 세 포트 이름만 바뀌었는지 기계적으로 확인했다.

사용자 3차 검토: 중간 프롬프트의 진행 설명을 제거했다. 범례 아래 전체를 하위 목록으로 바꾸고, 업무 경계는 같은 11개 요소·두 업무 연관·세 패키지 의존을 보존한 SVG로 재배치했다. SVG는 저자가 입력으로 제공했고 실제 최종 응답에서 그대로 반환됐다. Mermaid의 보이지 않는 연결 설명은 새 그림에 없어 삭제했다. 포트 구현 등 다른 절은 직전 응답과 바이트 수준으로 같은지 확인했다.

사용자 4차 검토: 포트의 구현 그림만 Mermaid라 업무 경계 그림과 표기가 달랐다. 같은 요소·관계를 같은 방식(탭 달린 패키지, 그 안의 클래스, `«port»`, 점선 구현·실선 통신)의 SVG로 재배치한 응답을 받았다. SVG는 저자가 입력으로 제공했고 실제 최종 응답에서 바이트 단위로 그대로 반환됐다. 직전 회차는 `finalization-rounds/10`에 있다. 다른 절은 직전 응답과 같은지 확인했다.
