# 작업 명세서 — 주문한다의 남은 작업 단위 셋

"주문한다"는 작업 단위 넷으로 나뉜다. **금액 확정**은 끝났다(`OrderApplicationService.createOrder`).
이번에 만드는 것은 남은 셋이다.

## 범위

| 작업 단위 | 구현할 결과 | 완료를 확인할 예 |
| --- | --- | --- |
| **승인** | 승인 요청·결제완료·배송 요청을 잇는다 | 승인 뒤 결제완료, 서울 배송 요청 1회 |
| **거절** | 상태와 확정 값을 지키고 배송을 막는다 | 거절 뒤 결제대기, 배송 요청 0회 |
| **재결제** | 같은 주문을 다른 카드로 결제한다 | 거절 뒤 카드 Y로 승인, 배송 요청 총 1회 |

단위에 순서가 있다. 승인을 먼저 올리고, 거절 경로를 확인한 뒤, 재결제를 검증한다.

## 수용 기준

주문 예는 펜 2개, 단가 1,000원, 주문 금액 2,000원, 배송지 서울이다.

1. 결제대기 주문을 카드로 결제해 승인되면 → 결제완료가 되고 배송 요청이 **1회** 나간다.
2. 결제 직전에 판매가가 1,200원이 되어도 승인 요청 금액은 **2,000원**이다.
3. 결제가 거절되면 → 주문은 **결제대기**로 남고 배송 요청은 **0회**다.
4. 거절된 주문을 다른 카드로 다시 결제해 승인되면 → 결제완료가 되고 배송 요청은 **총 1회**다.

## 제외

- 취소, 환불, 반품
- 배송 시작·완료 통보의 처리
- 외부 시스템의 실제 연동 구현(포트와 테스트 대역까지만)

## 미정

- **승인 뒤 배송 요청이 실패했을 때의 처리.** 업무 담당자가 정하지 않았다.
  기대 상태도 복구 동작도 만들지 말고, 닿으면 **멈추고 물어라**.
- **결제가 확정 불가로 돌아온 뒤의 처리.** 역시 정하지 않았다.
