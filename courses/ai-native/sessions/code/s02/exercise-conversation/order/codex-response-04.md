# 첫 주문 기능 개발 활용 방식 초안

전제: 지금은 활용 방식만 고른다. 요구·모델·설계·코드·검사·완료 조건의 내용은 뒤 실습에서 만든다. 미정 정책은 그대로 두며 외부 부작용은 없다. 코드 변경은 Git으로 되돌릴 수 있다.

1. **업무 조건 결정**

   - 업무 규칙: 확정 조건과 의도적으로 미정인 조건이 구분되어 있다.
   - 절차: 담당자가 정책을 결정하고 경계를 확인한다.
   - 자동 확인: 정책의 타당성은 자동 판정할 수 없다.
   - 되돌림: 문서 수정은 쉽지만 정책 결정은 사람의 책임이다.
   - 선택: **수작업**. LLM은 질문과 정리만 보조하고, 담당자가 답마다 확인한다.

2. **요구·모델·설계 초안**

   - 업무 규칙: 확정 범위만 반영하고 미정 사항을 대신 결정하지 않아야 한다.
   - 절차: 뒤 실습에서 마련한다.
   - 자동 확인: 아직 검사와 완료 조건이 없다.
   - 되돌림: 로컬 문서 변경은 Git으로 쉽게 되돌릴 수 있다.
   - 선택: **대화형 보조**. LLM의 초안을 담당자가 답마다 검토한다.

3. **저장소 골격**

   - 업무 규칙: 기술과 구성 규칙이 아직 정해지지 않았다.
   - 절차: 생성 순서와 명령을 뒤에서 정한다.
   - 자동 확인: 빌드·검사 환경이 준비되어야 한다.
   - 되돌림: Git으로 쉽게 되돌릴 수 있다.
   - 선택: 현재는 **대화형 보조**. 준비 후 절차가 고정되면 **일반 자동화**, 정한 단계마다 LLM과 도구의 조율이 필요하면 **워크플로**를 검토한다.

4. **확정 범위 코드 구현**

   - 업무 규칙: 확정된 조건만 구현하고 미정 분기를 정책화하지 않아야 한다.
   - 절차: 설계와 구현 절차가 아직 없다.
   - 자동 확인: 완료 조건이 명확하고 자동 검사로 판정 가능해야 한다.
   - 되돌림: 작은 로컬 변경이므로 Git으로 되돌릴 수 있다.
   - 선택: 현재는 **대화형 보조**. 준비 후에도 절차를 고정할 수 있으면 워크플로 또는 일반 자동화로 충분하다. 절차를 미리 고정하기 어렵고 실행 결과에 따라 다음 행동을 정해야 할 때만 **에이전트**를 검토한다.

5. **검사 작성·실행**

   - 업무 규칙: 확인할 대상과 기대 결과는 뒤 실습에서 정한다.
   - 절차: 작성·실행 절차가 아직 없다.
   - 자동 확인: 검사를 새로 만들고, 실제 오류를 잡는지 사람이 먼저 확인해야 한다.
   - 되돌림: 검사 코드도 Git으로 되돌릴 수 있다.
   - 선택: 현재 검사 초안은 **대화형 보조** 대상이다. 준비 후 고정된 검사 명령 실행은 **일반 자동화**다. 결과에 따른 후속 작업이 정해진 단계로 구성되면 워크플로, 사전 고정이 어려우면 에이전트를 검토한다.

6. **릴리스 설명**

   - 업무 규칙: 확정 범위, 제외 범위, 미정 사항을 구분해야 한다.
   - 절차: 작성과 승인 절차가 아직 없다.
   - 자동 확인: 실제 변경 내역과 검사 결과가 준비되어야 한다.
   - 되돌림: 문서 변경은 쉽게 되돌릴 수 있다.
   - 선택: 현재는 **대화형 보조**, 최종 확인과 승인은 **수작업**이다. 자료 수집과 작성 단계가 고정되면 워크플로를 검토할 수 있다.

현재는 **담당자의 수작업 결정과 LLM 대화형 보조**가 가장 단순하고 충분하다. 새 도구와 실행 체계를 구성하는 비용을 들이지 않고, 담당자가 LLM의 답마다 정책 침범이나 오류를 확인할 수 있기 때문이다.

사람의 확인 시점은 다음과 같다.

- 대화형 보조: LLM의 답마다
- 워크플로: 미리 정한 단계마다
- 에이전트: 종료 또는 중단 시점
- 일반 자동화: 실행 결과를 사용할 때

단가·횟수·소요 시간은 아직 측정하지 않았으므로 비용은 수치화하지 않는다. 자율성은 목표가 아니며, 필요한 통제 수준을 만족하는 가장 단순한 방식을 선택한다.
