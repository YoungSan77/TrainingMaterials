합의한 첫 주문 기능 개발의 일 목록과 작업 특성·활용 방식·근거를 간결한 Markdown 파일로 생성해라. 새 정책·구현을 추가하지 말고 미정과 자율성을 올릴 조건은 필요한 일에만 짧게 남겨라.
마지막 초안의 여섯 일과 현재 선택을 그대로 유지해라. 지금은 요구·모델·설계·코드·검사 내용을 만들지 않는다는 범위를 유지해라. 실습 1에서 미정으로 남긴 조건을 확정하지 마라. 문서는 짧은 전제 한 문단, 여섯 일의 번호 목록, 공통 전환 조건만 남겨라. 각 일은 '특성: 업무 규칙 / 절차 / 자동 확인 / 되돌림', '선택·근거와 사람 확인 시점'의 짧은 두 항목으로 묶어라. 같은 조건을 각 일마다 반복하지 말고 공통 조건에 한 번만 써라. 비용은 계측 전이라 수치를 쓰지 말고 현재는 실행 체계 구성과 검토 비용을 줄이는 선택임을 짧게 밝힌다. 도식이나 큰 표, 부가 체크리스트, 다음 실습의 실제 산출물을 추가하지 마라. 앞에서 합의한 내용만 파일화해라.
