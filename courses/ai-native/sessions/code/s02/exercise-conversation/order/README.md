# 실습 2 — 활용 방식 고르기 실제 대화

- 실행일: 2026-10-22 (Asia/Seoul). Codex CLI 0.149.1.
- 실행기: 저장소 루트의 `tools/run-exercise-turn.py`. 도구 사용·파일 탐색·편집을 금지하고 실제 응답을 저장했다. 모델명은 실행기에서 지정하지 않았으며 기록에 없는 서버 모델명을 추정하지 않는다.
- 입력: 실습 1의 최종 응답을 그대로 복사한 `input-s01.md`.
- 실제 입력·응답: `prompt-01.txt`~`prompt-05.txt`, `codex-response-01.md`~`codex-response-05.md`. 각 단계의 input/events/stderr/metadata 파일에 앞 대화와 실행 근거가 있다.
- ②는 개발 작업과 주문 실행 흐름을 구분하고 미정 정책의 잠입을 막았다. ③은 일반 검사 명령과 LLM 워크플로를 구분했다. ④는 현재 선택과 준비 후 조건, 비용·확인 시점을 고쳤다. ⑤는 최종 합의를 파일화했다.
- ④에서 Codex 요청 제한(429)이 두 차례 발생했다. 실패 당시 기록은 `failed-attempts/`에 보존했으며 중복 보존본도 있다. Claude CLI로 이어 가려는 시도 역시 기존 세션 한도(429, usage_limit_reached)로 실패했다. 그 뒤 Codex의 ④와 ⑤가 성공했다. 실패 응답을 실습 답으로 쓰지 않았다.
- 최종 파일: `활용-방식-판단.md`는 `codex-response-05.md`와 바이트가 같다. 원고 별첨은 그 전문이며 제목 단계·목록 들여쓰기만 대응했다. 원본의 일 목록과 공통 전환 조건은 별첨의 두 절로 나뉜다.
- 수강생의 Windows 로컬 실습에서는 최종 MD를 자기 저장소의 `docs`에 두고 커밋한다. 교재 작성용 실행 환경은 macOS였다.
