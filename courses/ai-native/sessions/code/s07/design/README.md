# 세션 07 설계 실행 예

저장소 루트에서 JDK 17 이상과 Node.js로 실행한다. 외부 의존성 다운로드나 실제 결제·배송 호출은 없다.

```sh
node courses/ai-native/sessions/code/s07/design/run.mjs
```

실행기는 임시 폴더에 `src/`를 컴파일하고 두 실행 예를 돌린다. `test.ContractTest`는 작업 단위 넷(금액 확정·승인·거절·재결제)과 계약 둘(사전조건, 확정 불가에서 멈춤)을 검사한다. `test.FalseGreenExample`은 계약을 검사하지 않는 대역이 잘못된 구현을 통과시키는 것과, 같은 구현을 계약 대역이 잡는 것을 함께 보인다. 여덟 검사가 모두 통과하면 `features.json`에 네 단위의 통과 표식을 기록한다. 종료 시 자신이 만든 임시 폴더만 정리한다.

`src/`는 현재 원고의 발췌 원본이다. 패키지 경계와 포트 소유는 세션 06의 아키텍처 결정을 따른다 — 업무 패키지는 `order`·`payment`·`delivery`·`product`이고 연동·영속은 포트를 구현한다. 세션 06의 예제와 달라진 것은 둘이다. 결제 포트의 반환이 결제 결과(`PaymentDecision`)이며, 주문 저장소가 주문 번호를 따로 받지 않는다(`save(Order)`). 둘 다 이 세션의 설계 결정이다.

`src/alternative/`는 **쓰지 않기로 한 안**이다. 컴파일만 확인하며 정상 설계의 기준이 아니다.

- `PortHoldingOrder` — 주문이 결제·배송 포트를 들고 직접 부르는 안
- `ExternalSystemGateway` — 결제·배송·상품을 인터페이스 하나로 묶은 안
- `AnemicOrder`·`AnemicOrderService` — 주문이 값만 들고 규칙은 서비스가 가진 안
- `RepricingOrderService` — 결제 직전에 현재 판매가를 다시 조회해 요청 금액을 만드는 구현(업무 규칙 "주문 금액" 위반). `FalseGreenExample`이 이 구현으로 거짓 녹색을 보인다

예제가 **보장하지 않는 것** — 실제 제공자의 응답 형식, 통신 실패와 재시도, 동시 실행, 저장의 내구성, UI 계층. 확정 불가 뒤의 처리와 승인 뒤 배송 요청 실패의 처리는 미정이며 코드가 정하지 않는다. 확정 불가에서는 어떤 전이도 하지 않고 예외로 멈춘다.
