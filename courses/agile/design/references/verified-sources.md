### Agile Verified Principles & Sources Pack v2.0

#### 1. Foundational Position

`Diagnose → Stabilize → Shorten → Apply → Adapt`

Scrum은 출발점이 아니라 Apply 단계의 대표 Framework다.

#### 2. Primary Evidence

##### AG01 — Working software and frequent delivery
- Source: Manifesto for Agile Software Development / Principles behind the Agile Manifesto
- Teaching use: 진척은 문서나 task completion보다 검증 가능한 working increment를 중심으로 본다.

##### AG02 — Change and adaptation
- Source: Agile Manifesto / Principles
- Teaching use: 상세 장기계획을 없애는 것이 아니라 uncertainty가 높은 곳에서 feedback을 통해 계획을 조정한다.

##### AG03 — Technical excellence supports agility
- Source: Principles behind the Agile Manifesto
- Teaching use: Engineering Discipline이 낮은 상태에서 Sprint만 짧게 하면 문제 반복 주기만 짧아질 수 있다.

##### AG04 — Scrum is intentionally incomplete
- Source: The Scrum Guide 2020, Ken Schwaber & Jeff Sutherland
- Teaching use: Scrum이 detailed engineering practice를 제공한다고 가르치지 않는다.

##### AG05 — Scrum empirical pillars
- Source: The Scrum Guide 2020
- Teaching use: Transparency / Inspection / Adaptation을 Event/Artifact 암기보다 먼저 설명한다.

#### 3. Teaching Distinctions
- Agile ≠ Scrum
- Agile ≠ no planning
- Iterative ≠ Incremental ≠ Adaptive
- Sprint ≠ Feedback
- Task completion ≠ Working Increment
- Scrum ≠ Engineering Practice
- Velocity ≠ Productivity KPI
- Outsourcing ≠ Agile impossible
- Scaling Framework ≠ team-level problem solution

#### 4. Awareness-only Topics
각 1~5분: XP, Kanban, Story Point, Planning Poker, Velocity, Burn-down/Burn-up, Jira, Nexus, LeSS, SAFe, Hybrid, DevOps relation.

#### 5. Source Baseline
- Agile Manifesto: https://agilemanifesto.org/
- Principles: https://agilemanifesto.org/principles
- Scrum Guide: https://scrumguides.org/scrum-guide.html

#### 6. Source Rule
Agile/Scrum 원칙은 원출처를 우선한다. Scaling framework/vendor/tool 설명은 현재 예시로만 사용하며 Course Thesis를 지배하지 않는다.

### 2.2 Course Source Precedence — Agile (`evidence-policy.md` §13, verbatim)

1. Agile Manifesto / Principles 등 foundational source
2. 관련 empirical / established practice evidence
3. Scrum Guide 등 framework definition은 해당 framework 설명에 사용
4. scaling/tool/vendor 자료는 필요한 경우 example/reference

**Common rule** (evidence-policy.md §13): Current legal/regulatory claims, benchmark numbers, DORA metrics, AI governance status, product/vendor claims는 detailed deck publication 시 재검증한다. Agile 과정에는 DORA/legal claim이 없으나, Scaling framework(SAFe/LeSS/Nexus) awareness 언급이 detailed deck 단계로 갈 경우 최신성을 재확인한다.
