# 과정 설계 지침

> `portfolio/governance.md`가 통제하는 Course Design stage annex다. Workflow, authority와 공통 원칙은 Governance와 해당 Portfolio owner를 따르며 여기서 재정의하지 않는다.

## Input

- User Intent
- `portfolio/governance.md`와 관련 Portfolio owner
- 실제 학습자·업무 맥락과 capability evidence
- 과정에 필요한 검증된 외부 Source

다른 과정의 Course Design, 기존 Curriculum, Deck과 과거 migration 자료는 현재 과정을 설계하는 선례나 제약이 아니다.

## Responsibility

Course Design LLM은 지식 목록이 아니라 학습자의 업무 문제와 required decision에서 출발해 Curriculum의 Guardrail이 되는 단일 논리 정본을 완성한다.

- 대상 학습자, 현재 업무 맥락과 대표 failure mode를 구체화한다.
- capability gap과 target capability를 연결한다.
- 과정 목적, thesis, scope, non-scope와 ownership boundary를 결정한다.
- 학습자가 내려야 할 핵심 결정과 그 trade-off·failure condition을 밝힌다.
- Curriculum이 교육 흐름을 설계할 수 있는 learning progression과 필수 outcome을 제공한다.
- target capability를 적용·관찰할 핵심 실습 방향을 설계한다.
- 핵심 정의와 방향을 실제로 고정하는 Source만 `portfolio/evidence-policy.md`에 따라 검증한다.
- Portfolio와 충돌하거나 Portfolio 갱신이 필요한 지점을 숨기지 않는다.

Course Design은 하나의 논리 정본이다. 책임상 분리가 필요하면 여러 physical file로 구현할 수 있지만, 파일 수·파일명·디렉터리 구조를 품질 기준으로 고정하지 않는다.

## Output

승인 가능한 Course Design은 최소한 다음 질문에 답할 수 있어야 한다.

- 누구의 어떤 업무 문제를 해결하는가?
- 과정 후 어떤 판단과 행동이 달라지는가?
- 무엇을 소유하고 무엇을 다루지 않는가?
- 어떤 핵심 결정·trade-off·failure condition을 가르치는가?
- 어떤 progression과 outcome이 Curriculum을 제약하는가?
- 어떤 실습과 Source가 capability에 실제로 필요한가?

항목 수나 section heading은 고정하지 않는다. 필요한 책임이 명확하고 추적 가능하면 된다.

## Prohibited Behavior

- 현재 repository 구조나 과거 3파일 구조를 목표 구조로 간주하지 않는다.
- 다른 과정의 구성·항목 수·Source 수·실습 수를 맞추지 않는다.
- body of knowledge, tool, framework 또는 vendor 목차에서 과정을 시작하지 않는다.
- Session 수·제목·시간·claim과 세부 학습 흐름을 설계하지 않는다. 이는 Curriculum 책임이다.
- Portfolio의 용어·원칙·ownership·evidence 규칙을 Course Design에 복제하지 않는다.
- 검증되지 않은 Source, 장식용 인용과 미래 참고 후보를 live artifact에 보존하지 않는다.
- storyboard, session source, semantic IR, slide-plan 같은 intermediate SSOT를 만들지 않는다.

## Verification Expectations

### Deterministic

- 승인된 과정 identity와 duration이 명시돼 있다.
- 내부 path와 Source locator에 dangling dependency가 없다.
- 필요한 Source의 verification status가 evidence policy와 일치한다.

### Semantic

- learner problem → capability gap → required decision → target capability가 연결된다.
- scope·non-scope·ownership이 Portfolio와 정합하다.
- progression과 실습이 target capability의 evidence를 만들 수 있다.
- 시간 제약에 비해 scope와 깊이가 현실적이다.

### Human

- 과정이 실제 업무 가치와 독립적인 교육 필요성을 갖는다.
- 중요한 우선순위와 trade-off가 승인됐다.
- Curriculum stage의 Guardrail로 사용할 수 있다.
