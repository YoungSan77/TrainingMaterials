# 교재 작성 지침

> `portfolio/governance.md`가 통제하는 Deck stage annex다. Workflow와 authority는 Governance, executable schema·geometry·rendering behavior는 Engine이 소유한다. 이 지침은 승인된 content를 어떻게 시각적으로 표현하는가(typography·semantic grouping·whitespace·optional structure)를 정한다 — 어떤 Anchor·개념·judgment question이 필요한가와 그 정확한 의미·source fidelity·semantic flow는 Session Detailed Design이 정한다. 세 layer(DD/Guide/Engine)의 책임을 섞지 않는다.

## Input

- 이 지침
- 승인된 전체 Curriculum과 생성 대상 Session
- Curriculum이 해당 Session에 연결한 실습
- Curriculum이 해당 Session에 연결한 검증된 Source
- Curriculum이 해당 Session에 지정한 Portfolio Common Standards
- 현재 Engine의 executable contract

Course Design은 Curriculum의 누락을 우회하기 위한 직접 Deck 입력이 아니다. 기존 Deck, legacy session source와 연결되지 않은 자료도 입력으로 사용하지 않는다.

## Responsibility

Deck LLM은 Curriculum의 필수 교육 설계를 모두 계승해 해당 Session을 실제로 가르칠 수 있는 instructional/visual realization을 완성한다.

- Curriculum claim의 핵심 의미, 관계와 boundary를 learner-visible content로 구현한다.
- Session 시간에 맞는 설명, 예제, 질문, 짧은 interaction과 instructor notes를 보완한다.
- claim을 기계적으로 slide와 1:1 대응시키지 않고 자연스러운 논증 단위로 결합하거나 전개한다.
- Detailed Design이 하나의 독립된 teaching unit(definition·judgment question·evidence/example을 갖춘 개념)을 다른 slide와 병합할 수 있다. 단, 병합 후에도 그 definition과 distinguishing judgment question은 learner-facing content에 남아야 한다 — 단순 mention이나 한두 단어로 축약되거나 notes-only로 밀려나 사라지면 안 된다. 보존 대상은 content element이지 slide 수가 아니다.
- 여러 관련 claim·subsection을 하나의 slide나 작은 묶음으로 결합할 때는 source가 요구하는 핵심 distinction·definition·judgment criterion·vocabulary가 결합 후에도 식별 가능해야 한다. 압축으로 그중 하나라도 learner-facing에서 사라지면 그 부분만 slide를 나눈다. slide 수 자체를 늘리는 것이 목적은 아니며, 같은 의미를 반복하는 slide는 합친다.
- Curriculum의 권장 slide 수와 허용 범위를 따르되, 필수 내용을 보존하면서 교육적·시각적 근거가 있으면 범위 안에서 가감한다. 범위를 벗어나야 하면 그 근거를 semantic/human review에 드러낸다.
- 인과, 전환, 경계, 책임, 상태, 순서와 대조가 내용이면 그 관계가 보이는 visual type을 선택한다.
- Box·Card는 단순 항목 수 때문에 만들지 않는다. 실제 grouping, comparison, boundary 또는 독립된 semantic unit이 있을 때 사용한다.
- Arrow·Flow는 실제 인과, 순서, interaction, dependency, feedback 등 관계가 있을 때만 사용한다. 단순 나열이나 작성 절차를 장식용 flow로 만들지 않는다.
- 공식 taxonomy, standard characteristic set, notation set을 전체 범위로 소개하는 경우 명확한 교육적 근거 없이 `등`·`etc.`로 임의 축약하지 않는다.
- notation 자체가 학습 대상이면 prose만으로 대체하지 않고 실제 notation을 보여준다.
- named authority, 직접 인용, 표준, 중요한 외부 근거는 learner-visible attribution을 제공한다. Notes-only citation으로 교육 근거를 숨기지 않는다.
- Detailed Design에서 두 개념이 대조·인과·feedback 관계로 함께 설명되면, Deck에서 slide를 분리하더라도 인접 배치·명시적 transition·공유된 visual language로 그 관계가 학습자에게 즉시 유지되도록 한다. 반드시 한 slide에 담으라는 뜻은 아니다.
- 과정 전체와 Session 내부에서 사례·용어·narrative를 일관되게 유지한다.
- Source의 검증 범위와 Portfolio Common Standard의 정의·규칙을 변경하지 않는다.
- Engine이 처리할 수 있는 유효 Deck data를 작성한다.

Harness는 Deck을 생성하거나 교육 내용을 대신 채우지 않는다. 오류는 수정해야 할 계약 위반이고, 경고는 semantic/human 판단이 필요한 신호다.

> **Visual Economy는 Content Reduction을 의미하지 않는다.** 시각적 단순화를 위해 필요한 정의, 설명, 근거, 예제, 반례·주의점, 판단 기준, teaching density를 제거하지 않는다. Slide의 완성 기준은 빈 공간이 많거나 시각적으로 단순한지가 아니라, 해당 teaching point가 충분히 설명되고 강의 가능한 수준으로 완성되었는가이다. Visual Economy는 불필요한 *시각 요소*(box, 장식용 flow, 반복되는 label)를 없애는 것이지 필요한 content를 없애는 것이 아니다 — whitespace는 빈 공간이 아니라 semantic separation을 표현하는 visual element일 수 있다. box를 넣어야 slide가 완성되는 것도, 모든 공간을 채워야 하는 것도 아니다. 반대로 내용이 부족한 slide를 "clean하다"고 정당화하지도 않는다.

## Presentation

Slide는 sub/question/lead/visual/foot 다섯 필드를 기계적으로 채우는 template이 아니다 — 실제 teaching value가 있는 요소만 렌더한다(Required structure보다 Teaching Meaning이 우선). visual과 title처럼 slide identity·renderer 동작에 필수적인 최소 필드는 유지한다.

- **Optional Regions** — sub/question/lead/foot는 실제 teaching content가 있을 때만 쓴다. 채울 내용이 없으면 생략한다. `?`, `:`, `[kind]`만 단독 표시, `아래에서 확인한다`·`다음 내용을 본다`처럼 구조를 채우기 위한 형식적 문구를 만들어 넣지 않는다 — 빈 자리를 만드느니 그 field 자체를 없앤다.
- **Semantic Grouping** — 한 slide에 여러 근거·개념이 있을 때 구분 수단은 이 순서로 먼저 고려한다: ① typography(굵기·크기) ② whitespace ③ 정렬 ④ divider(실제로 의미 있을 때) ⑤ box/card(경계 자체가 의미를 가질 때만 — 실제 grouping·comparison·boundary). *Meaningful grouping does not imply a box.* 짧은 label(Anchor Keyword 등)로 의미 단위를 표시할 때는 본문과 같은 줄에 억지로 붙이지 않고 그 자체로 강조되는 한 줄(own-line heading)로 둔다 — label은 의미 단위 표시이지 저자명·source 반복 용도가 아니다.
- **Whitespace as Semantic Separation** — 서로 다른 저자·근거·example·principle이 한 slide에 연속되면 문장 내용만으로 구분하지 말고 whitespace로 semantic boundary를 보여준다. 한 덩어리 문단처럼 읽혀 의미 경계가 사라지면 spacing이 부족하다는 뜻이다(대략 본문 1~2줄 이상). 모든 항목 사이에 강제하는 숫자 규칙은 아니다 — 독립된 의미 단위가 이어질 때만 적용한다.
- **Anchor Citation Rich Text** — 저자 원문을 인용할 때는 학습자 번역과 원문·저자를 하나의 text unit으로 유지한다(서로 다른 영역으로 쪼개지 않는다). 한글 번역/메시지는 본문 크기, 영어 원문·저자·`원문 미확인`은 10pt다. 형식: 단일 인용 `한글 번역, 영어 원문, 저자명` / 같은 저자 복수 인용 `한글1 -- 한글2, 영어1 -- 영어2, 저자명` / 서로 다른 저자는 각각 독립된 semantic group(bullet)으로 분리하고 저자명을 heading으로 반복하지 않는다 / 원문 미확인은 `한글 내용, 저자명, 원문 미확인`이며 영어 문장을 추정·생성하지 않는다.
- **Meaningful Addition vs Redundant Explanation** — Anchor나 핵심 문장이 이미 의미를 충분히 전달하면 그것을 요약·재진술하는 문장을 추가하지 않는다. 추가 설명은 개념 구분, 판단 기준, 현재 학습 주제와의 연결, 적용 의미, 중요한 경계, 오해 방지 중 하나를 실제로 제공할 때만 쓴다. 판단 기준: 이 문장을 지웠을 때 학습자의 이해·구분·판단 능력이 실제로 줄어드는가 — 아니면 지운다.
- **Question/Conclusion Are Optional** — question은 실제 판단을 유도하거나, 개념을 구분하거나, misconception을 드러내거나, 다음 설명의 틀을 줄 때 쓴다. 제목을 의문문으로 바꾸거나 형식을 채우기 위한 질문은 쓰지 않는다. foot/conclusion도 같다 — 여러 요소를 새로운 판단으로 통합하거나, 다음 개념으로 의미 있게 연결하거나, 오해를 바로잡거나, 적용 함의를 제시할 때만 쓴다. Anchor 요약, 제목 재진술, "따라서 중요하다" 수준, 빈 공간 채우기용 conclusion은 쓰지 않는다.

## Output

- Engine이 읽을 수 있는 해당 Session Deck source
- Curriculum claim과 slide realization의 추적 가능성
- 실제 강의 진행을 지원하는 instructor notes
- 필요한 Source attribution과 한계

PPTX, PDF와 PNG는 generated output이며 별도 승인된 regression baseline이 아니면 Git 정본으로 유지하지 않는다.

## Prohibited Behavior

- Curriculum의 교육 범위, claim, 순서, 실습 배치와 ownership을 바꾸지 않는다.
- Curriculum에 없는 핵심 주장이나 연결되지 않은 Source·Common Standard를 임의 추가하지 않는다.
- 기존 Deck의 문장·구성·layout을 정답으로 복사하지 않는다.
- 단순 카드·표·bullets를 관계 시각화의 대체물로 반복하지 않는다.
- claim 수를 slide 수와 1:1 대응시키거나 전 과정 공통 quota와 visual type 분포를 목표 수치에 맞추지 않는다.
- 인용을 의역해 축자 인용으로 제시하거나 Source보다 강한 사실을 만들지 않는다.
- `S01`, `S02`, DD 번호, owner/routing 등 authoring metadata를 learner-facing content에 불필요하게 노출하지 않는다.
- Renderer 결함을 Deck 내용 왜곡으로 우회하거나 Deck 결함을 Engine 변경으로 숨기지 않는다.
- storyboard, semantic IR와 slide-plan을 persistent artifact로 만들지 않는다.

## Verification Expectations

### Deterministic

- `node engine/verify.js <deck>` 또는 동등한 현재 CLI 검사에서 오류가 없다.
- Curriculum claim coverage와 routing integrity가 완전하다.
- Curriculum의 필수 학습 목표·요약·실습 흐름과 slide 범위 계약이 추적된다.
- 알 수 없는 claim·Source·실습·Common Standard 참조가 없다.
- schema, 필수 field, quote exactness, geometry와 overflow 검사를 통과한다.
- 자동화 가능한 경우 learner-facing internal identifier, known notation/structure violation, duplicate numbering과 source-attribution 누락을 검사한다.

### Semantic

- claim의 의미·경계·사례가 축소되거나 왜곡되지 않는다.
- slide를 병합·분리했더라도 source의 definition·distinguishing judgment·approved vocabulary·개념 간 관계(대조·인과·feedback)가 learner-facing content에서 식별 가능하다.
- 시각 구조가 실제 인과·책임·상태·대조와 전환을 표현한다.
- 중복, 과밀, 과소 설명과 기계적인 layout 반복이 없다.
- Session 시간 동안 자연스럽게 설명하고 interaction할 수 있다.
- 정의, taxonomy, notation과 example이 서로 일치한다.
- 일부 항목 생략이 학습 의미를 왜곡하지 않는다.
- example이 개념의 실제 semantics를 만족한다.
- arrow가 나타내는 관계를 명확히 설명할 수 있다.
- box/card가 실제 grouping 또는 boundary를 표현한다.

### Human

- 실제 글자 표시, 가독성, hierarchy와 presentation 환경을 시각 검토한다.
- 교육적 전달력, semantic accuracy와 narrative를 승인한다.
- deterministic 통과를 최종 교재 품질 승인으로 간주하지 않는다.
