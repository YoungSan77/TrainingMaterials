# 교재 작성 지침 (도메인 독립 · 형식 어휘의 정본)
> 버전: v1.3 (순수 덱 + 로더 — 덱은 경로·config·self-run을 담지 않는다)

> 이 문서는 어떤 주제의 교재든 공통으로 적용되는 **형식 계약**이며, 형식 어휘의 정본이다.
> **덱 세션에서 커리큘럼과 함께 첨부한다.** 커리큘럼 작성 지침은 여기의 어휘를 *참조*할 뿐 소유하지 않는다.
> 주제·내용은 여기 없다 — 그건 커리큘럼에 있다.
> **최종 정본은 `engine/master_render.js` 헤더다.** 이 문서는 그 헤더의 사람용 요약이며, 충돌 시 엔진이 우선한다(verify가 드리프트를 잡는다). 엔진 헤더에는 가상 소재의 완성 예시([형식 앵커 예시])가 들어 있어, 그 헤더 자체를 첨부하면 가장 정확하다.

## 1. 덱 데이터 스키마
- 덱 = `{ session:{ no, title, slides:[...] } }` — **순수 데이터**. `book`·`curriculum`·`meta`는 과정의 `global_config.js`가 소유하고, 로더(`engine/load_deck.js`)가 병합한다. 덱은 경로·config·self-run을 담지 않는다(toc는 덱의 getter가 slides에서 파생).
- 슬라이드 = `{ kind, title, head?, sub, question, lead, visual?, quote?, foot, notes? }`.
- `kind ∈ '학습 목표' | 현상 | 원인 | 원칙 | 적용 | 타협 | 요약` — **'학습 목표'는 띄어쓰기 포함**(붙여 쓰면 verify가 학습 목표 슬라이드 없음으로 중단).
- 파일은 **CommonJS**: `module.exports = { session:{...} }`. `export default` 아님(로더가 `require`로 읽는다 → 터진다). `require`·self-run·`...config` 스프레드를 넣지 않는다 — 로더가 병합한다.
- 정확한 필드·타입은 엔진 헤더가 정본.

## 1-c. 덱 껍데기 — 순수 데이터 (경로·config·self-run 없음)
덱은 슬라이드만 담는다. `book`·`curriculum`·`meta`(인용 경로)는 과정의 `global_config.js`가 소유하고,
로더가 병합한다. 덱이 config·경로를 emit하지 않으므로 폴더 깊이가 바뀌어도 덱은 안 깨진다.
```js
const slides = [ /* 본문 슬라이드 객체들 */ ];
module.exports = { session: {
  no: <세션번호>, title: '<세션 제목>', slides,
  get toc() { return this.slides.map((s, i) => [String(i + 1).padStart(2, '0'), s.head || s.title]); }
}};
```
- `require`·`...G`·`if (require.main …)` self-run을 **넣지 않는다.** 실행·검증은 엔진/verify가 로더를 거쳐 한다:
  `node engine/verify.js <덱경로>` · `node engine/master_render.js <덱경로>` — 로더가 덱 위 과정 폴더에서 `global_config.js`를 찾아 병합한다(cwd 무관).
- **레이아웃 규약**(로더 discovery의 전제): `courses/<과정>/{ global_config.js, <커리큘럼>.md, decks/NN.js }`. 덱은 `decks/`에, config·커리큘럼은 과정 폴더에 둔다.
- `global_config.js`가 `book`·`curriculum`·`meta`를 소유한다. `curriculum`은 **배열**(스칼라면 엔진이 `.forEach`에서 터진다). `meta.quotes`는 **config 파일 기준 상대경로**(과정-로컬, 예: `'QM_커리큘럼.md'`) — 로더가 절대경로로 고정하므로 엔진·verify는 경로 계산을 하지 않는다.
- 자립 덱(테스트 fixture처럼 `curriculum`을 자체 포함)은 로더가 그대로 통과시킨다 — 이때 `meta.quotes`는 그 덱 파일 기준으로 해석한다.

## 1-b. 필수 필드 (누락 = 치명, pptx 생성 중단 / `--draft`면 경고로 강등)
**statement를 뺀 모든 본문 슬라이드**(학습 목표·현상·원인·원칙·적용·타협·요약)는 4종을 반드시 갖는다:
- `sub`      : 명제 한 줄 (무엇을 말하는가)
- `question` : 핵심 질문 한 줄, **물음표로 끝난다**
- `lead`     : `{ label, text }` — 문자열 아님
- `foot`     : `{ kw, color, body }` — 하단 결론. `color ∈ 'navy' | 'teal' | 'failL' | 'failT'`

- **statement(단문)만 예외**: `sub/question/lead/foot`를 쓰지 않는다. 대신 `visual.text` 또는 `visual.quote.ko` 중 하나는 반드시 있어야 한다(없으면 치명).
- **인용**(`quote` 또는 `visual.quote`)은 `{ id, ko, en, author }` 4필드 전부(하나라도 없으면 치명). `quote:"Q-..."`(문자열)는 오류. **같은 세션 안 같은 id 중복은 치명**(세션 간 재사용은 허용).
- 필수 구성: `kind:'학습 목표'` 슬라이드 1장 + **현상/원인/원칙/적용/타협 각 분류에 논증 슬라이드(=statement 아님) 최소 1장.** statement는 분류 요건을 못 채운다.

## 2. 전개와 분량 · 분류 어휘 (정본)
- 세션 본문은 **현상 → 원인 → 원칙 → 적용** 흐름으로 논리 분할(+ 타협 = 전제/Trade-off/실패조건).
- 분류 어휘 = **현상 / 원인 / 원칙 / 적용 / 타협**. 커리큘럼은 이 이름을 그대로 쓴다.
- 본문 슬라이드 **12~17장**(표지·목차 제외 · 벗어나면 경고). 분류별 최소 1장이 분량보다 우선.
- 한 슬라이드 = 한 명제. 장수를 채우려 명제를 쪼개거나 타 세션 내용을 끌어오지 않는다(개념 소유는 커리큘럼이 규정).

## 3. 시각 문법 — 타입별 data 스펙 (엔진 헤더 대조 · 정본)
`visual`은 **반드시 객체**다: `visual: { type, data, caption? }`. `type`만 쓰고 `data`를 빼면 그릴 게 없어 덱이 빈다(`visual:"pipeline"` 금지).

선택 규칙: 관계→flow/pipeline/loop · 항목→boxes/steps/versus/table · 숫자 명제→share/magnitude · 계층→pyramid · 두 축→quadrant. **표는 최후의 수단**("표로도 되는데"는 표를 고를 이유가 못 된다). "숫자가 명제" = 그 수치 자체가 주장일 때만(근거 수치는 → table).

| type | data 형태 | 비고 |
|---|---|---|
| `table` | `[[헤더…],[행…], …]` | 2차원 배열. 셀이 2줄 흐르면 밴드 초과 |
| `boxes` | `[{ title, body:[줄,…] }, …]` | 병렬 2~3요소 |
| `steps` | `[{ title, body:[줄,…] }, …]` | 3~4단계 권장, 본문 2줄까지 |
| `versus` | `[{ title, body:[줄,…], negative? }, …]` | 2열. 좌=적색/우=청록 기본. `negative:false`로 적색 해제 |
| `takeaways` | `[{ title, body }]` | 요약 슬라이드 전용. body는 문장 |
| `flow` | `{ dir:'LR'\|'TD', nodes:[{id,label}], edges:[{from,to,label?}] }` | 기본 LR. 노드 3~6, 라벨 10자 이내. 밴드 초과 시 오류 → 노드·라벨 줄인다 |
| `pipeline` | `{ nodes:[{id,label,gate?:true}], edges?:[{from,to,label?}] }` | edges 생략 시 순차 연결. `gate:true`=청록(통과/차단). 되돌림은 역방향 edge |
| `loop` | `{ nodes:[{id,label}], edges?:[{from,to,label?}] }` | 3~5노드, 원형 배치. 노드=타원, 라벨 짧게(한글 8자) |
| `share` | `[{ label, value, note? }]` | **합계 100**. 2~4항목. caption 필수(없으면 경고) |
| `magnitude` | `[{ label, value, unit?, note? }]` | 자릿수 격차(1/10/100). caption 필수(없으면 경고) |
| `pyramid` | `[{ label, note? }]` | 위(좁음)→아래(넓음) 순서로 준다 |
| `quadrant` | `{ x:{label,low,high}, y:{label,low,high}, cells:[{ at:'TL'\|'TR'\|'BL'\|'BR', title, body? }] }` | **4칸(TL/TR/BL/BR) 다 채운다** |
| `statement` | data 없음 — `{ type:'statement', text \| quote:{id,ko,en,author}, note?, caption? }` | 그림 없음. 세션당 2~3장(4장부터 경고) |

- `caption`(8pt): 근거·한계만. 저자·출처·인용 원문(영문)을 넣지 않는다(엔진이 강사 노트에 자동 첨부).
- 트리거 경고: 명제(sub/question/lead/foot)에 비율·배수가 있는데 시각화가 share/magnitude가 아니면 경고 → 근거 수치일 뿐이면 `visualNote`에 사유를 남겨 끈다.

## 4. 단문 슬라이드(`statement`)
- 세션 전환점을 한 문장으로 던진다. 질문·리드·결론(foot) 안 붙인다(골격 예외).
- 그림 안 넣는다. 세션당 2~3장, 4장부터 경고.
- 단문으로는 분류 요건을 채울 수 없다(논증 없는 장으로 분류를 때우면 교재가 빈다).
- 인용의 기본 자리는 단문이 아니라 논증 슬라이드 하단 `quote` 오버레이. 인용 하나에 단문 한 장 만들지 않는다.

## 5. 크기 위계
| 개체 | 크기 | 뜻 |
|---|---|---|
| `text` / `quote.ko` | 20pt | 이 슬라이드가 하려는 말 |
| `note` | 14pt | 해설(본문 크기, 각주 아님) |
| `quote.en` · 저자 · 출처 | 10pt | 인용 기본형(엔진이 자산에서 자동 첨부) |
| `caption` | 8pt | 한계만. 저자·출처·해설을 넣지 않는다 |

## 6. 인용 정책과 자산 블록 형식 (정본)
- `quote:{id,ko,en,author}` — id 필수. verify가 원문과 문자열 대조(환각·의역은 오류).
- URL은 슬라이드에 쓰지 않는다(엔진이 자산에서 강사 노트에 자동 첨부).
- 등급 어휘 = **PRIMARY**(원전 확인) / **WIDELY-CITED**(원전 미확인·통용 → 슬라이드에 한계 표기).
- 세션 간 재사용 허용, 같은 세션 내 중복 금지. **개수를 채우려 인용을 끌어오지 않는다**(세션 전체 0장도 정당).
- 세션 태그는 **권장 사용처**다. 태그 밖 사용은 금지가 아니라 경고(나선형 심화에서의 전용을 막지 않는다).

**인용 자산 블록 형식 (verify 파싱 대상).** 커리큘럼의 '인용 자산' 절은 아래 형식으로 적는다. 형식을 바꾸면 대조가 깨진다.
```
- `ID` [등급] 세션태그
  EN: 영문 원문
  KO: 한글 번역
  AUTHOR: 저자
  SRC: 출처(원전·페이지·한계)
  URL: (선택)
```

## 7. 톤
- 건조한 공학 문장. '완벽히·철저히·거대한·극단적인' 등 과장 수식어와 불필요한 영문 괄호 배제.
- 특정 국가·시장 관행 배제. 보편 공학 원칙과 비용 대비 효율만 기준.
- 명사 나열이 아니라 완결된 서술문으로 쓴다(엔진 [형식 앵커 예시]의 문장 밀도).

## 8. 강사 노트(`notes`)
- 모든 본문 슬라이드에 쓴다(없으면 경고). 길이 하한 없음(쿼터는 채우기를 부른다).
- 슬라이드에 안 넣은 것을 넣는다: 던질 질문, 흔한 반론, 시간 배분, 인용의 한계.
