# 교재 작성 지침 (도메인 독립 · 형식 어휘의 정본)
> 버전: v1.4 (세션 유형 · 장수 파생 · bullets · part · claim)

> 이 문서는 어떤 주제의 교재든 공통으로 적용되는 **형식 계약**이며, 형식 어휘의 정본이다.
> **덱 세션에서 커리큘럼과 함께 첨부한다.** 커리큘럼 작성 지침은 여기의 어휘를 *참조*할 뿐 소유하지 않는다.
> 주제·내용은 여기 없다 — 그건 커리큘럼에 있다.
> **최종 정본은 엔진 소스다.** 이 문서는 사람용 요약이며 충돌 시 엔진이 우선한다(verify가 드리프트를 잡는다).
> 규칙별 정본 파일: 골격=`engine/skeleton.js` · 데이터 형태=`engine/shape.js` · 기하=`engine/layout.js`
> · 세션 요건=`engine/session_types.js` · 과정 요건=`engine/course.js`.

---

## 0. 무엇을 누가 정하는가 (v1.4의 핵심 변경)

이 계약은 **형식**만 정한다. 무엇을 말할지는 커리큘럼이 정한다.

| 결정 | 주인 |
|---|---|
| 세션의 유형·분량 | 커리큘럼 노드 |
| 각 장이 무엇을 주장하는가(명제) | 커리큘럼 노드 |
| 본문 장수 | **파생값** = 명제 수 + 고정 장 |
| 그림이어야 하는 명제의 시각 타입 | 커리큘럼 노드(`시각 지정`) |
| 문구·강사 노트·나머지 시각 선택 | 덱 생성 |

**장수 범위 검사는 없다.** 예전 계약의 "본문 12~17장"은 폐기했다 — 범위를 두면 하한이 목표가 되고, 실제로 다섯 덱이 전부 하한 12장에 붙었다.

---

## 1. 덱 데이터 스키마

- 덱 = `{ session:{ no, title, type?, slides:[...] } }` — **순수 데이터**. `book`·`curriculum`·`meta`는 과정의 `global_config.js`가 소유하고 로더(`engine/load_deck.js`)가 병합한다. 덱은 경로·config·self-run을 담지 않는다.
- 슬라이드 = `{ kind, title, head?, part?, claim?, sub, question, lead, visual, quote?, foot, notes }`.
- 파일은 **CommonJS**: `module.exports = { session:{...} }`. `export default` 아님.
- 파일명은 `NN.js`(01.js…), 위치는 `courses/<과정>/decks/`.

### 1-a. 덱 껍데기
```js
const slides = [ /* 본문 슬라이드 객체들 */ ];
module.exports = { session: {
  no: <세션번호>, title: '<세션 제목>', type: '<세션 유형>',   // type 생략 시 설명형
  slides,
  get toc() { return this.slides.map((s, i) => [String(i + 1).padStart(2, '0'), s.head || s.title]); }
}};
```
- `require`·`...G`·self-run을 **넣지 않는다.** 실행은 `node engine/verify.js <덱>` · `node engine/master_render.js <덱>`.
- **레이아웃 규약**: `courses/<과정>/{ global_config.js, <커리큘럼>.md, decks/NN.js }`.
- `global_config.js`가 `book`·`curriculum`·`meta`·`course`를 소유한다. `meta.quotes`는 config 기준 상대경로.

### 1-b. 골격 — 필수 5종 (누락 = 치명)
**statement를 뺀 모든 본문 슬라이드**는 다섯을 반드시 갖는다:

- `sub`      : 명제 한 줄
- `question` : 핵심 질문, **물음표로 끝난다**
- `lead`     : `{ label, text }` — 문자열 아님
- `visual`   : `{ type, data, caption? }` — **없으면 슬라이드 가운데가 빈 채로 렌더된다**
- `foot`     : `{ kw, color, body }` — `color ∈ 'navy'|'teal'|'failL'|'failT'`

`visual`이 골격에 들어간 이유: 시각 없는 본문 장은 y 2.3~5.7이 통째로 빈다. 예전엔 경고였는데 실제로 세 장이 그 상태로 남았고 아무도 못 봤다 — **경고는 쌓이면 읽히지 않는다.** 억제 필드는 없다. 한 문장만 던질 자리는 `statement`가 담당하며 그것이 유일한 예외다.

`notes`(강사 노트)는 모든 본문 슬라이드에 쓴다(없으면 경고).

## 2. 세션 유형 — 요건은 유형이 정한다 (정본: `engine/session_types.js`)

현상·원인·원칙·적용·타협은 형식이 아니라 **개념을 가르치는 한 가지 교수법**이다. 그것이 계약에 박혀 있으면 워크숍도 종합 정리도 그 방식이 된다. 그래서 유형을 밖으로 꺼냈다.

| 유형 | 고정 장(명제 없음) | 필수 분류(각 1장 이상) | 선택 | 장당 시간 |
|---|---|---|---|---|
| `설명형`(기본) | 학습 목표 · 요약 | 현상 · 원칙 · 적용 | 원인 · 타협 | 약 4분 |
| `워크숍형` | 목표 · 디브리프 | 준비 · 진행 · 산출 | — | 약 12분 |
| `종합형` | 요약 | 연결 | 적용 · 타협 | 약 4분 |

- `session.type` 미선언 = `설명형`.
- 유형에 없는 `kind`를 쓰면 오류.
- **필수 분류는 statement로 채울 수 없다** — 논증 없는 장으로 분류를 때우면 교재가 빈다.
- 설명형 필수가 셋인 이유: 다섯이면 최소 7장이 강제되고 거기 균형을 맞추면 12장이 나온다. 원인이 자명한 주제도, 타협이 없는 주제도 있다.

## 3. 명제와 장수 (`claim`)

커리큘럼 노드의 명제 목록이 각 장의 주장이다. 덱은 장마다 어느 명제를 맡는지 밝힌다.

- `claim: 'C3'` — 고정 장(학습 목표·요약 등)을 뺀 모든 본문 슬라이드에 붙인다(없으면 경고).
- **명제 하나가 한 장이다(1:1).** 같은 명제를 두 장이 맡으면 오류 — 두 장이 필요하면 커리큘럼에서 명제를 쪼갠다.
- `claim`의 분류가 그 장의 `kind`가 된다(불일치 = 오류).
- **본문 장수 = 명제 수 + 고정 장.** 불일치 = 오류.
- 커리큘럼에 명제 목록이 없으면(구 형식) 이 검사는 건너뛴다.

---

## 4. 부 (`part`) — 선택

한 세션 안에서 주제가 갈릴 때 쓴다.

- `part: '1부 — CMMI'`. 세션 목차가 이 라벨로 묶어 그린다.
- **같은 부의 장은 붙어 있어야 한다**(떨어져 다시 나오면 오류). 부가 하나뿐이면 경고.
- **부 구분 슬라이드는 만들지 않는다** — 목차의 그룹 헤더와 헤더 연번으로 위치는 충분히 전달된다.
- 판단: **학습 목표·요약을 공유하면 한 세션의 두 부, 각자 가지면 두 세션.**

## 5. 시각 문법 — 타입별 data 스펙 (정본: `engine/shape.js`·`engine/layout.js`)

`visual`은 **반드시 객체**다: `{ type, data, caption? }`. `visual:"pipeline"` 금지.

**항목 계열의 `body`는 전부 문자열 배열이다** — 원소 하나가 한 문단. 문자열로 써도 엔진이 감싸 보정하고 `[형태 보정]`으로 알리지만, 보정에 기대지 않는다.

| type | data 형태 | 비고 |
|---|---|---|
| `bullets` | `[{ text }]` 또는 `[{ head, text }]` | **2~6개**(양 끝 오류). 거버닝 메시지는 `lead`에 있으므로 여기엔 본문만 |
| `boxes` | `[{ title, body:['줄','줄'] }, …]` | 병렬 2~3요소 |
| `steps` | `[{ title, body:['줄','줄'] }, …]` | 3~4단계 권장 |
| `versus` | `[{ title, body:['줄','줄'], negative? }, …]` | 2열. `negative:false`로 적색 해제 |
| `table` | `[[헤더…],[행…]]` | 모든 행의 칸 수가 같아야 한다. **표는 최후의 수단** |
| `takeaways` | `[{ title, body:['한 문장'] }]` | 요약 장 전용 |
| `flow` | `{ dir:'LR'\|'TD', nodes:[{id,label}], edges:[{from,to,label?}] }` | 기본 LR. **밴드 초과를 피하려고 TD로 돌리지 않는다** |
| `pipeline` | `{ nodes:[{id,label,gate?}], edges? }` | edges 생략 시 순차. `gate:true`=통과/차단 |
| `loop` | `{ nodes:[{id,label}], edges? }` | 3~5노드, 타원. 라벨 한글 8자 |
| `share` | `[{ label, value, note? }]` | 합계 100. caption 필수 |
| `magnitude` | `[{ label, value, unit?, note? }]` | 자릿수 격차. caption 필수 |
| `pyramid` | `[{ label, note? }]` | 위(좁음)→아래(넓음) 순. 라벨은 이름만, 설명은 `note` |
| `quadrant` | `{ x:{label,low,high}, y:{…}, cells:[{at:'TL'\|'TR'\|'BL'\|'BR', title, body?}] }` | 4칸 다 채운다 |
| `statement` | data 없음 — `{ type:'statement', text \| quote:{id,ko,en,author}, note?, caption? }` | 세션당 2~3장(4장부터 경고) |

### 5-a. `bullets`와 `boxes`의 구분
- 이름이 붙는 항목이면 `boxes`, 이름 없는 근거 나열이면 `bullets`.
- **어느 쪽인지는 기계가 판정하지 않는다** — `boxes`에는 언제나 `title`이 있으니 형식만으로는 통과한다. 그래서 판정을 저작 시점으로 옮겼다: **커리큘럼의 `시각 지정`이 정한다.**
- `bullets`는 그리기 어려운 명제의 탈출구가 될 수 있다. 비중이 늘면 과정 검사기의 타입 분포에 드러난다.

### 5-b. caption
8pt, **근거·한계 전용**. 저자·출처·인용 원문을 넣지 않는다(엔진이 강사 노트에 자동 첨부).

---

## 6. 단문 (`statement`)
- 세션 전환점을 한 문장으로 던진다. 골격(sub/question/lead/foot)을 쓰지 않는다.
- 그림 안 넣는다. **단문의 힘은 비어 있음에서 나온다.**
- **분류 요건을 채울 수 없다.**
- 인용의 기본 자리는 단문이 아니라 논증 슬라이드 하단 `quote` 오버레이. 인용 하나에 단문 한 장 만들지 않는다.

## 7. 크기 위계
| 개체 | 크기 | 뜻 |
|---|---|---|
| `text` / `quote.ko` | 20pt | 이 슬라이드가 하려는 말 |
| `note` | 14pt | 해설(각주 아님) |
| `quote.en` · 저자 · 출처 | 10pt | 인용 기본형(엔진 자동 첨부) |
| `caption` | 8pt | 근거·한계만 |

## 8. 인용 (정본: `engine/quotes.js`)
- `quote:{id,ko,en,author}` — 4필드 전부(하나라도 없으면 치명). verify가 자산 원문과 문자열 대조(환각·의역 = 오류).
- 등급 = **PRIMARY**(원전 확인) / **WIDELY-CITED**(원전 미확인·통용 → 슬라이드에 한계 표기).
- 세션 간 재사용 허용, **같은 세션 내 중복 금지**.
- **개수를 채우려 인용을 끌어오지 않는다**(세션 전체 0장도 정당).
- URL은 슬라이드에 쓰지 않는다.

**인용 자산 블록 형식 (verify 파싱 대상)**
```
- `ID` [등급] 세션태그
  EN: 영문 원문
  KO: 한글 번역
  AUTHOR: 저자
  SRC: 출처(원전·페이지·한계)
  URL: (선택)
```

## 9. 밀도 — 기록이지 판정이 아니다
verify가 매 실행에 `밀도: 시각 N장 · 단문 N장 · 시각 없음 N장 | 시각 내용 N자 · 밴드 점유 N% | …`를 찍는다.

**임계는 없다.** 타입마다 정상값이 다르고(`flow` 4노드 16자 vs `bullets` 5줄 200자) 절대 기준은 반드시 하나를 오측정한다. 편차는 임계가 아니라 **과정 단위 비교표**(`npm run course`)가 드러낸다.

## 10. 톤
- 건조한 공학 문장. '완벽히·철저히·거대한·극단적인' 등 과장 수식어 배제.
- 특정 국가·시장 관행을 **원칙의 자리에 두지 않는다**(사례로 쓰는 규칙은 커리큘럼 지침 참조).
- 명사 나열이 아니라 완결된 서술문. 뜻이 깎이면 2줄을 쓴다(엔진이 박스를 키운다).

## 11. 검사 실행
```
node engine/cli.js check  <덱>        verify
node engine/cli.js build  <덱>        verify 게이트 통과 시 렌더
```
