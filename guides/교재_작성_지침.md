# 교재 작성 지침 (도메인 독립 · 형식 어휘의 정본) > 버전: v1.0

> 이 문서는 어떤 주제의 교재든 공통으로 적용되는 **형식 계약**이며, 형식 어휘의 정본이다.
> **덱 세션에서 커리큘럼과 함께 첨부한다.** 커리큘럼 작성 지침은 여기의 어휘를 *참조*할 뿐 소유하지 않는다.
> 주제·내용은 여기 없다 — 그건 커리큘럼에 있다.
> 최종 정본은 `engine/master_render.js` 헤더이며, 충돌 시 엔진이 우선한다(verify 드리프트 가드).

## 1. 덱 데이터 스키마
- 덱 = `{ ...config, session:{ no, title, slides:[...] } }` (toc는 엔진이 slides에서 파생).
- 슬라이드 = `{ kind, title, sub?, question?, lead?, visual?, quote?, foot, notes? }`.
- `kind ∈ 학습목표 | 현상 | 원인 | 원칙 | 적용 | 타협 | 요약`.
- 정확한 필드·타입은 엔진 헤더가 정본.

## 2. 전개와 분량 · 분류 어휘 (정본)
- 세션 본문은 **현상 → 원인 → 원칙 → 적용** 흐름으로 논리 분할.
- 분류 어휘 = **현상 / 원인 / 원칙 / 적용 / 타협**. 커리큘럼은 이 이름을 그대로 쓴다.
- 본문 슬라이드 **12~17장**(표지·목차 제외). 분류별 **최소 1장**이 분량보다 우선.
- 분량 하한으로 타 세션 내용을 끌어오지 않는다(개념 소유는 커리큘럼이 규정).

## 3. 시각 문법 — 타입 어휘와 선택 규칙 (정본)
타입 어휘: `flow` `pipeline` `loop` `boxes` `steps` `versus` `table` `share` `magnitude` `pyramid` `quadrant` `statement`.
선택 규칙(무엇을 그릴지는 커리큘럼이 정하고, 타입은 이 규칙으로 고른다):
- 관계가 내용 → `flow` / `pipeline` / `loop`
- 항목이 내용 → `boxes` / `steps` / `versus` / `table`
- 숫자가 명제 → `share` / `magnitude` · 계층 → `pyramid` · 두 축 → `quadrant`
- **표(`table`)는 최후의 수단.** 타입 선택 실패가 표로 흘러간다.
- "숫자가 명제" = 그 수치 자체가 슬라이드의 주장일 때. 근거 수치는 명제가 아니다(→ 표).
- 수치를 그림으로 올리면 `caption`에 출처·한계를 반드시 적는다.
- `loop`의 노드는 타원, 라벨 예산 10pt 한글 8자(노드는 문장이 아니라 상태의 이름).

## 4. 단문 슬라이드(`statement`)
- 세션 전환점을 한 문장으로 던진다. 질문·리드·결론 안 붙인다(골격 예외).
- 그림 안 넣는다. 세션당 2~3장, 4장부터 경고.
- 단문으로는 분류 요건을 채울 수 없다(논증 없는 장으로 분류를 때우면 교재가 빈다).
- 인용의 기본 자리는 단문이 아니라 논증 슬라이드 하단 `quote` 오버레이. 인용 하나에 단문 한 장 만들지 않는다.

## 5. 크기 위계
| 개체 | 크기 | 뜻 |
|---|---|---|
| `text` / `quote.ko` | 20pt | 이 슬라이드가 하려는 말 |
| `note` | 14pt | 해설(본문 크기, 각주 아님) |
| `quote.en` · 저자 · 출처 | 10pt | 인용 기본형(엔진이 자산에서 자동 첨부) |
| `caption` | 8pt | 한계만. 저자·출처·해설을 넣지 않는다 |

## 6. 인용 정책과 자산 블록 형식 (정본)
- `quote:{id,ko,en,author}` — id 필수. verify가 원문과 문자열 대조(환각·의역은 오류).
- URL은 슬라이드에 쓰지 않는다(엔진이 자산에서 강사 노트에 자동 첨부).
- 등급 어휘 = **PRIMARY**(원전 확인) / **WIDELY-CITED**(원전 미확인·통용 → 슬라이드에 한계 표기).
- 세션 간 재사용 허용, 같은 세션 내 중복 금지. **개수를 채우려 인용을 끌어오지 않는다.**
- 세션 태그는 **권장 사용처**다. 태그 밖 사용은 금지가 아니라 경고(나선형 심화에서의 전용을 막지 않는다).

**인용 자산 블록 형식 (verify 파싱 대상).** 커리큘럼의 '인용 자산' 절은 아래 형식으로 적는다. 형식을 바꾸면 대조가 깨진다.
```
- `ID` [등급] 세션태그
  EN: 영문 원문
  KO: 한글 번역
  AUTHOR: 저자
  SRC: 출처(원전·페이지·한계)
  URL: (선택)
```

## 7. 톤
- 건조한 공학 문장. '완벽히·철저히·거대한·극단적인' 등 과장 수식어와 불필요한 영문 괄호 배제.
- 특정 국가·시장 관행 배제. 보편 공학 원칙과 비용 대비 효율만 기준.

## 8. 강사 노트(`notes`)
- 모든 본문 슬라이드에 쓴다(verify 경고). 길이 하한 없음(쿼터는 채우기를 부른다).
- 슬라이드에 안 넣은 것을 넣는다: 던질 질문, 흔한 반론, 시간 배분, 인용의 한계.
