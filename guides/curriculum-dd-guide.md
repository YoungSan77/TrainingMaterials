# Curriculum / Session DD Guide

승인 순서·변경 통제·기준선 기록은 `governance.md`가 정한다. 이 지침은 세션 사이와 세션 내부의 교육 설계를 소유한다. Markdown이나 Renderer의 기능을 교육 설계의 범위로 사용하지 않는다.

## Curriculum / Session Architecture

- **시작 확인** — Governance의 「단계 시작 계약」에 따라 이 지침, Course Design 승인 버전, 편성·시간·인계의 변경 허용 범위를 대조한다.
- **필수 입력** — 승인된 Course Design의 과정 목표·범위·시간 예산·공통 사례, 대상의 선수지식, 해당 과정에 지정된 검증 근거.
- **출력과 책임** — 과정 Overview와 Session Architecture를 `curriculum.md`에 작성한다. 세션별 ID·제목·역할, 순서, 강의·실습·토론 및 휴식을 구분한 시간, 선행 입력과 확정 산출물의 인계, 목표의 분담과 제외 범위, DD 경로를 기록한다. DD의 전체 주장·사례·프롬프트를 복제하지 않는다.
- **승인과 진입** — 먼저 Architecture에 대한 Human 승인을 받는다. 이후 승인된 DD들을 연결해 합계, 선수 관계, 중복·누락과 학습 흐름을 전체 통합 검토한다. 같은 예가 새로운 질문에 쓰이는 경우와 같은 판단을 반복하는 경우를 구분한다. 통합본의 Human 승인이 Deck Authoring의 진입 조건이다.
- **필수 검사** — ID·경로의 유일성과 존재, 시간 합계, 선행 산출물의 선후 관계, 과정 교육 목표별 세션 연결을 대조한다(학습 성과를 정의한 과정은 그 성과별 연결도 함께 본다). 전용 하네스는 미구현 요구이며 수동 대조 결과를 별도로 남긴다. 학습 전개의 타당성, 활동 시간의 현실성, 선행과 중복의 교육적 이유는 의미 검토한다.
- **실패·기준선** — 경계나 총시간 변경이 필요하면 Course Design에 환류한다. 세션 사이 시간·순서 수정은 Curriculum의 변경으로 기록하고 영향을 받는 DD·Deck을 식별한다. 승인 Architecture, 통합본과 참조 DD 버전을 과정 기록에 연결한다.

## Session DD

- **시작 확인** — Governance의 「단계 시작 계약」에 따라 이 지침, 승인 Architecture와 연결된 Course Design·선행 DD의 버전, 대상 DD의 변경 허용 범위를 대조한다.
- **필수 입력** — 승인 Architecture, 과정 공통 전제와 지정 출처, 세션별 역할과 시간, 승인된 선행 DD 및 해당 실습의 확정 입력.
- **출력과 책임** — `sNN-detailed-design.md`에 세션의 거버닝 메시지, 학습자가 답할 판단 질문, 학습 성과, 핵심 주장과 순서를 적는다. 각 주요 가르침은 정의·대조·근거·사례 및 필요한 경우 반례나 실패 기준과 연결한다. 도식이 전달할 관계·상태·순서, 표의 비교 기준·값, 코드의 동작·기대 결과를 정한다. 최종 문구·시각 표현은 Deck, 실제 좌표·페이지 분할은 Production에 위임한다.
- **실습 계약** — 입력·과제·추천 프롬프트·결과물·검토 기준과 총시간을 명시한다. 결과에 문제가 없으면 승인할 수 있는 조건과, 근거 있는 불일치에만 개입하는 조건을 정한다. 비교 실습의 Before/After는 동일 대상과 범위, 실제 차이와 근거를 지정한다. 실행 증거가 없거나 명확한 결함이 없으면 그 상태를 표시한다. 답안 공개 순서와 강사 개입·세부 시간 배분·운영 조건을 학습자 본문 요구와 구분한다.
- **승인과 진입** — Human이 메시지·정의·근거·학습 흐름·실습 판정 기준을 검토하고 대상 DD 버전을 승인한다. 통합 검토에서 변경된 승인 항목을 다시 확인한다. 실행 증거를 교재에 싣는 계약이라면 최종 Deck 승인 전에 실제 입력·응답·선정 근거를 대조한다.
- **필수 검사** — 필수 항목·안정된 참조·출처 기록·실습 시간 합계·승인 입력 연결을 대조한다. DD 전용 자동 검사는 미구현 요구이며 수동 확인을 별도 기록한다. 근거가 주장을 지지하는지, 도식과 코드가 같은 의미를 보이는지, 검토 기준으로 실제 판단할 수 있는지는 의미 검토한다. 실행 검증은 `session-authoring-guide.md`의 실습 검증 절을 따른다.
- **실패·기준선** — DD 안의 결함은 승인 범위에서 고친다. 선행 개념 누락이나 세션 역할·시간 충돌은 Curriculum으로, 과정의 공통 값·업무 규칙 충돌은 Course Design으로 돌린다. 승인 DD, 입력 버전, 변경 사유와 영향을 받는 Deck을 기존 과정 기록에 남긴다.
