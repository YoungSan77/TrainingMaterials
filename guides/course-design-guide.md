# Course Design Guide

## 목적

Course Design은 과정 전체의 의미 구조와 세션 경계를 정의한다. 그 이상을 소유하지 않는다.

모든 과정은 `sw-engineering-principles.md`의 기본 원칙을 따른다.

## 필수 항목

- 총 교육시간
- 대상 / 선수지식
- 과정 목표
- 범위·제외 범위와 세션 간 판단 경계
- 과정 공통 판단 원칙
- 재사용하는 사례·실습 방향과 **공통 전제** — 관통 사례의 공통 식별자(용어, 상태 값, 흐름 번호, 이벤트·오퍼레이션 이름, 외부 시스템)를 표 하나에 둔다. 이 표가 원고·다이어그램·예시 코드가 쓰는 이름과 값의 **유일한 원천**이다. 설계와 코드가 있는 과정은 **영한 용어집과 명명 규칙**(한글 용어 ↔ 설계·코드의 영문 이름)을 함께 둔다
- 목차 / 세부 목차(설계 용어를 사용할 수 있으나 Session Source topic 제목은 SA의 한글 중심 규칙을 따른다)
- 세션별 시간
- 세션별 목표
- Anchor Message (세션마다 한 개, 수강생이 가져가야 할 핵심 메시지. Session Source의 별도 `앵커 메시지` 블록을 의미하지 않는다.)
- 과정의 맥락 — 대상의 성숙도와 과정이 다루는 불확실성, 그에 따른 깊이의 결정(「과정의 맥락」)
- 관통 사례 — 요구에서 코드·테스트까지 이어 쓰는 사례와, 세션마다 그 사례에서 새로 답하는 결정(요구·분석·설계·코드·테스트 중 어디인지)
- 실습 관통 사례 — 실습을 하나의 시나리오로 잇는 신규 개발 사례(강의 사례와 별개일 수 있음)와 세션마다의 실습 산출물 순서. 사례의 이름·규칙의 원천(첫 실습의 답 (안))을 밝히고, 강의 사례의 공통 식별자와 섞지 않는다(작성 방식은 `session-authoring-guide.md`의 「사례·가정·실습」)
- 세션별 다이어그램과 코드 — 세션이 다루는 다이어그램과 그 다이어그램을 잇는 예시 코드·테스트를 세부 목차에 한 줄로 밝힌다(예: "클래스 다이어그램 초안·상세와 자바 코드·테스트")

## 과정의 맥락

과정의 맥락은 이 과정이 **누구에게, 어떤 불확실성을, 어느 깊이로** 다루는지 정한다. 세션의 깊이·사례의 난이도·실습 방식·시간 평가의 근거가 되며, 대상 정보(직무·선수지식)와 구분한다(`sw-engineering-principles.md` 3절).

- **대상의 성숙도** — 도메인 지식, 기술 숙련(이 과정이 요구하는 언어 독해·모델링·도구 경험 등), 팀워크(요구 합의·리뷰·협업 방식)를 관점마다 한 줄로 적는다. 확인한 사실과 가정을 구분하고, 가정이면 확인 방법(사전 설문·과제 등)을 적는다.
- **다루는 불확실성** — 과정의 사례와 판단이 다루는 업무 불확실성(규칙·범위가 불분명한 정도)과 기술 불확실성(새 기술·제약)을 적는다.
- **깊이의 결정** — 위 두 항목에서 나온 결정이다. 무엇을 명시하고 먼저 검증할지(성숙도가 낮거나 불확실성이 큰 관점), 무엇을 가볍게 다룰지(성숙도가 높고 영향이 작은 관점)를 과정 수준으로 정한다.
- **운영 조건** — 인원, 실습 형태(개인·소그룹), 실습 환경처럼 교육량과 방식을 바꾸는 조건을 적는다. 모르면 가정으로 표시한다. 모든 과정의 실습은 수강생이 **LLM**을 쓰는 것을 전제로 하므로, 그 환경을 운영 조건에 적는다(실습 방식은 `session-authoring-guide.md`의 「사례·가정·실습」).

맥락은 한 번 정하고 끝내지 않는다. 최종 SA 완성 후 강의·실습 검토, 실제 교육 후 피드백으로 확인하고, 달라지면 깊이의 결정과 세션 시간을 함께 고친다.

## 좋은 Course Design의 판단 기준

- 과정의 맥락에서 깊이의 결정이 나오고, 세션별 목표·세부 목차의 깊이가 그 결정과 맞는다. 성숙도·불확실성을 적지 않고 깊이를 정하지 않는다.

- 세션 경계가 중복 없이 과정 목표 전체를 나눈다.
- 세션별 시간 합계가 총 교육시간과 정확히 일치한다.
- 세션별 시간은 계획값으로 기록한다. 최종 SA 완성 후 실제 설명·실습·토론과 대상자의 선수지식을 기준으로 적합성을 평가한다. 세션별 균등 배분이나 topic 수만으로 교육량을 판단하지 않는다.
- 목차만으로 세션 간 순서와 경계를 알 수 있다.
- SA의 핵심 주제가 Course Design의 세부 목차에 의미 있게 대응한다. 개요의 예시 미리보기와 후속 세션의 본격 판단을 구분하며, 등장했다는 이유만으로 중복이나 범위 위반으로 판정하지 않는다.
- Anchor Message는 학습자 본문에서도 확인 가능해야 한다. 원고 검토에서 강사 노트에만 있는 메시지를 충족으로 보지 않는다.
- Anchor Message가 한 문장으로 그 세션의 핵심을 전달한다.
- Anchor Message는 Session Authoring의 방향을 통제하는 설계 수준의 기준이며, 슬라이드에 별도 라벨이나 전용 블록으로 노출할 필요는 없다.

## 내용 완성과 시간 평가

- SA 작성 중에는 정해진 시간 때문에 필요한 설명·사례·실습·검토 기준을 축소하거나 의미를 왜곡하지 않는다.
- 시간 계획의 합계 검산과 교육 시간의 적합성 평가는 구분한다. 합계가 맞는다고 실제 교육량이 적절하다고 판정하지 않는다.
- 최종 SA를 완성한 뒤 강의·실습 진행 검토와 **과정의 맥락**(대상의 성숙도·운영 조건)을 근거로 시간·운영 방식을 조정한다. 휴식 포함 여부도 확인 없이 확정하지 않는다.
- 내용의 중복이나 목적과 무관한 상세는 학습 목적을 근거로 정리한다. 시간에 맞추려는 삭제와 혼동하지 않는다.

## 세션 간 경계와 지침 변경

- 개요 세션은 핵심 개념의 의미·역할·관계를 설명하고 적용 예를 미리 보여줄 수 있다. 대안의 본격적인 선택·검증을 어느 세션에서 다루는지 명시한다.
- 같은 개념을 여러 세션에서 다루면 각 세션의 질문·상세화 수준·다음 세션으로 이어지는 판단을 명시한다. 단순한 재등장이 곧 중복은 아니다.
- 필요한 개념이 빠졌거나 목표와 실제 내용이 어긋나면 과정 목표·세부 목차·SA를 함께 정렬한다. 시간 때문에 목표를 축소하지 않는다.
- 여러 세션에 재사용하는 용어·사례의 공통 전제는 이 Course Design에 둔다. 개별 예시의 추가 가정은 해당 SA에 표시한다.
- 공통 식별자는 `sw-engineering-principles.md`의 **진화와 오류**를 따른다. 뒤 세션이 발견해 더한 값(진화)은 그 세션에서 보이고 공통 전제에 반영한다. 같은 대상의 다른 이름·규칙(오류)은 공통 전제에 맞춰 모든 세션을 고친다.
- 개요 세션은 다이어그램마다 **한 장의 미리보기**(다이어그램과 짧은 코드)로 "왜 필요한가"를 보이고, 표기·작성법·코드 매핑의 상세는 해당 상세 세션이 맡는다. 개요에서 상세를 반복하지 않는다.
- 산출물 결함을 수정할 때 공통 지침의 누락·모호함도 점검한다. 재사용 가능한 작성 원칙은 해당 지침에, 과정 고유의 정책·사례·결정은 과정 문서에 반영한다.
- 출처를 필요로 하는 사실·통계·표준 주장을 Course Design에 넣으면 Session Authoring Guide와 동일한 검증 원칙을 적용한다. 학습 순서를 보편적 개발 절차나 필수 기술 의존관계로 단정하지 않는다.

## 하지 말아야 할 것

- Session 상세 설명 작성
- slide 설계, visual 배치
- 코드 상세 작성
- renderer 제약 반영
- Curriculum/DD 생성

Course Design은 downstream Production의 형식이나 제약에 끌려가지 않는다. Production이 무엇을
할 수 있는지는 Course Design의 판단 기준이 아니다.

## Downstream handoff

Course Design의 각 세션 정의는 Session Authoring의 입력이 된다.
Anchor Message는 Session Authoring에서 각 topic의 설명·정의·사례·인용문에 자연스럽게 반영하며, 별도 `앵커 메시지` 구분자를 강제하지 않는다.
Session Source 작성 규칙은 `session-authoring-guide.md`를 따른다.
