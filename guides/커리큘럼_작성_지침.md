# 커리큘럼 작성 지침

> `portfolio/governance.md`가 통제하는 Curriculum stage annex다. Workflow, authority와 Session 01 공통 Guardrail은 Governance가 소유하며 여기서 반복 정의하지 않는다.

## Input

- 이 지침
- 승인된 해당 과정 Course Design 전체
- Course Design이 요구하거나 허용한 Portfolio Common Standards
- Course Design에 포함되거나 연결된 검증된 Source와 실습 설계
- User Intent의 시간·운영 제약

기존 Curriculum, Deck, legacy session source와 다른 과정의 산출물은 생성 입력이나 보존 제약이 아니다.

## Start Condition

다음이 모두 제공되면 Curriculum LLM은 추가적인 장문 prompt를 요구하지 않고 `Working Procedure` Step 1부터 자동으로 진행한다.

- 이 Curriculum Guide
- 승인된 Course Design
- Course Design이 요구하거나 허용한 Portfolio Common Standards와 검증된 Source·Anchor·Reference
- 사용자의 명시적인 Curriculum 개발 시작 요청

필수 입력이 없거나 서로 충돌하면 내용을 추측해 채우지 않고 blocker와 필요한 입력을 사용자에게 요청한다.

## Working Procedure

이 절은 Governance가 소유하는 Human-in-the-Loop authority를 실행하는 Curriculum LLM의 작업 절차다.

1. **Course Overview + Session Architecture:** Course Design의 capability, progression, topic/decision weight, 실습과 duration에서 Course Overview와 Session Architecture만 작성하고 사용자 승인을 기다린다. 첫 응답에서 Session Detailed Design이나 전체 상세 Curriculum을 생성하지 않는다.
2. **Session Detailed Design:** Session Architecture 승인 후 첫 Session부터 하나씩 상세 설계한다. 현재 Session의 사용자 승인 전에는 다음 Session 상세 설계를 시작하지 않는다.
3. **Upward Feedback:** Session Detailed Design 중 Course Design 또는 Session Architecture의 누락·모순·부정확한 경계, 선수 개념 누락이나 이미 승인된 앞 Session과의 narrative 단절이 발견되면 임의로 우회하거나 현재 Session 안에서만 보정하지 않는다. 영향 범위와 최소 수정안을 사용자에게 제시하고, 승인 후 필요한 상위 기준 또는 앞 Session을 먼저 보완한 뒤 현재 Session 상세 설계를 계속한다.
4. **Approved Session Preservation:** 승인된 Session은 승인되지 않은 변경으로부터 보존한다. Preservation은 불변성을 뜻하지 않는다. 후속 상세 설계에서 선수 개념 누락·용어 충돌·narrative 단절 등 수정 필요성이 발견되면 변경 이유·영향 범위·최소 수정안을 명시하고 사용자 재승인을 받아 수정할 수 있다. 승인 내용이 현재 context에 없으면 임의 복원하지 않고 사용자에게 승인본을 요청한다.
5. **Whole-Curriculum Integration:** 모든 Session이 승인된 뒤 승인본 전체를 모아 `Whole-Curriculum Integration Review`를 수행하고 최종 Curriculum으로 재구성한다. 승인본을 단순 concatenate하지 않는다.
6. **Final Approval:** 통합된 전체 Curriculum이 사용자에게 최종 승인된 뒤에만 Deck stage의 승인 입력으로 간주한다.
7. **Periodic Authoring Rule Harvest and Intermediate Review:** 긴 Curriculum 개발에서는 판단 근거와 반복 패턴이 유실되지 않도록 **3개 Session의 상세 설계·승인이 진행될 때마다** 중간 회수와 전반적 중간 평가를 함께 수행한다. 첫 회수 시점이 이미 지나간 경우 현재 시점의 회수를 기준점으로 삼고 다음 3개 Session 완료 후 다시 수행한다. 중간 평가는 해당 구간뿐 아니라 지금까지 완성된 Curriculum 전체를 대상으로 narrative, 선수 관계, 중복·누락, boundary drift, Course Design·Session Architecture 정합성, 반복되는 Human–LLM 판단과 실패 패턴을 점검한다. 그 결과에서 과정별 내용과 일회성 예외를 분리하고, 다른 Session·과정에도 재사용할 가치가 있는 Rule of Thumb만 Curriculum Guide, Governance 또는 Portfolio Common Standard의 보완 후보로 제안한다. 필요한 상위 기준 보완은 Human 승인 후 즉시 반영하여 이후 Session에 사용한다. 필요하면 Codex·Claude Code 등 독립된 코드/LLM 검토를 통해 규칙의 일관성·중복·과잉 일반화와 이전 시행착오의 반복 여부를 평가한 뒤 Human이 반영 여부를 결정한다.
8. **Final Authoring Integration:** 전체 Curriculum이 완성되면 중간 평가와 회수에서 축적·반영한 Rule of Thumb과 상위 기준을 전체 과정 관점에서 다시 조율한다. 이 단계는 처음부터 규칙을 회수하는 단계가 아니라, 이미 수시로 반영된 기준의 중복·충돌·누락을 정리하고 전체 narrative와 밀도를 최종 조정하며 마지막으로 필요한 내용을 보강하는 단계다.

승인 상태를 보존하기 위한 별도 persistent helper, session source, storyboard, semantic IR, slide-plan, registry 또는 intermediate SSOT를 만들지 않는다.

## Responsibility

Curriculum LLM은 Course Design Guardrail 안에서 전체 교육과정을 완성한다.

- 확정 duration 안에서 Session 수, 제목, 시간과 학습 흐름을 설계한다.
- 각 Session의 outcome과 학습자가 이해·판단·적용해야 할 핵심 claim을 완성한다.
- 각 Session의 학습 목표, 설명·사례·interaction·실습의 teaching progression, 요약과 다음 전환을 완성한다.
- 정의, 인과, 대조, 경계, 상태, 순서와 전환을 LLM이 추측하지 않아도 될 정도로 claim에 명확히 쓴다.
- 중요도·난이도·선수 관계·실습과 feedback 필요성에 따라 시간을 비균등하게 배분한다.
- 필요한 실습을 선택하고 content flow 안의 위치, 입력, 활동, 산출물, feedback·실패 기준과 소요 시간을 결정한다.
- **`[실습]`은 15~30분 동안 수강생이 하나의 명확한 주제 또는 산출물에 집중하여 직접 판단·작성하고, LLM을 활용해 대안·근거·누락을 검증한 뒤 자신의 판단으로 결과를 완성하는 독립 학습 활동에만 사용한다.**
- 실습 범위는 15~30분 안에 수행할 수 있도록 제한하되, 선택한 산출물 자체의 핵심 구성요소는 생략하지 않는다. 예를 들어 정적 분석 모델을 작성한다면 Concept뿐 아니라 필요한 Attribute, analysis-level Type/Value Domain, Association/Relationship, Multiplicity, 의미 있는 Whole-Part 등을 함께 표현한다.
- **하나의 `[실습]`은 본편 슬라이드 1장으로 표현한다.** 수강생은 그 한 장만 보고 작업을 시작·완료할 수 있어야 하며, 제목·시간·입력·과제·LLM 활용·필수 산출물·판단/검토 기준을 포함한다.
- 짧은 질문, 즉석 응답, 강사와 함께 따라가는 모델링, 단순 오류 찾기, 1~3분 Checkpoint, Discussion, Review는 `[실습]`으로 표시하지 않는다.
- 실습의 세부 진행 순서, 단계별 힌트, 강사 개입 시점, 예시 prompt, 권장 시간 배분은 **Slide Notes**에 둔다. `Step`은 본편 슬라이드 제목이나 별도 실습 장표로 자동 변환하지 않는다.
- **실습의 예시 답안·해설·대안 비교는 해당 Session의 본편 뒤 `[별첨]` 슬라이드에 둔다.** 별첨은 수강생 작업 전에 정답을 노출하지 않으며 본편 권장 슬라이드 수와 구분하여 관리한다.
- 한 Session의 실습은 그 Session에서 설명한 모든 내용을 종합 평가하는 미니 프로젝트가 아니다. 핵심 학습목표 중 하나를 실제로 적용하는 제한된 Practice로 설계한다.
- `[실습]` 제목에는 반드시 `[실습]`을 포함하고, Session Detailed Design에는 목적·입력·수강생 과제·LLM 활용·필수 산출물·검토 기준·15~30분의 소요 시간을 명시한다.
- LLM은 정답 생성기가 아니라 수강생의 초안·가설에 대한 대안 생성, 누락 탐색, 반론, 검증에 사용한다. LLM이 제안한 내용은 Requirement·Model·Source 근거가 없으면 그대로 채택하지 않는다.
- 경험 기반 초기 설계를 의도한 실습에서는 **수강생이 자신의 경험으로 먼저 초안을 만든 뒤** LLM을 사용한다. 이때 LLM이 아직 배우지 않은 Pattern/원칙을 정답처럼 선행 주입하지 않도록 prompt 범위를 제한한다.
- Pattern을 적용하는 실습에서는 실습 슬라이드에 **고려할 Pattern/원칙 목록**을 명시하되, 전부 적용하는 checklist로 사용하지 않는다. 수강생은 현재 문제에 필요한 것만 선택하고 선택·비선택 이유를 설명할 수 있어야 한다.
- claim에 실제 필요한 검증된 Source·Anchor·Reference와 Portfolio Common Standards만 선택하고, 사용할 내용·목적과 예상 teaching 위치를 결정한다.
- Session Architecture의 권장 slide 수는 초기 교육 밀도 추정값이며 제약이 아니다. Session Detailed Design에서 실제 claim, 설명 밀도, interaction, practice·feedback이 구체화된 뒤 권장 slide 수와 허용 범위를 다시 산정한다. 차이가 있으면 근거 있는 Detailed Design 값을 우선하고 Session Architecture를 갱신한다. claim 수를 slide 수로 기계 변환하지 않는다.
- Analysis, Design, Architecture, Test 등 논리적 activity/concern을 Course Design이 명시하지 않은 lifecycle phase로 자동 해석하지 않는다. 무엇을 판단하는가와 언제 수행하는가를 구분하고, iterative·incremental feedback과 왕복이 허용되는 경우 그 관계를 명시한다.
- 상세 기법과 심화 적용은 충분한 개념·판단 기반 뒤에 배치한다.
- Governance가 소유하는 Session 01 공통 Guardrail을 적용하되 과정별 구조를 자율적으로 설계한다.

Guardrail은 최소 요구사항과 경계다. Curriculum LLM은 그 안에서 더 나은 설명, 근거, 사례, interaction과 구성을 자율적으로 보완할 책임이 있다.

## Output

Curriculum은 교육 orchestration의 단일 정본이며 최소한 다음을 소유한다.

- 과정 identity와 총 instructional time
- Session ID·제목·시간·outcome·학습 흐름
- Session별 학습 목표, teaching progression과 요약
- Session별 핵심 claim과 필요한 관계·경계
- 선택한 실습의 위치·입력·활동·산출물·feedback과 실패 기준
- 선택한 검증 Source·Anchor·Reference의 사용 내용·목적과 예상 teaching 위치
- 필요한 Portfolio Common Standards
- 다음 Session으로 이어지는 학습 전환
- Session별 권장 slide 수와 근거 있는 허용 범위

실습의 Course Design guardrail, Source·Anchor·Reference 원문과 Common Standard는 복제하지 않고 owner를 식별한다. Curriculum은 이 정본들을 다시 소유하지 않으면서 실제 교육 흐름에서의 사용 방식을 구체화한다. 연결이 없으면 `없음`으로 명시할 수 있다. 특정 markdown field 이름이나 schema는 Harness가 실제로 요구할 때만 고정한다.

## Final Curriculum Document Structure

최종 Curriculum은 다음 네 부분을 유지한다.

1. **Course Overview** — 과정 목적, 대상, capability, scope·boundary, 총 instructional time과 전체 progression
2. **Session Architecture** — 승인된 전체 Session 구조와 시간·흐름·실습·주요 입력·권장 slide 범위
3. **Session Detailed Designs** — Session별 학습 목표, 핵심 내용과 claim, teaching progression, Anchor/Reference 사용, 실습 실행, 요약과 전환
4. **Whole-Curriculum Integration Review** — 전체 관점의 정합성 검토와 최종 승인 근거

### Session Architecture 기본 포맷

| Session | Title | Time | Core Question / Outcome | Main Learning Flow | Practice | Main Anchors / References | Recommended Slides |
|---|---|---:|---|---|---|---|---|

| Column | 작성 기준 |
|---|---|
| Session | 과정 안에서 유일하고 안정적인 Session 식별자. Session 수를 먼저 정하거나 다른 과정과 맞추지 않는다. |
| Title | 학습자가 해당 Session의 핵심 주제와 판단을 이해할 수 있는 간결한 제목 |
| Time | 설명·interaction·실습·feedback을 포함한 instructional time. 중요도와 난이도에 따라 비균등 배분한다. |
| Core Question / Outcome | Session이 답할 핵심 질문과 종료 시 학습자가 설명·판단·적용할 수 있어야 하는 outcome |
| Main Learning Flow | 현상·질문·정의·관계·판단·적용·회수 등 해당 Session의 핵심 논증 순서를 압축한 표현 |
| Practice | `[실습]` 유무, 제목, **15~30분**, 본편 **1장**, content flow 안의 위치와 필수 산출물을 표시한다. 짧은 질문·Checkpoint·Discussion·Review는 Practice로 세지 않는다. 세부 진행은 Notes, 예시 답안·해설은 Session 끝 `[별첨]`으로 분리한다. Pattern 적용 실습이면 고려할 Pattern/원칙 목록을 함께 기록한다. |
| Main Anchors / References | 실제 사용할 주요 Source·Anchor·Reference만 기록한다. 개수를 채우거나 Course Design 전체 목록을 복사하지 않는다. 사용 목적과 teaching 위치는 Session Detailed Design에서 완성한다. |
| Recommended Slides | Session Architecture 단계의 초기 교육 밀도 추정 범위. 상세 설계의 제약이 아니며, Session Detailed Design에서 실제 claim·설명 밀도·interaction·실습·feedback을 근거로 재산정한다. 상세 설계 값이 달라지면 그 값을 우선하고 Architecture를 갱신한다. 전 과정 공통 quota나 claim 수의 1:1 계산으로 정하지 않는다. |

Session Architecture는 승인 후 폐기하는 작업표가 아니라 최종 Curriculum에도 유지되는 전체 구조다. 다만 상세 설계 과정에서 확인된 근거에 따라 상향 feedback과 재승인을 거쳐 갱신될 수 있다. 상세 claim, 실제 slide 구성에 필요한 교육 내용과 실습 세부 절차는 Session Detailed Design에서 완성한다. 실제 slide wording과 visual form은 Deck stage가 결정한다.

## Whole-Curriculum Integration Review

모든 Session 승인 후 다음을 전체 과정 관점에서 다시 검토하고 필요한 통합 조정을 한다.

- narrative와 learning progression의 연속성
- Detailed Design 과정에서 승인된 Course Design·Session Architecture·앞 Session 상향 수정이 전체에 일관되게 반영됐는지
- Session 사이와 과정 전체의 중복·누락
- 핵심 concept의 최초 소개, 반복, 심화와 회수
- Source·Anchor·Reference의 사용 목적, 위치, 중복과 누락
- 실습의 난이도·산출물·feedback progression
- Session 내부와 Session 사이의 transition
- 총 instructional time과 Session별 시간 합계
- 권장 slide 범위와 과정 전체 slide density
- Course Design의 target outcome, scope, non-scope와 ownership coverage
- 3개 Session 단위의 중간 평가·회수에서 반영된 authoring Rule of Thumb과 상위 기준이 이후 Session에 일관되게 적용됐는지
- 개발 중 발견된 반복 판단 중 과정 고유 내용과 재사용 가능한 authoring Rule of Thumb을 구분하고, 아직 상위 공통 기준으로 승격하거나 마지막으로 보강할 항목이 남아 있는지

통합 조정으로 승인된 Session의 목적·필수 outcome·scope 또는 중요한 내용을 바꿔야 하면 해당 변경을 사용자에게 드러내고 다시 승인받는다.

## Prohibited Behavior

- Course Design의 목적, target capability, scope, non-scope, ownership과 확정 시간을 변경하지 않는다.
- Course Design의 section이나 topic을 동일 시간 Session으로 기계 변환하지 않는다.
- Governance의 Human-in-the-Loop workflow를 건너뛰거나 첫 제안에서 전체 상세 Curriculum을 한 번에 생성하지 않는다.
- claim 수, Session 수와 형식을 다른 과정에 맞추지 않는다.
- 기존 Curriculum·Deck·legacy source를 복원하거나 현재 정답으로 사용하지 않는다.
- 검증되지 않은 Source를 확정 사실이나 축자 인용 근거로 승격하지 않는다.
- Portfolio 전체를 무차별 routing하거나 실습·Source 수를 채우지 않는다.
- Course Design이 소유한 실습 목적·필수 outcome, Source·Anchor·Reference 원문과 Portfolio 공통 규칙을 Curriculum에 중복 소유하지 않는다.
- storyboard, semantic IR, slide-plan과 session source를 중간 정본으로 만들지 않는다.

## Verification Expectations

### Deterministic

- Session time 합계와 총 instructional time이 일치한다.
- Session·claim·실습·Source·Common Standard 식별자와 연결에 누락·중복·dangling dependency가 없다.
- 각 Session에 학습 목표·요약, Source·Anchor·Reference 사용 목적과 teaching 위치, 실습 실행 정보와 권장 slide 범위가 필요한 수준으로 존재한다.
- 필수 field와 형식이 Curriculum Harness 계약에 맞는다.

### Semantic

- Course Design의 필수 outcome과 ownership이 충분히 구현된다.
- 논리적 activity/concern과 lifecycle phase가 근거 없이 동일시되지 않는다.
- 선수 관계, 난이도, 실습과 feedback을 고려한 학습 흐름이 자연스럽다.
- claim이 Deck LLM의 핵심 의미 추측을 요구하지 않는다.
- 권장 slide 범위가 Session 시간, 내용 밀도와 interaction에 비례하며 임의 quota가 아니다.
- scope와 밀도가 시간 안에 실제로 가르칠 수 있다.

### Human

- Session별 교육 가치와 과정 전체 narrative가 승인됐다.
- Session Architecture, 각 Session 상세와 최종 통합본이 Governance의 순서대로 승인됐다.
- 중요한 누락·중복·과밀과 boundary 오해가 없다.
- Deck stage의 Guardrail로 사용할 수 있다.
